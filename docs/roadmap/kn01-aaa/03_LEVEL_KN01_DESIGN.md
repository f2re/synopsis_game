# 03. Дизайн уровня 1 «Кодовый пост» (КН-01)

**Статус:** принято к исполнению; все метеорологические формулировки помечены как **предварительные** до задачи W1-01.

> Правило для всех агентов: ни одно правило дешифрирования из этого документа не попадает в задания, тесты или объяснения, пока `meteo-methodologist-ru` не подтвердил его с `source_id` и указанием страницы/пункта, а `meteo-verifier` независимо не воспроизвёл результат. Ниже — дизайн, а не эталон.

## 1. Фантазия уровня

Игрок — стажёр, прибывший на ночную (или текущую по часам мира) смену на станцию с индексом `26063`. Его первое рабочее место — **кодовый пост**: комната с телетайпом, справочником кода, барографом, настенными часами UTC и окном во двор кампуса. Наставник — ведущий синоптик **Вера Павловна Ладожская** (вымышленный персонаж). На телетайпе спит кот центра **Барограф**.

Первая телеграмма, которую печатает телетайп, — сводка **самой станции 26063**. Когда игрок расшифровывает индекс, наставник говорит: «Это мы. Добро пожаловать на 26063». Так документальная координата бренда становится личным моментом игрока.

## 2. Петли уровня

### 2.1. Микропетля (5–20 с) — одно задание

`лента печатает группу → игрок выделяет/читает → вводит или выбирает → «Проверить» → штамп «ПРИНЯТО» или разбор по цифрам → значение «перелетает» в мини-схему станции → следующая группа`

### 2.2. Средняя петля (6–8 мин) — смена

`брифинг наставника (1–2 реплики) → 6–8 заданий с растущей сложностью → итог «Сводка смены» → награда/изменение мира → возврат в центр или «ещё одна смена»`

### 2.3. Большая петля (5–7 смен) — уровень

`карта уровня на ленте → смены С1–С5 → допуск → свидетельство → разблокировка Картографического класса (и Архива) в мире → новый уровень`

## 3. Учебная область уровня (предложение для W1-01)

| Смена | Название | Группы | Новые умения | Связь с предыдущим |
|---|---|---|---|---|
| С1 | «Позывные эфира» | `AAXX`, `YYGGiw`, `IIiii` | распознать начало сводки, день и срок, указатель скорости ветра, индекс станции | вход в уровень |
| С2 | «Термометр» | `1snTTT`, `2snTdTdTd` | знак, десятые, отрицательные значения, проверка `Td ≤ T` | использует умение «найти группу по цифре-опознавателю» из С1 |
| С3 | «Барометр» | `3PoPoPoPo`, `4PPPP`, `5appp` | давление на уровне станции и на уровне моря, восстановление тысяч, характеристика и величина тенденции | — |
| С4 | «Ветер и облака» | `Nddff` (и `00fff` как особый случай) | общая облачность, направление в десятках градусов, скорость с учётом `iw` из С1 | профессионально связанная серия С1 → С4 |
| С5 | «Полная лента» | все группы С1–С4 в одной телеграмме | чтение сводки целиком, перенос значений в мини-схему станции | мост к модулю MET-03 (схема станции) |
| Д | Допуск «Кодовый пост» | всё | без справочника и подсказок | открывает следующие уровни |

Группы `iRixhVV`, `6RRRtR`, `7wwW1W2`, `8NhCLCMCH`, разделы 3 и 5 переносятся на уровень 2, потому что требуют больших кодовых таблиц. Методист может сдвинуть границу; изменение фиксируется в W1-01 и отражается в `harness/plan.json`.

## 4. Типы заданий уровня

Все типы имеют машинно-проверяемый контракт (`docs/00A_FOUNDATIONAL_RUNTIME_PRINCIPLES.md` §7). Эталон хранится только на сервере.

| Код типа | Название для игрока | Что делает игрок | Ответ | Где появляется |
|---|---|---|---|---|
| `identify` | «Что это за группа?» | на ленте подсвечена группа, выбрать её смысл из 4 карточек | `choiceIndex` | С1–С4 вводные |
| `decode` | «Расшифруй» | ввести физическую величину на пиксельной клавиатуре | `value` с допуском, заданным методистом | С1–С5, Д |
| `anatomy` | «Покажи цифру» | нажать на цифру(ы) группы, отвечающие за знак/десятые/тысячи | множество индексов позиций | С2–С4 |
| `encode` | «Закодируй» | дано значение, набрать группу на клавиатуре телетайпа | строка из 5 цифр | С2–С5 |
| `sequence` | «Собери ленту» | перетащить карточки групп в порядке следования | порядок идентификаторов | С1, С5 |
| `findError` | «Где сбой?» | в телеграмме выбрать группу, нарушающую физическое условие или формат | идентификатор группы + код причины | С2–С5, Д |
| `fullTelegram` | «Полная лента» | заполнить бланк по всей телеграмме | объект полей; проверка по полям | С5, Д |

### 4.1. Диагностические неверные варианты

Каждый неверный вариант в `identify`/`choice` и каждый типичный неверный ввод в `decode` порождается **из конкретной типичной ошибки** и несёт код причины. Предварительная таксономия (утверждается в W1-02):

| Код причины | Смысл | Пример для дизайна |
|---|---|---|
| `kn01.sign_ignored` | знак проигнорирован | отрицательная температура прочитана как положительная |
| `kn01.tenths_shift` | сдвиг десятичной запятой | 23,4 прочитано как 234 |
| `kn01.thousands_missing` | не восстановлена старшая цифра давления | давление на уровне моря без тысяч |
| `kn01.group_confused` | спутаны группы по опознавателю | `3PoPoPoPo` принята за `4PPPP` |
| `kn01.tendency_char_misread` | неверно прочитана характеристика тенденции | — |
| `kn01.wind_units` | не учтён `iw` | скорость в узлах принята за м/с |
| `kn01.direction_scale` | направление прочитано не в десятках градусов | — |
| `kn01.td_gt_t` | нарушено условие `Td ≤ T` | — |
| `kn01.order` | нарушен порядок групп | — |
| `generic.inattention` | невнимательность, не относящаяся к правилу | — |

### 4.2. Генерация заданий

- Шаблон задания (`TaskTemplate`) описывает группу, диапазоны значений, обязательные граничные случаи (ноль, минус десятые, переход через тысячу и т. п. — список составляет методист) и правила порождения неверных вариантов.
- Генератор детерминирован по сиду смены: один сид — одни и те же задания (для повторов, споров и тестов).
- Каждый сгенерированный экземпляр проходит обратную проверку кодеком: `encode(decode(x)) == x`.
- Банк реальных телеграмм (≥ 40 сводок, из них первая — станция `26063`) используется в С1, С5 и Д; синтетические группы — в С2–С4.

## 5. Структура смены

| Позиция | С1 | С2 | С3 | С4 | С5 | Допуск |
|---|---|---|---|---|---|---|
| 1 | identify | identify | identify | identify | sequence | decode |
| 2 | identify | decode | decode | anatomy | fullTelegram | decode |
| 3 | sequence | anatomy | anatomy | decode | findError | encode |
| 4 | decode | decode | decode | decode | fullTelegram | findError |
| 5 | decode | encode | encode | encode | — | fullTelegram |
| 6 | decode (26063!) | findError | findError | findError | — | ×12 заданий всего |
| 7 | — | повтор из журнала | повтор из журнала | повтор из журнала | — | — |

Последнее задание С1 — индекс станции в первой телеграмме; после ответа воспроизводится сценка «Это мы».

## 6. Режимы смены (выбор игрока)

Перед каждой сменой игрок выбирает режим на экране S08:

| Режим | Справочник | Подсказка наставника | Таймер | Влияние на освоение | Доступен |
|---|---|---|---|---|---|
| «С наставником» | открыт всегда | после первой ошибки | нет | ×0,6 | всегда |
| «Самостоятельно» | открывается за отметку «с подсказкой» | нет | нет | ×1,0 (×0,6 для задания со справочником) | после первой сдачи смены |
| «Блиц 90 с» | закрыт | нет | 90 с на всю серию | ×0,8, только для освоенных групп | после С2 |

Коэффициенты — предварительные, утверждаются в W1-04. Рейтинг уровня 1 не меняет: пакет остаётся вне рейтингового режима до двойной приёмки.

Другие выборы игрока на уровне: внешность и форма (S04), спутник (после находки синицы), оформление рабочего места (после награды), какие ошибки повторять из журнала (S16), порядок смен С2–С4 (после С1 открыты все три — игрок выбирает, с чего начать).

## 7. Серия и оперативный ресурс в учебной смене

- Серия правильных ответов отображается пятью лампами на телетайпе.
- ×3 — лампы загораются янтарём, кот поднимает голову; ×5 — короткий звонок телетайпа, кот потягивается, наставник кивает.
- Ошибка тушит лампы мягким затуханием 300 мс, без резкого звука.
- Оперативный ресурс уровня 1 **не используется** (он нужен в дуэлях); лампы — только индикатор темпа. Это снимает давление и сохраняет учебный режим.

## 8. Обратная связь

### 8.1. Верно

1. 0 мс — кнопка «Проверить» нажата (звук `ui_click_soft`).
2. ≤ 100 мс — на группу на ленте опускается штамп «ПРИНЯТО» (3 кадра: замах, удар со сжатием, оттиск), звук штампа + `feedback_synoptic_chime`.
3. 300 мс — значение отрывается от бланка и пиксельной дугой за 400 мс перелетает в мини-схему станции в правом верхнем углу бланка, встаёт на своё место (связь «код → наноска»).
4. Лампа серии загорается.
5. Кнопка меняется на «Дальше» (клавиша Enter).

### 8.2. Неверно

1. Группа на ленте вздрагивает по горизонтали (±1 логический пиксель, 3 цикла, 180 мс), звук `feedback_mistake_thud` на −6 дБ.
2. Открывается **разбор по цифрам**: группа раскладывается в ячейки, под ячейками — скобки с подписями («опознаватель», «знак», «значение в десятых»), ячейка с ошибкой обводится красным карандашом, рядом зачёркнутая интерпретация игрока и правильная.
3. Текст объяснения — по коду причины (§4.1), 1–2 предложения, затем источник (`title`, `locator`).
4. Кнопки: «Понятно, дальше» (основная), «Повторить похожее позже» (добавляет в журнал ошибок с пометкой).
5. Наставник (портрет слева внизу) меняет выражение на «задумчивость» и даёт одну короткую реплику (не закрывая разбор).

### 8.3. Принципы текста

- Никогда «Неправильно!» и восклицаний. Используется «Посмотрим ещё раз», «Здесь знак», «Почти: не хватает тысяч».
- Объяснение называет **принцип**, а не только ответ.
- Числа: десятичная запятая, неразрывный пробел перед единицей, минус — знак «−» (U+2212).

## 9. Итог смены «Сводка смены»

Показывается всегда, в том числе при выходе после половины заданий (с пометкой «смена прервана»).

Содержание: точность, лучшая серия, время, изменение освоения по каждому навыку (полоски с приростом), новые записи в журнале ошибок, полученные предметы, подпись наставника и одна персональная реплика, кнопки «В центр» (основная), «Ещё одна смена», «Повторить ошибки».

## 10. Освоение, допуск и разблокировка

- Освоение навыка 0–100 хранится на сервере; формула и затухание задаются в W1-04 по `02_GAMEPLAY_AND_BALANCE.md` и GDD §7.2.
- Допуск открывается, когда освоение каждого навыка уровня ≥ порога профиля курса (предложение: 70) и пройдены С1–С5.
- Допуск: 12 заданий, без справочника, точность ≥ порога (предложение: 80%). Повтор не раньше чем через одну тренировочную смену.
- Успех: экран свидетельства (S21), звание «Техник-метеоролог», жетон «Кодовый пост 26063», событие сервера `progression.unlocked` для `cartography` и `archive`.
- Клиент **никогда** не решает о разблокировке сам; `locationRegistry` получает состояние из ответа сервера.

## 12. Данные и контракты (для W1-12)

```text
LevelDefinition { id: "kn01_level1", title, shifts: ShiftDefinition[], exam: ShiftDefinition,
                  unlocks: LocationId[], rankOnPass, methodProfile, sources[] }
ShiftDefinition { id, order, title, briefing: DialogLine[], slots: TaskSlot[],
                  modesAllowed: ShiftMode[], reward?: RewardId, estimatedMinutes }
TaskSlot        { templateId | bankQuery, kind, difficulty, required: boolean }
TaskTemplate    { id, group, kind, ranges, edgeCases[], distractorRules[], sourceIds[] }
ShiftMode       = "mentor" | "solo" | "blitz"
ProgressionState{ userId, mastery: Record<SkillId, number>, shiftsPassed[], examPassed,
                  unlockedLocations[], rewards[], errorJournal: ErrorEntry[] }
ErrorEntry      { taskTemplateId, errorCode, createdAt, resolvedAt? }
Events          progression.unlocked, progression.reward_granted, shift.completed
```

Поля, раскрывающие ответ (`correct`, `answerKey`, порядок эталона), не входят ни в одну клиентскую схему; это проверяет `security-privacy-reviewer`.
