# План реализации 26063 по результатам аудита — 05.11.2026

**Опора:** [технический аудит](../architecture/PROJECT_AUDIT_20261105.md). Цель — не количество строк кода и не число зарегистрированных агентов, а доказуемо работающий сценарий с сохранённым научным смыслом, визуальной целостностью и независимой приёмкой.

## Архитектурные решения, которые сохраняем

- React 19 отвечает за страницы, модальные окна и доступность; Phaser 4 — за жизненный цикл игровых сцен и резервный 2D мир. Three.js из draft PR #95 — целевой экспериментальный 2.5D Hub **без смены значения по умолчанию до допуска**.
- Синоптическая карта и проверяемые фигуры — отдельная функциональная область `apps/web/src/features/map` на SVG/Canvas; не переносить профессиональную картографию в Phaser ради эффекта.
- Сервер — единый `apps/server` до одобренного ADR; сервер авторитетен для результата, награды, времени матча и рейтинга.
- Семантические идентификаторы, методические профили и SHA оригиналов R01–R06 — неизменяемые опоры. Любой изменённый источник получает версию.

## Первые три инженерных пакета

### Пакет A — защита и восстановление смены

1. Поднять общий формат `attemptId`, `shiftId`, `instanceId`, `userId`, `packId@version`, `methodProfile@version`, `answerHash`, `checkedResult`; источник истины — сервер.
2. Разделить запись сырой попытки, фиксацию валидированного результата и выдачу наград. Сначала определить атомарную транзакцию (SQLite WAL для одиночного сервера либо существующее совместимое хранилище с гарантиями), оформить ADR.
3. Гарантировать повторяемость запросов/зачёта и восстановление после падения между проверкой и фиксацией; добавить миграционные тесты из JSON.
4. Исправить семантику `GET /api/shifts` (сейчас возвращает объект прогрессии), сделать выбор активной/прошлой смены.
5. После независимой проверки открыть безопасный маршрут зачёта; небезопасный приём клиентского `isCorrect` не возвращать.

**Сдача:** тест «ответ → kill/restart → продолжение → завершение → повтор запроса → ровно одна награда», включая отказ поддельному ответу.

### Пакет B — один завершённый визуальный экран

1. На 6 оригиналах R01–R06 закрепить приоритет R01, неизменность SHA; мастер геометрии и safe areas без генеративного интерфейса.
2. Производственный набор L0–L9: дальний план и плоский берег, грунт/подходы, корпуса/входы, декор/фауна, маски погоды и света, отдельный DOM HUD.
3. Принятые исходники проходят `tools/assets`; девять PNG для legacy и согласованные атласы/материалы для Three не подменяются друг другом.
4. Выпустить реальный кадр из работающего браузера на 1920×1080, 1440×900, 2560×1440, 390×844, сохранить метрики и изображения в CI.
5. Принять/отклонить визуал независимо двумя ролями и только после этого рассматривать новый режим по умолчанию.

**Сдача:** подтверждённая геометрия 8 взаимодействий, новая художественная графика, ни одной замещающей серой коробки или повреждённого WebP.

### Пакет C — подтверждённая метеорологическая смена

1. Связать 30 шаблонов из `kn01_level1_pack` с реально исполняемыми уровнями/сменами только через версионированный адаптер; старый `core_ru_001` сохранить как демонстрационный, пока нет двойной проверки.
2. По каждой группе `AAXX`, `YYGGiw`, `IIiii`, `1snTTT`, `2snTdTdTd`, `3PoPoPoPo`, `4PPPP`, `5appp` проверить методические правила, типичные неоднозначности и источник.
3. Убедиться, что клиент до ответа не получает эталон, после получает объяснение с локатором источника; показатель освоения рассчитывается по подтверждённым попыткам.
4. Выполнить браузерный путь `вход → Hub → смена → ответ → исправление → итог → Hub` с сохранением после перезагрузки и отказа сервера.

**Сдача:** научный и интеграционный PASS с реальными журналами, не только флагами `approved` в JSON.

## Условие завершения ближайшего игрового среза

Пользователь входит, видит принятый R01 или честно обозначенный резервный режим, выбирает рабочее место, выполняет проверенные научные задачи, получает объяснение с источником, сохраняет результат, обновляет страницу и продолжает работу; серверный рестарт не теряет состояние, повтор ответа не начисляет вторую награду, а основные действия выполняются с клавиатуры и на мобильном экране.
