# 06. Технические требования и архитектурные ограничения

## 1. Общий принцип

Проект — браузерное адаптивное приложение для ноутбуков, учебных классов, смартфонов и большого экрана. Для базового сценария не требуется отдельное настольное или мобильное приложение.

Архитектура первого рабочего среза определяется `ADR-0004`, `ADR-0005` и `ADR-0007`.

## 2. Зафиксированный стек

### Клиент

- TypeScript;
- React — оболочка, навигация, формы, панели и доступность;
- Phaser 4 — игровой lifecycle, input, audio, UI/HUD и интеграция живого мира внутри `packages/world-engine`;
- Three.js — специализированный 2.5D renderer нового Hub внутри `packages/world-engine`;
- WebGL2 — основной способ отрисовки 2.5D Hub; legacy Phaser/WebGL renderer сохраняется на переходный период;
- SVG/Canvas — профессиональная синоптическая карта и геометрический ввод;
- CSS;
- GLB/glTF — рабочий контур-формат сложных reusable 3D assets и skinned characters;
- PWA — необязательная возможность после первого вертикального среза.

Phaser не является источником метеорологической истины и не заменяет React. Three.js не заменяет Phaser глобально и не становится источником игровой процесс state. Карта остаётся отдельным модулем веб-приложения на SVG/Canvas.

Версии Phaser и графических инструментов фиксируются в `config/art-toolchain.yaml` и package manifests/lockfile. Версия Three.js должна быть зафиксирована точной рабочий контур dependency после technical spike; неконтролируемое major/minor обновление renderer dependency запрещено.

Нормативные документы нового Hub:

- `architecture/HUB_2_5D_RENDERER_CONTRACT.md`;
- `architecture/CHARACTER_2_5D_ANIMATION_CONTRACT.md`;
- `design/PIXEL_3D_STYLE_CONTRACT.md`;
- `roadmap/HUB_2_5D_MIGRATION.md`.

### Сервер

- Node.js + TypeScript;
- авторитетный модульный монолит;
- REST/HTTP для учётных записей, учебного материала и истории;
- WebSocket/Socket.IO для матчей и состояния трансляции;
- проверка схем данных на границах API.

### Хранение

Для локального прототипа допустим SQLite. Для многопользовательского развёртывания: PostgreSQL; Redis подключается только при подтверждённой необходимости координации между процессами; крупные архивные карты и медиа хранятся в объектном хранилище.

## 3. Каноническая топология

```text
apps/
  web/                 # React + GameWorld mount + SVG/Canvas map + /arena-tv
  server/              # авторитетный модульный монолит
packages/
  kn01-codec/
  content-engine/
  game-rules/
  world-engine/        # Phaser lifecycle + Three.js 2.5D Hub renderer
  contracts/
assets/
  source/
  scenes/
  manifests/
  generated/
tools/
  assets/
```

На первом рабочем срезе `identity`, `live-ingest`, `realtime`, `broadcast`, `replay` и `rewards` являются внутренними модулями `apps/server`. Профессиональная карта является модулем `apps/web/src/features/map`.

`Arena TV` реализуется маршрутом `/arena-tv` внутри `apps/web`; отдельное приложение большого экрана не создаётся.

Three.js renderer не выделяется в отдельный top-level package до появления как минимум двух независимых потребителей и отдельного ADR.

## 4. Авторитетность сервера

На сервере обязательно выполняются:

- выбор или формирование задания;
- фиксация снимка исходных данных и версий;
- установка срока ответа;
- проверка ответа;
- начисление игрового эффекта;
- изменение рейтинга и наград;
- определение окончательного результата.

Состояние клиента является представлением серверного состояния. Клиент не получает правильный ответ до разрешённого правилами момента.

## 5. Учебные задания и защита эталона

`content-engine` разделяет серверное каноническое задание и публичный `TaskInstance`.

Для последовательностей и вариантов ответа:

1. сервер формирует канонический порядок;
2. выполняет детерминированную перестановку по зерну раунда;
3. отправляет клиенту только переставленные публичные элементы;
4. обратное соответствие остаётся на сервере;
5. воспроизведение хранит зерно и версии правил.

Сетевой инспектор браузера не должен раскрывать правильный порядок или значение ответа.

## 6. Геометрия карты

Экранные пиксели не являются частью эталона ответа. Каноническое пространство бланка:

```text
[0, 0] .. [1000, 1000]
```

Клиент переводит координаты указателя в пространство карты. Сервер проверяет геометрию в единицах карты и применяет профильные правила пересечений, концов линий, непрерывности и контекста.

Это обеспечивает одинаковую проверку на смартфоне, ноутбуке и проекторе.

## 7. КН-01

`packages/kn01-codec`:

- чистый и версионированный;
- не выполняет сетевой ввод-вывод;
- принимает явный `kn01_ruleset_id`;
- поддерживает разбор, кодирование и контролируемое обратное преобразование;
- хранит различия правил в данных и тестах, а не в пользовательском интерфейсе.

Приём внешнего потока, удаление дублей, карантин и снимки данных остаются в серверном модуле `live-ingest`.

Раздел `333` и случаи высокогорных станций реализуются только по конкретному набору правил и источнику. Наличие группы не интерпретируется автоматически как факт опасного явления.

## 8. Игровые правила

`packages/game-rules` содержит детерминированный автомат состояния, таймеры правил, Надёжность, оперативный ресурс, серии, эффекты и итог раунда. Он не знает терминов КН-01 и не читает учебные источники.

## 9. Контракты

`packages/contracts` содержит только версионированные структуры обмена:

- публичный `TaskInstance`;
- события матча;
- сообщения трансляции;
- канонические структуры наблюдения;
- манифест воспроизведения;
- версии схем.

Бизнес-логика в `contracts` запрещена.

## 10. Живой мир

`packages/world-engine` отвечает за Phaser lifecycle, WebGL, загрузку ресурсов, анимации, эффекты, diagnostic primitives и новый Three.js 2.5D renderer Hub.

Для нового Hub действуют следующие требования:

- canonical игровой процесс/composition space: 640×360;
- default internal render target: 320×180;
- fixed orthographic camera;
- scene-specific logical viewport вместо глобального принудительного перевода всех сцен на 640×360;
- renderer-independent `HubWorldDefinition` как источник spatial semantics;
- 2D collision/navigation truth сохраняется вне 3D renderer;
- weather/season/day/building states выражаются materials, lighting, particles и state parameters;
- character movement остаётся игровой процесс-authoritative, root motion не определяет положение;
- interaction использует stable semantic IDs, а не mesh/material UUID.

Состояние времени суток, сезона и фоновых событий может задаваться сервером или детерминированным локальным расписанием, но покадровые координаты птиц, частиц, костей и декоративных объектов по сети не передаются.

Уменьшенная анимация и режим пониженного энергопотребления обязательны.

## 11. Производственный путь графики

### 11.1 2D и legacy assets

Для UI, portraits, documents, icons, legacy scenes и иных намеренно raster assets источником истины остаются `assets/source`, `assets/manifests` и `assets/scenes` там, где Tiled ещё используется. `assets/generated` создаётся инструментами и не исправляется вручную.

### 11.2 Новый Hub

Для Hub source of truth смещается к:

- `HubWorldDefinition`;
- procedural/parameterized geometry;
- reusable mesh kits;
- instanced vegetation/props;
- GLB/glTF только для сложных reusable assets и skinned characters;
- canonical palette/material definitions;
- environment/world state.

Концепт-арты и AI-generated Geometry Lock/season/weather batches служат визуальными эталонами. После перехода соответствующее изображение может стать `reference only`, если его визуальный state полностью воспроизводится renderer-ом.

Не допускается заменять sprite proliferation на отдельный GLB для каждого visual state.

## 12. Большой экран

Маршрут `/arena-tv`:

- использует роль `display`;
- работает только на чтение;
- автоматически переподключается;
- не получает приватные поля списка пользователей;
- не получает правильный ответ до разрешённого момента;
- при отсутствии матчей переходит в демонстрационный режим.

## 13. Воспроизводимость

Для матча сохраняются версии:

- набора правил КН-01;
- методического профиля;
- пакета учебного материала;
- профиля баланса;
- схем событий;
- снимка данных;
- зерна случайности.

Повтор не должен зависеть от текущей версии баланса или свежего внешнего потока.

Декоративная локальная анимация не обязана хранить каждый render frame, но игровой процесс-significant world state и deterministic seeds должны позволять восстановить смысловое состояние сцены.

## 14. Производительность

Проверяются как минимум три профиля:

- обычный настольный браузер;
- проектор или большой экран;
- смартфон среднего класса.

Проверка включает частоту кадров, frame time, задержку ввода, память текстур, загрузку ресурсов, изменение размера окна, плотность пикселей, потерю и восстановление WebGL-контекста.

Для нового Hub дополнительно контролируются:

- draw calls;
- visible triangle count;
- shader compile stalls;
- animation mixer cost;
- particle cost;
- shadow cost;
- internal render target size.

Целевые ориентиры vertical slice:

- 60 FPS desktop preferred;
- 30 FPS minimum / 60 preferred mid-range mobile;
- ≤150k visible triangles preferred;
- ≤80 draw calls preferred, >150 требует review;
- 20–30 simultaneous animated humanoids;
- один default shadow-casting key light;
- 32–64 MB texture memory preferred for Hub.

Единый универсальный лимит памяти для всех устройств не устанавливается без измерений реального вертикального среза.

Поддерживаются quality profiles `high`, `balanced`, `reduced`; reduced-motion является отдельной осью.

## 15. Безопасность

- внешний метеорологический поток считается недоверенным;
- права проверяются сервером;
- публичный большой экран получает только разрешённые данные;
- секреты и правильные ответы не встраиваются в клиентский пакет;
- ограничения попыток входа и временная блокировка применяются согласно профилю доступа;
- происхождение сторонних графических, 3D и звуковых ресурсов фиксируется.

## 16. Условие выделения нового пакета или приложения

Новая физическая граница допускается только после отдельного ADR, если есть независимые потребители, устойчивый программный интерфейс и измеримое снижение связанности. До этого функциональность остаётся модулем существующего приложения или одного из пяти базовых пакетов.
