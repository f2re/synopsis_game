# Руководство по добавлению учебных заданий

**Статус:** предложено

Пошаговая инструкция для добавления нового задания или сценария без изменения игрового движка.

## 1. Определите учебную цель

Сформулируйте один измеряемый навык:

- дешифрировать группу КН-01;
- корректно нанести элемент станции;
- выявить ошибочное наблюдение;
- выбрать следующий шаг анализа;
- провести линию фронта по комплексу признаков.

Не начинайте с игрового эффекта.

## 2. Выберите учебный модуль и навык

Проверьте [`../meteorology/CONTENT_MODULES.md`](../meteorology/CONTENT_MODULES.md).

Если нужного модуля нет, сначала добавьте его туда и опишите предварительные требования.

## 3. Укажите методический профиль

Пример технического идентификатора:

```text
RUS_CLASSIC_TRAINING_V1
```

Если правило относится только к конкретной кафедре, создайте отдельный профиль или переопределение. Не меняйте глобальную трактовку молча.

## 4. Привяжите источник

Минимально указываются:

- `source_id`;
- редакция;
- раздел, страница или пункт;
- авторитетность и статус.

Для реальной архивной ситуации дополнительно:

- поставщик;
- дата и срок;
- права использования;
- предварительная обработка;
- контрольная сумма или устойчивый идентификатор.

## 5. Выберите существующий тип задания

Предпочтительно использовать один из уже поддерживаемых технических типов:

- `choice` — один вариант;
- `multiChoice` — несколько вариантов;
- `sequence` — последовательность;
- `decode` / `encode` — дешифрирование и кодирование;
- `stationPlot` — схема станции;
- `findError` — поиск ошибки;
- `hotspot` — указание области;
- `drawLine` — проведение линии;
- `compare` — сопоставление;
- `numeric` — числовой ответ;
- `scenario` — многошаговый сценарий.

Новый тип отображения создаётся только тогда, когда существующие типы действительно не выражают учебное действие.

## 6. Опишите эталонный ответ

Эталон включает:

- правильный ответ;
- допуски и допустимые альтернативы;
- объяснение;
- метки методических принципов;
- коды причин типичных ошибок.

Для задания на последовательность лучше использовать граф зависимостей, если строгая линейная последовательность методически неверна.

## 7. Проверьте однозначность

Нужно ответить на вопросы:

- возможен ли второй физически корректный ответ?
- достаточно ли исходных данных?
- зависит ли решение от неуказанного кафедрального правила?
- является ли ложный вариант действительно неверным, а не просто редким?
- не смешаны ли разные редакции методики?

## 8. Добавляйте игровые параметры только после учебной проверки

Учебное задание может существовать без сетевого состязания.

Игровой слой является необязательным и может переопределяться `BalanceProfile`.

## 9. Статусы публикации

В человекочитаемом виде:

```text
черновик → источник проверен → методически проверено → проверено на пилоте → опубликовано
```

В данных эти состояния могут храниться как технические значения `draft`, `source_checked`, `method_reviewed`, `pilot_validated`, `published`.

Рейтинговый и экзаменационный режимы не используют черновики.

## 10. Минимальный пример

```json
{
  "id": "kn01_temp_001",
  "topic": "kn01",
  "skills": ["kn01_temperature"],
  "type": "decode",
  "difficulty": 1,
  "method_profile": "RUS_CLASSIC_TRAINING_V1",
  "data_origin": "synthetic_drill",
  "sources": [
    {
      "source_id": "ROSHYDROMET_KN01_CURRENT",
      "locator": "temperature_group"
    }
  ],
  "question": "Раскодируйте температуру воздуха",
  "payload": {},
  "answer": {},
  "explanation": "...",
  "principle_tags": ["code_reading"]
}
```

Имена полей остаются английскими как часть схемы данных.

## 11. Лист самопроверки автора

- [ ] учебная цель одна и ясна;
- [ ] источник указан;
- [ ] методический профиль указан;
- [ ] возможная неоднозначность рассмотрена;
- [ ] объяснение есть;
- [ ] коды причин ошибок есть;
- [ ] происхождение данных указано;
- [ ] синтетические и реальные данные не смешаны;
- [ ] выбран подходящий тип задания;
- [ ] схема данных проходит автоматическую проверку;
- [ ] методическая проверка выполнена перед рейтинговым или экзаменационным использованием;
- [ ] если меняется предметная истинность, выполнена независимая метеорологическая верификация.
