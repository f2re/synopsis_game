# Ситуативная примерка R02: передача интерфейса на проверку

**Исторический документ (12.11.2026).** Показанные здесь ситуационная сборка и анимация заменены [сохранённым портретом R04](../design/MODULAR_CHARACTER_SAVED_PORTRAIT_R04.md). Снимки и результаты ниже относятся к предыдущему выпуску.

**Задача:** `MODULAR-PLAYER-R02`. **Исполнитель интерфейса:** `screens_audit`, роль `ui-pixel-designer`. **Дата:** 11.11.2026.

Это запись реализации и сценарий независимой проверки. Она не заменяет художественную приёмку, браузерные снимки или измерение производительности.

## Реализованный срез

В [редакторе персонажа](../../apps/web/src/features/avatar/AvatarEditor.tsx) появился переключатель четырёх ситуаций. [Общий компонент](https://github.com/f2re/synopsis_game/blob/9573d70e5857f27105f3c14ff896bbad4251f38a/apps/web/src/features/avatar/AvatarSituationPreview.tsx) держит только один `AvatarPreview` и получает тот же черновик внешности, который меняют предметы, палитры и готовые комплекты. Переключение ситуации не изменяет `AvatarProfile`, не сохраняет его и не начинает смену.

| Ситуация | Отображение | Источник внешности |
|---|---|---|
| Гардероб | Полный рост, принятые направления и движения | Черновик примерки |
| Кампус | Уменьшенная фигура и спутник среди слоёв площади | Тот же черновик |
| Рабочее место | Фигура за передним планом стола; спокойное отображение | Тот же черновик; это примерка перед будущей сменой |
| Блиц | Спокойная фигура за столом, подпись «Макет сцены» | Тот же черновик; игрового запуска, таймера и счёта нет |

Общий компонент отображения принимает `context` и, для настоящей смены, `equipment`. Реальное [рабочее место](../../apps/web/src/features/shift/ShiftWorkspace.tsx) передаёт исходный сохранённый профиль и серверный снимок экипировки; выбор инструмента из снимка выполняет один общий адаптер. В [профиле кампуса](../../apps/web/src/features/hub/HubScreen.tsx) явно указан контекст `campus`.

Направление при смене ситуации выбирается из стандартного вида этой сцены: спереди в гардеробе/кампусе, справа за столом. Пользователь может повернуть персонажа кнопками или стрелками в области предпросмотра. Движение возвращается к `idle`; список действий обновляется из допуска рига и политики ситуации. Во время загрузки нового контекста доступна только стойка.

Состояние «Примерка» / «Сохранённый образ» остаётся видимым во всех четырёх сценах. Объяснение блица сообщает, что режим ещё не подключён. Описание рабочего места напоминает о фиксации инструмента в начатой смене. Учебные эффекты не выводятся из изображения или выбранного контекста.

## Сценарий независимой браузерной проверки

1. Открыть гардероб с сохранённым профилем. Выбрать заметный комплект, причёску, обувь, рюкзак, предмет и спутника. Убедиться, что отображается «Примерка».
2. Последовательно выбрать четыре ситуации. На каждом шаге сравнить `data-avatar-profile` и убедиться, что в области `.inventory-situation` существует только один canvas. В рабочей сцене и макете блица спутник скрыт политикой отображения, но поле `companion` профиля сохранено.
3. В макете блица не должно быть таймера, очков, запуска матча или запросов начала смены. Объяснение и «Макет сцены» читаются на ширине 390 px.
4. Повернуть фигуру кнопками и клавиатурой; проверить волосы/головной убор, рюкзак, предмет и кисти. Передний план стола не должен закрывать лицо; инструмент должен оставаться различимым.
5. На 390 px и настольном размере проверить отсутствие горизонтального прокручивания, видимый фокус, читаемость четырёх переключателей, подписи состояния и управления поворотом. Минимальная высота кнопок — 44 px.
6. Вернуться без сохранения: кампус сохраняет прежний образ. Восстановить черновик, сохранить и открыть кампус: все выбранные поля должны совпадать. Переключение ситуации само по себе не должно создавать черновик.
7. Начать настоящую смену с папкой, сохранить планшет в другом представлении профиля и возобновить смену: инструмент остаётся папкой из серверного снимка. Новый контекст не расходует заряды.
8. Проверить системное уменьшенное движение, скрытую вкладку и область предпросмотра вне окна. Переключения и кнопки работают; временные потребители и таймеры не накапливаются.

Независимые принимающие роли: `ux-accessibility-reviewer`, `art-director`, `web-performance-engineer`, затем `integration-release-engineer`. Физический телефон и проектор проверяются отдельно от изменения размеров настольного браузера.

## Открытый стенд проверки внешности

Для визуального прохода без пользовательского входа добавлен отдельный [HTML-стенд](../../apps/web/tools/review/modular-player.html) и его [сценарий](../../apps/web/tools/review/modular-player.tsx). Vite в режиме разработки открывает `/tools/review/modular-player.html`. Обычный вход приложения и производственная точка сборки не изменены; сценарий дополнительно проверяет `import.meta.env.DEV`.

Стенд монтирует настоящие `AvatarEditor` и `HubScreen`, загружает опубликованные изображения и общий композитор. Баннер «Тестовый стенд внешности» сохраняется над обоими экранами. Общедоступный тестовый профиль не является серверным аккаунтом; все методы `api` перекрываются локальными функциями до монтирования. Неожиданный вызов заканчивается локальной ошибкой. Токены, вход и реальные HTTP API не используются. Сохранение тестового профиля и восстановление примерки происходят только в этой вкладке; сброс очищает исключительно ключи данного стенда.

Стартовые учебные показатели равны нулю, открыт только начальный значок. Эти данные помогают проверить размещение реальных элементов интерфейса; они не подтверждают серверное начисление наград. Проверка API проводится отдельно. Проверка типов свежих исходников интерфейса вместе со стендом завершилась **PASS**.

Независимый просмотр обнаружил перекрытие предмета и кисти столом. По замечанию `runtime_review`, подтверждённому снимком root, фигура рабочих ситуаций поднята на 53 CSS-пикселя (`bottom: -28px` → `25px`). Изображения рига не менялись. Видимость предмета и головного убора подтверждена финальными настольными снимками и снимками области 390×844 в [независимом художественном протоколе](2026-11-11-modular-situations-art-review.md).

Для проверки узкой компоновки добавлен [стенд iframe](../../apps/web/tools/review/modular-player-narrow.html): область настоящего внутреннего окна 390×844, с возможностью выбрать ширину 768. Он загружает тот же открытый стенд, не меняет производственную точку входа и не требует инструментов разработчика браузера.
