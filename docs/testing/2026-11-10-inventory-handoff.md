# Персонаж и инвентарь: передача реализации

**Дата:** 10 ноября 2026. **Задача:** `20261110-characters-inventory`.
**Исполнитель UI:** `/root/inventory_ui`, роль `ui-pixel-designer`.
**Основа:** локальный коммит `6a5dfd3` с экраном R01. Настоящий документ относится к изменениям рабочей ветки; итоговый SHA фиксирует интеграционный отчёт после объединения.

## Исправленная проблема

Прежний интерфейс предлагал значения, которых нет в серверном `AVATAR_OPTIONS`, например `skin.nordic-fair`, `top.lab-coat` и `held.folder`. Часть путей к изображениям также отсутствовала, а обработчик `onError` скрывал поломку. Поэтому красивый выбранный комплект мог не сохраняться через `PATCH /api/identity/avatar`.

Каталог UI приведён к действующему серверному контракту: **11 полей, 42 варианта, 24 предмета инвентаря, 29 PNG** с учётом пяти причёсок. Из них 25 переиспользованы, четыре неправильно подписанные старые картинки заменены независимо принятыми изображениями шарфа, очков и двух значков. Три готовых комплекта состоят только из принимаемых сервером значений.

## Реализованное поведение

Маршрут остаётся `/profile/avatar`, доступный вошедшему пользователю из профиля кампуса.

- Инвентарь содержит категории «Всё», «Одежда», «Снаряжение», «Спутники», поиск по названию/описанию и фильтр «На персонаже».
- Выбор карточки открывает её описание. Отдельное действие надевает вещь, берёт предмет, прикрепляет значок или выбирает спутника.
- Восемь слотов показывают выбранные вещи. Головной убор, рюкзак, предмет в руках, значок и спутник можно снять через соответствующее серверное значение `*.none`. Верх, брюки и обувь заменяются другим вариантом.
- Раздел «Внешность» меняет тон кожи, цвет волос и причёску.
- Изменения сначала являются примеркой. «Сохранить образ» отправляет весь `AvatarProfile` в существующий аутентифицированный API. Только успешный ответ обновляет профиль приложения.
- Ошибка сохранения остаётся видимой и сохраняет черновик для повторной попытки. Сетевой `Failed to fetch` заменяется понятным русским сообщением о недоступном сервере; ответы сервера, в том числе истёкшая сессия, сохраняют свой смысл. Кнопка отмены возвращает последний успешно сохранённый образ.
- Возвращение в кампус при несохранённой примерке открывает нативный диалог с действиями сохранения, выхода без сохранения и продолжения. Перезагрузка/закрытие страницы защищены `beforeunload`; перехват произвольной SPA-навигации историей браузера отдельно не реализован.
- Изменение аккаунта сбрасывает черновик, выбранную карточку и поисковый фильтр. Нового локального хранилища экипировки нет.

Все предметы — базовая косметика. Экран не создаёт уровни, бонусы точности, редкости, награды, стоимость, владение платными предметами или серверную прогрессию. Кот Паскаль не добавлен в каталог доступных спутников: сервер поддерживает только синичку и белку.

## Графика и доступность

Использованы существующие изображения `/assets/items/*.png`, четыре принятые замены, иконка профиля R01 и восемь состояний кнопок SpriteCook R01 (`primary`/`secondary`: normal, hover, pressed, disabled). Графика загружается локально. Новые четыре иконки подготовлены отдельной художественной задачей; UI-задача не выполняла генераций и не расходовала кредиты SpriteCook. Текстовые обозначения сохранены как запасной вид при отсутствии изображения в каталоге. Regression запрещает возвращение к четырём ошибочным старым путям.

Логические состояния и названия остаются в DOM, а не в растровом изображении. Кнопки снабжены видимым фокусом, выбранные/надетые предметы обозначены текстом. Переключатель разделов имеет стандартные роли вкладок, перемещаемый `tabIndex`, стрелки и Home/End. Предпросмотр обрабатывает поворот, шаг и осмотр только при фокусе на самом предпросмотре; пробел и стрелки в обычных элементах формы не перехватываются. Целевой минимум интерактивных областей — 44 CSS px; при узком экране слоты занимают полную ширину.

UI не заменяет собственную внешность игрока фиксированным NPC. Реализация и ограничения `AvatarPreview.tsx`, анимации NPC и связи с Phaser проверяются отдельной задачей координатора.

## Воспроизводимые проверки

После установки обычных зависимостей web:

```bash
node tools/test_avatar_inventory.cjs
```

Проверка сравнивает все значения UI с реальным серверным каталогом, пропускает каждый выбор и готовый комплект через серверный `validateAvatar`, проверяет набор предметов и наличие PNG. Она ловит исходную ошибку рассогласования контрактов.

После сборки сервера:

```bash
node tools/test_avatar_inventory.cjs --api
```

Режим `--api` запускает реальный API на свободном локальном порту с явно включённым примером тестового ростера в новом временном каталоге. Выполняет обычный вход, сохраняет все 42 варианта, проверяет отказ для неизвестного ID и анонимного запроса, перезапускает процесс сервера, снова входит и сравнивает сохранённый комплект. Второй аккаунт сохраняет собственный исходный образ. Токены не печатаются, временные файлы удаляются.

**Выполнено:** оба режима `test_avatar_inventory.cjs`, TypeScript с проверкой актуального исходника world-engine и производственная сборка Vite — успешно. В исходной рабочей копии pnpm-снимок `file:` пакета не содержит новых файлов параллельно изменённого рабочего контура; для проверки актуального исходника использован существующий `runtime-source-tsconfig.json`. Интеграционная проверка должна обновить локальный пакет либо применять утверждённую конфигурацию с путями к исходникам.

Производственная сборка сохраняет существующее предупреждение о крупном основном JS и одновременном статическом/динамическом импорте world-engine; разделение движка на чанки в эту UI-задачу не входило.

## Приёмка в браузере

Начальный запуск отдельного Playwright Chromium не состоялся из-за запрета Unix-сокета (`socket() failed: Operation not permitted`). Проверка затем выполнена через поддерживаемый CUA-браузер. Настоящая производственная сборка Vite и скомпилированный API запущены в native Terminal на localhost, в изолированном каталоге данных. Использован тестовый профиль «Тестовый наблюдатель UI» с предусмотренным продуктом первым входом без кода. Реальные пользовательские данные не менялись; пароль или код не вводились.

| Проверка | Наблюдаемый результат |
| --- | --- |
| Каталог и отдельная примерка | 24 предмета; выбор карточки сам по себе не меняет экипировку. «Надеть» меняет слот и показывает несохранённую примерку. |
| Сохранение и перезагрузка | Кепка, затем полный комплект «На площадке» сохранены через UI; после перезагрузки и повторного входа после перезапуска API слоты совпали. |
| Фильтры | Пустой поиск дал 0 результатов, скрыл описание и показал сброс; сброс восстановил 24 карточки. «На персонаже» показал 7 вещей сохранённого полевого комплекта. |
| Спутник и комплекты | Синичка добавлялась и снималась штатными действиями; комплект менял соответствующие слоты без новых наград или очков. |
| Вкладки и диалог | Стрелка вправо и Home переключили вкладки; активная вкладка имела `tabIndex=0`, другая `-1`. Escape закрыл предупреждение о выходе и вернул фокус на «В кампус», сохранив примерку. |
| Отмена | Вернула сохранённые значения и убрала признак несохранённого черновика. |
| Настоящий сетевой сбой | Тестовый сервер остановлен через Terminal. UI показал «Нет связи с сервером. Изменения остались в примерке…», сохранил комплект и доступность повторной попытки, не показал ложного успеха. |
| Восстановление сервера | После перезапуска API прежняя сессия закономерно стала недействительной, и UI показал точное сообщение сервера. После отмены черновика, перезагрузки и штатного входа прежний сохранённый комплект восстановился. |
| Кампус | `data-characters`: `visibleActors=3`, `animatedActors=3`, `artAccepted=true`, `errors=[]`. Уменьшенное движение дало `animatedActors=0` при трёх видимых актёрах. Архив → кампус вернул ровно три актёра без дубликатов. |

Фактический основной viewport — **1363×936 CSS px при 100%**. Обычный масштаб Chrome дал узкие проверки **454×312 при 300%** и **340×234 при 400%**. В этих состояниях `scrollWidth` совпал с `clientWidth`, отсутствующих изображений не было, все видимые кнопки имели ширину и высоту не меньше 44 CSS px. У фильтра «На персонаже» малый нативный checkbox входит в кликабельную метку высотой 44 px.

Это проверка адаптивной вёрстки и клавиатуры в настольном браузере, **не эмуляция телефона или touch-устройства**. DevTools в браузере запрещены организационной политикой; ограничение не обходилось. Обычные команды изменения окна не изменили его размер. Поэтому 320×568, 390×844, 800×600, 1440×900 и 1672×941 этим прогоном не подтверждены, как и FPS или физическая скорость на слабом устройстве. Снимки полного документа при масштабировании имеют ошибку обрезки в CUA и исключены из evidence; для узкого режима сохранены корректные снимки viewport по отдельным участкам.

Снимки и диагностические JSON находятся в `docs/testing/evidence/inventory-20261110`. Визуальная проверка обнаружила ранее неверно подписанные картинки шарфа, очков и двух значков; их идентичности в сервере не менялись. Итоговое решение по этим изображениям зафиксировано в художественной приёмке координатора.

**Независимые принимающие:** Art Director, UX/Accessibility, Web Performance и Integration & Release фиксируют свои решения отдельно. Эта передача описывает результаты реализации и фактически выполненных проверок, не присваивая себе их роли.
