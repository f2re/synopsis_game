# Независимая проверка выхода и публичных экранов

Дата: 2026-11-12. Задача: `COZY-SCREENS-20261112-SESSION`.

Исполнитель изменений: `/root`. Проверяющий: `/root/settings_audio`, роль `security-privacy-reviewer`. Проверяющий не редактировал `App.tsx`, `api.ts` или навигационный модуль.

## Итог — PASS для проверенного изменения

Рассмотрены корневая загрузка сессии, вход наблюдателя/администратора, выход, публичные страницы, `safeReturnPath()` и защита обновления профиля после смены сессии.

Первый просмотр выявил два дефекта, переданных автору и исправленных им:

1. Поздний ответ входа мог восстановить token после закрытия формы/выхода. Теперь номер поколения авторизации делает такой ответ неактуальным; он не сохраняется, выдаёт `login_cancelled`, полученный серверный token отзывается отдельным запросом.
2. Прямой доступ к запрещённому sessionStorage мог прервать главный экран и завершение сеанса. Теперь предусмотрен безопасный сеансовый резерв в памяти.

Повторно проверено по реализации:

- закрытие формы, переход страницы и начало выхода отменяют ожидающие входы;
- запрос завершения получает прежний token синхронно; локальный вход закрывается до ожидания сетевого ответа;
- поздний ответ завершения не удаляет более новую сессию;
- загрузка `/me` имеет тайм-аут и `AbortController`, а поздний профиль применяется только к тому же token;
- обновление внешности/кода не возвращает чужой устаревший профиль после выхода;
- публичные библиотека, помощь и настройки не требуют roster API и не дают права изменять серверные результаты;
- административные/учебные права остаются на сервере; саморегистрация не добавлена;
- возврат ограничен известными внутренними страницами; активные задания и внешние URL не принимаются как сохранённое место возврата;
- неудачный отзыв на сервере честно отделён от завершённого локального входа сообщением пользователю;
- страницы и подтверждение выхода не обещают автоматического закрытия вкладки.

## Выполненный тест

Независимо запущен и прочитан `node tools/test_session_navigation.cjs` — PASS. Он исполняет действующий API-модуль с управляемыми отложенными HTTP-ответами и проверяет:

- поздний вход наблюдателя и администратора после отмены;
- отзыв отставшей серверной сессии;
- немедленное локальное завершение;
- старый logout после нового login;
- ошибку сети при выходе;
- работу при запрете sessionStorage;
- фильтр внутренних возвратов;
- различие `study`/`silent` для маршрутов смены и выхода.

Это проверка изменения клиентского жизненного цикла. Она не объявляет полную повторную сертификацию серверной аутентификации и не подменяет браузерный сценарий кнопок/модальных окон. При физическом удалении данных браузером или потере сети не заявляется сохранение неподтверждённых ответов.
