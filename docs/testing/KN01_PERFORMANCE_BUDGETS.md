## 1. Классы целевых устройств и бюджеты

Игра ориентирована на работу в университетских аудиториях, учебных классах гидрометеорологических техникумов и на персональных устройствах студентов. Выделяются 4 аппаратных профиля:

| Параметр бюджета | Tier 1: Настольный ПК / мощный ноутбук | Tier 2: Офисный ноутбук / планшет | Tier 3: Бюджетный смартфон (альбомная ориентация) | Аудиторный проектор (Classroom Display) |
|---|---|---|---|---|
| **Характерное «железо»** | Дискретный GPU / Apple Silicon, 8+ ГБ ОЗУ | Встроенный Intel Iris/UHD / Snapdragon 7xx, 4–8 ГБ | Встроенный GPU 3–5 летней давности, 2–3 ГБ | Встроенная графика преподавательского ПК |
| **Целевое разрешение** | 1920×1080 (логика 480×270 ×4) | 1366×768 (логика 480×270 ×2..×3) | 844×390 (логика 480×270 ×1..×2) | 1024×768 / 1920×1080 (крупный текст) |
| **Кадров/с (p50 / p95)** | **60 / 58** кадров/с | **60 / 55** кадров/с | **35 / 30** кадров/с | **60 / 58** кадров/с (строго без тиринга) |
| **Память текстур (VRAM)** | $\le 64\text{ МБ}$ | $\le 48\text{ МБ}$ | $\le 32\text{ МБ}$ | $\le 64\text{ МБ}$ |
| **Размер JS-бандла (gzip)** | $\le 450\text{ КБ}$ | $\le 450\text{ КБ}$ | $\le 450\text{ КБ}$ | $\le 450\text{ КБ}$ |
| **Суммарный вес растров** | $\le 2{,}5\text{ МБ}$ (спрайт-атласы) | $\le 2{,}5\text{ МБ}$ | $\le 1{,}8\text{ МБ}$ (сжатый атлас) | $\le 2{,}5\text{ МБ}$ |
| **Первая интерактивность (TTI)** | $\le 1{,}5\text{ с}$ | $\le 2{,}5\text{ с}$ | $\le 3{,}5\text{ с}$ (4G) / $\le 2{,}0\text{ с}$ (LAN) | $\le 2{,}0\text{ с}$ |
| **Допустимое падение кадров (jank)** | $\le 1$ фрейм в 60 с | $\le 2$ фрейма в 60 с | $\le 5$ фреймов в 60 с | 0 фреймов при демонстрации |
| **Восстановление WebGL** | $\le 500\text{ мс}$ без reload | $\le 800\text{ мс}$ без reload | $\le 1200\text{ мс}$ без reload | $\le 500\text{ мс}$ без reload |

## 2. Профили плотности и режимы рендеринга

Рендерер Phaser в `packages/world-engine` управляется профилями плотности, автоматически переключаемыми игровым состоянием, типом устройства и системными настройками доступности.

### 2.1. `hub-rich` (Полный живой мир)
- **Где включается:** экран хаба S06–S08 на устройствах Tier 1 и Tier 2 при нормальном энергопотреблении.
- **Активно:**
  - все 14 независимых циклов фоновой жизни (слои облаков, струйки дыма, покачивание деревьев, блики воды залива);
  - полная фауна (синицы, воробьи, чайка, кот Барограф, белка, голуби);
  - все NPC с анимациями ожидания и реакциями на клик;
  - динамическое освещение окон и фонарей в сумерках и ночью;
  - погодные частицы атмосферных осадков (до 60 одновременных частиц).

### 2.2. `study-calm` (Учебная концентрация)
- **Где включается:** рабочее место «Кодовый пост» (экраны S09–S12) во время выполнения заданий.
- **Цель:** исключить паразитное движение на периферии зрения, мешающее чтению бланка и телеграммы.
- **Правило отсечения:**
  - отключаются любые спонтанные случайные перемещения вне стола;
  - кот Барограф на телетайпе спит статично; анимация пробуждения/потягивания проигрывается **только как реакция на событие серии** ($\times 3, \times 5$);
  - пейзаж за окном рендерится с пониженной частотой кадров (2–4 кадра/с для медленного движения облаков);
  - эффекты частиц на экране стола строго локализованы (штамп, пылинка при ударе, перелёт значения);
  - не более 1 активного янтарного акцента на экране.

### 2.3. `battle-focus` (Спортивная концентрация)
- **Где включается:** режим «Блиц 90 с» и в будущем синоптическая дуэль.
- **Правило отсечения:**
  - мир за окном полностью заморожен в статичный кадр;
  - фоновые микро-анимации отключены;
  - активны только таймер, телетайпная лента, лампы серии и ввод ответа;
  - минимизация оверхенда WebGL для гарантированных 60 fps без микрофризов на замере времени.

### 2.4. `reduced-motion` (Уменьшенное движение)
- **Где включается:** системный медиа-запрос `prefers-reduced-motion: reduce` либо переключатель в настройках S17.
- **Обязательные требования доступности:**
  - все непрерывные перемещения бланков и телетайпной ленты заменяются на мгновенное переключение либо плавное растворение (crossfade $\le 150\text{ мс}$);
  - отключены вздрагивания при ошибке (`shake`);
  - мигания ламп и вспышки заменяются статичным изменением пиксельной пиктограммы (лампа зажглась / погасла);
  - частицы снега/дождя отключены.

### 2.5. `low-power` (Энергосбережение и аварийная деградация)
- **Где включается:**
  - автоматический детектор производительности: если средняя частота кадров падает ниже 28 fps в течение 3 последовательных секунд;
  - батарея устройства $\le 20\%$ при отсутствии внешнего питания;
  - устройства Tier 3 по умолчанию.
- **Что отключается:**
  - слои облаков L2 и L4 отключаются;
  - число животных сокращается до 2 активных;
  - анимации окружения переводятся на частоту 4 кадра/с;
  - динамические маски света и шейдеры выключаются, заменяясь статичным умножением цвета вершины (tint);
  - размер буфера частиц снижается до 10.

## 3. Методика инструментального замера

Для регулярного контроля бюджетов в CI и при локальной разработке используется утилита `tools/measure_performance.py` (или интеграция с Chrome DevTools Protocol):

1. **Замер веса сборки и ассетов:**
   ```bash
   python tools/measure_performance.py --assets
   ```
   Анализирует `apps/web/dist` и `apps/web/public`: суммарный вес JavaScript, CSS, шрифтов и растров хаба. Превышение порога 2,5 МБ для растров или 450 КБ для JS gzip приводит к коду возврата 1.

2. **Замер стабильности кадров/с (FPS harness):**
   Встроенный в `packages/world-engine` модуль `PerformanceMonitor` агрегирует дельту кадров за скользящее окно 300 кадров (5 секунд) и рассчитывает:
   - $p50$ (медиана) $= \text{quantile}(\Delta t, 0.50)^{-1}$;
   - $p95$ (95-й процентиль задержки) $= \text{quantile}(\Delta t, 0.95)^{-1}$;
   - счётчик выпавших кадров (jank frames, $\Delta t > 33{,}3\text{ мс}$).
   При тестовом прогоне `pnpm --filter @synopsis/web test:perf` эти метрики сериализуются в JSON-отчёт.

3. **Контроль памяти текстур:**
   ```ts
   const renderer = scene.game.renderer as Phaser.Renderer.WebGL.WebGLRenderer;
   const gl = renderer.gl;
   // Подсчёт суммарного размера загруженных WebGL текстур
   ```
   Лимит для хаба составляет строго 64 МБ VRAM.
