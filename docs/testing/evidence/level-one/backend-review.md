## Исходный материал

Использован принятый пакет `kn01_level1_pack@1.0.0`, без редактирования вопросов, объяснений или эталонных ответов:

1. `tmpl_c1_aaxx_header`.
2. `tmpl_c2_temp_vs_dewpoint`.
3. `tmpl_c2_sign_bit_sn`.
4. `tmpl_c2_positive_temp`.
5. `tmpl_c2_negative_dewpoint`.
6. `tmpl_c2_encode_temp`.

Три первых задания имеют выбор ответа, три следующих — числовой ввод. Последний идентификатор исторически содержит `encode`, однако вопрос и серверный тип требуют дешифрирования. Он не описывается как реализованное упражнение по кодированию.

Выбор передан методологом и обоснован в [методическом протоколе](methodology-review.md). Определения остаются отдельными учебными примерами: общая телеграмма или единый случай наблюдений не выдумывались. Для полного допуска требуется также независимая верификация.

При загрузке проверяются версия пакета, статус `approved`, разрешение публикации и отметки источников/методической/независимой проверки пакета, а также допуска каждого выбранного задания. Числовые эталоны повторно сверяются с настоящим кодеком; публичные задачи проходят `assertPublicTaskSafe`. Отсутствие допуска останавливает загрузку, а не молча заменяет задания.

## API

Все адреса используют существующую проверку сессии `identity.me`, затем `requireLevelOnePlayer` до чтения тела и обращения к сервису. Роль `display` получает 403, в том числе при сочетании с `admin` или другой игровой ролью: экрану доступно только публичное состояние трансляции согласно [архитектуре](../../../architecture/README.md). Идентификатор владельца берётся из проверенной сессии, а не из тела запроса. Администратор проходит к прежней проверке владения и не получает доступ к чужим прохождениям.

| Запрос | Результат |
|---|---|
| `GET /api/level-one` | Лобби, количество завершённых прохождений, лучший результат и активное либо последнее прохождение. Ничего не создаёт |
| `POST /api/level-one` с `requestId` | Начать, возобновить активное или повторно получить результат того же запроса |
| `GET /api/level-one/:id` | Текущее состояние или сохранённый итог собственного прохождения |
| `POST /api/level-one/:id/answer` с `instanceId`, `answer` | Один проверенный ответ, объяснение и актуальное состояние |
| `POST /api/level-one/:id/reference` с `instanceId` | Полная справка текущего задания, отметка помощи и неизменные заряды экипировки |

Точные интерфейсы находятся в [levelOneRules.ts](../../../../apps/server/src/modules/shift/levelOneRules.ts): `LevelOneLobbyView`, `LevelOneSessionView`, `LevelOneReview`. Для выбора используется `{ choiceIndex: number }`, для числового ответа — `{ value: number }`; нечисловые, пустые и бесконечные значения не считаются ответом.

Начальный запрос принимает строку `requestId` из 16–100 букв, цифр, подчёркиваний или дефисов. Повтор этого ключа возвращает тот же результат даже после завершения. Другой ключ при активном прохождении возобновляет его; новый ключ после завершения начинает новое прохождение. На одно прохождение разрешено не более 64 связанных ключей, после чего для восстановления используется GET.

## Сохранность и изоляция

- Прохождение, принятый ответ, отметка помощи и разбор записываются одной транзакцией существующего `TrainingStore`.
- Сбой записи не оставляет в памяти принятого ответа или фантомного начала. Повтор уже сохранённого ответа не нуждается в новой записи и возвращает актуальное состояние.
- Каждый ответ относится к текущему `instanceId`. Повтор того же ответа идемпотентен; другой ответ для принятой попытки отклоняется.
- Сохраняются разбор только принятых ответов и текущая открытая справка. Эталоны будущих задач в публичное состояние не включаются.
- Снимок комплекта и сохранённый PNG фиксируются при начале. Гардероб и повторное открытие активного уровня не заменяют их; новое явное прохождение получает новую сохранённую внешность.
- Справка не расходует предметы и доступна у каждого задания. Она содержит полное существующее объяснение; использовавший её ответ не считается самостоятельным.
- Обычная смена и блиц имеют отдельные состояния и маршруты. Старые методы обычной смены не принимают прохождение `level-one`.
- Восстановление проверяет последовательность задач, разбор, счётчики, отсутствие чужих наград, ключи запуска и единственность активного уровня пользователя. Повреждённые данные не сбрасываются автоматически.
