# Первый уровень: независимая проверка доступа и сохранности

**Дата:** 21 ноября 2026 года. **Проверяющий:** `/root/level_security_review`, роль `security-privacy-reviewer`. **Задача:** `LEVEL-ONE-PLAYABLE`.

**База:** `fac9275af6d6d0f53e4ca6d62035dc7fcf80120d`. **Ветка:** `agent/playable-level/level-one-character`. Проверено рабочее дерево; точные контрольные суммы приведены ниже. Проверяющий не писал продуктовую реализацию и не изменял её.

## Заключение

**`PASS` в границах новых серверных операций `/api/level-one` и узкого восстановления клиентской сессии при 401.** Блокирующих замечаний в проверенном изменении после исправления доступа роли `display` не осталось. Это не разрешение на публикацию в открытом Интернете и не приёмка всей игры, методики или графики.

Изначально новые маршруты проверяли только наличие сессии. Поэтому роль `display` могла начать собственное прохождение и получить учебные объяснения вопреки ограничению большого экрана в [архитектуре](../../../architecture/README.md). Исполнитель добавил [requireLevelOnePlayer](../../../../apps/server/src/modules/shift/levelOneAccess.ts). Повторно проверено: любая комбинация ролей с `display`, включая `admin`, получает 403. Все пять операций используют этот запрет до чтения тела или вызова сервиса. Администратор сохраняет собственный идентификатор и проходит обычную проверку владения.

## Изменение границ доверия

| Область | Проверенный результат |
|---|---|
| Сессия и владелец | Во всех действующих ветках [маршрутизатора](../../../../apps/server/src/index.ts) владелец определяется через `identity.me(bearer(request))`. Тело запроса не может заменить его. Общая проверка сессии отклоняет отсутствующий, истёкший или неактивный сеанс. |
| Чужое прохождение | `GET /api/level-one/:id`, `POST .../answer` и `POST .../reference` вызывают методы с идентификатором проверенного пользователя. Сервис возвращает 404 для другого владельца до выдачи состояния или изменения попытки. Проверено отрицательными вызовами настоящего сервиса. |
| Большой экран | Обе точные ветки `/api/level-one` и общая ветка `/:id[/answer\|/reference]` вызывают запрет роли `display`. Условия HTTP-методов и порядок вызовов прочитаны в исходном маршрутизаторе; сетевой обработчик не запускался. |
| Скрытые ответы | Начальная выдача содержит только текущую публичную задачу. Серверные данные проверки, будущие задачи, ключи запуска и эталоны не включены. Разбор добавляется после принятого ответа; полное объяснение текущей задачи открывается по явному запросу справки владельцем и отмечает помощь. |
| Повтор запроса | Ключ запуска ограничен форматом и длиной, связан с владельцем, сохраняется после завершения. На прохождение допускается до 64 ключей; 65-й отклоняется с 429, старый ключ и GET работают. Одновременные одинаковые ответы дают одну попытку; изменение принятого ответа даёт 409. |
| Сохранение | `TrainingStore` возвращает копии, сериализует транзакции и меняет состояние памяти после успешной записи. Сбой записи не создаёт прохождение или принятый последний ответ. Восстановление проверяет задачи, разбор, счётчики, ключи, помощь и отсутствие наград другого режима. |
| Недоверенный ввод | Общий JSON-парсер ограничивает тело 32768 байтами и требует объект. Для числа допускается только конечное значение типа `number`; пустая строка, строковое число, `null`, `NaN` и бесконечность не становятся нулевым ответом. Индекс выбора проверяется по допустимым вариантам. |
| Отделение режимов | Завершение `level-one` не увеличивает счётчик обычных смен, не начисляет их награды, не открывает блиц и не записывает квалификацию. Методы ответа и результата обычной смены отклоняют прохождение уровня. |

## Восстановление входа

В [api.ts](../../../../apps/web/src/api.ts) токен фиксируется до отправки запроса. При 401 очищается только этот токен, если он всё ещё текущий. Затем отправляется обычное событие без дополнительных данных. Поздний 401 прежнего аккаунта не закрывает новый. Ошибка входа, отсутствие токена до запроса и 403 прав не создают события истечения.

В [App.tsx](../../../../apps/web/src/App.tsx) обработчик события убирает пользователя и форму смены кода. Путь уровня или настройки персонажа сохраняется; условие маршрута показывает существующий экран входа с сообщением. Предыдущий ответ начальной проверки сессии не восстанавливает пользователя после замены токена. Это подтверждено чтением переходов состояния, без утверждения о проверке DOM или реальной клавиатуры.

## Границы заключения

HTTP-сервер, браузер, DOM, сеть между клиентом и сервером и реальное устройство не использовались. Проверка привязки авторизации к маршрутам выполнена по настоящему `index.ts`; отрицательные операции — через настоящий сервис, а не через HTTP. Существующая выдача кодов, политика `codeSet` и пригодность общей модели входа для публичного размещения остаются за пределами этого изменения. Проверка снимка не является защитой от произвольной подмены доверенного серверного диска. Методические эталоны, художественный стиль, источники ресурсов и доступность интерфейса принимаются соответствующими независимыми ролями.
