# Настройка персонажа перед первым уровнем

**Дата:** 21 ноября 2026 года.

**Задача:** `LEVEL-ONE-CHARACTER`. **Исполнитель:** `/root/character_setup`, роли `identity-avatar-engineer` и `ui-pixel-designer`.

**База:** `fac9275af6d6d0f53e4ca6d62035dc7fcf80120d`. **Ветка:** `agent/playable-level/level-one-character`.

## Результат

Редактор получил законченный путь от примерки к первому уровню. Он сохраняет образ перед переходом, если изменены вещи, отсутствует подтверждённый портрет или доступна новая версия изображения. Если образ уже сохранён, продолжение не отправляет лишний запрос записи. Настройка остаётся добровольной: решение о входе в редактор принимает основной маршрут игры.

Реализация следует решению [R04](../../../design/MODULAR_CHARACTER_SAVED_PORTRAIT_R04.md): статичная примерка в редакторе, готовый одетый портрет в игре. Новая графика, анимация личного персонажа, научные правила и серверная модель личности не изменялись.

## Контракт для основного маршрута

`AvatarEditor` сохраняет прежние `user`, `onSaved` и `onBack` и принимает необязательные параметры:

| Параметр | Значение |
| --- | --- |
| `onContinueToLevel?: () => void` | Действие перехода к уровню. Вызывается после принятого ответа сохранения, либо сразу для уже подтверждённого неизменённого образа |
| `continueLabel?: string` | Подпись готового перехода; по умолчанию «К первому уровню» |
| `backLabel?: string` | Подпись возврата; по умолчанию «На станцию» |
| `initialSection?: 'inventory' \| 'badges' \| 'appearance'` | Начальная вкладка; без портрета по умолчанию открывается внешность, с портретом — инвентарь |

Для входа из уровня основной маршрут может передать `initialSection="appearance"`, `backLabel="К уровню"` и нужный обработчик возврата. Изменение выбранной маршрутом вкладки не переинициализирует примерку и не теряет локальные изменения.

Если `onContinueToLevel` отсутствует, обычное сохранение по-прежнему оставляет пользователя в редакторе. Если присутствует, основная кнопка называется «Сохранить и продолжить», когда требуется запись; после сохранения она использует `continueLabel`. Самостоятельное сохранение и отмена изменений остаются доступными вторичными действиями.

## Границы подтверждения сохранения

Продолжение отклоняется, если ответ относится к другому аккаунту, возвращает другой набор вещей, не содержит допустимого портрета или оставляет прежний `appearanceKey` после изменения внешности. `onSaved` получает подтверждённый профиль раньше вызова перехода.

Клиент проверяет структуру и согласованность ожидаемого ответа. Он не пересчитывает криптографическую связь всех полей с PNG: создание картинки, канонический ключ, контрольная сумма и атомарность записи остаются ответственностью серверного сервиса портретов. Проверка известных серверных изображений в прежнем наборе тестов сохраняется.

Снимок уже начатой смены или уровня редактор не меняет. Новый образ используется при создании следующей работы. При сетевой ошибке или тайм-ауте переход не выполняется, прежний подтверждённый портрет остаётся на месте, примерка сохраняется для повторной попытки. Ответ предыдущего аккаунта после смены пользователя игнорируется.

Первый запуск старого `test_modular_avatar` выявил несовпадающий ответ проверочного примера: отправлялась только новая куртка, а ответ менял также волосы, головной убор и обувь. Новый защитный код правильно отверг такой ответ. Проверочный пример исправлен, чтобы перед успешной попыткой отправлялся именно заявленный комплект. Следующая остановка выявила отсутствовавшую зависимость `shiftLore` в том же изолированном стенде; она добавлена. После этих исправлений проверка прошла.

## Открытая приёмка

**Это реализация и небраузерные проверки, без самостоятельной художественной или интеграционной приёмки.** Стенд выполняет реальные обработчики с подставленными часами, состоянием React и ответами сервиса; он не проверяет настоящий DOM и сеть.

Браузер в этой задаче не открывался вследствие ранее установленного ограничения доступа к предпросмотру. Требуются независимая проверка кода и фактические снимки/взаимодействия на 1366×768, 390×844 и 844×390: переход из первого уровня, сохранение, возврат, чтение подписи о начатом уровне, фокус и работа клавиатуры, отсутствие перекрытий и удобство переноса кнопок. Серверные правила личности и портретов в этой задаче не редактировались.
