# 04. Учебный контент и типы заданий

## 1. Принцип контентной системы

Движок игры не должен содержать конкретные учебные ответы. Он должен поддерживать универсальные типы заданий, а содержание хранится в пакетах данных.

Цели:

- преподаватель добавляет задания без изменения кода;
- одна и та же механика используется в solo/PvP/экзамене;
- методические варианты поддерживаются профилями;
- каждый ответ имеет объяснение и источник;
- контент можно валидировать автоматически.

## 2. Базовые типы заданий

### `choice`

Один правильный вариант.

Примеры:

- выбрать обозначение;
- определить тип барического образования;
- выбрать следующий шаг анализа.

### `multiChoice`

Несколько правильных вариантов.

Примеры:

- выбрать признаки фронта;
- отметить все физически согласованные наблюдения.

### `sequence`

Расставить действия по порядку.

Ключевая механика для:

- первичного анализа;
- фронтологического анализа;
- обработки аэрологической диаграммы;
- прогностической схемы.

Поддерживает эквивалентные перестановки через `allowed_swaps`.

### `dragDrop`

Перетащить объект в область.

Примеры:

- схема нанесения станции;
- символ явления;
- положение элемента на карте.

### `stationPlot`

Специализированный конструктор схемы нанесения метеорологических данных вокруг кружка станции.

Проверяется отдельно каждый компонент:

- T;
- Td;
- p;
- тенденция;
- ветер;
- N/Nh;
- ww;
- W1/W2;
- CL/CM/CH;
- видимость и другие элементы профиля.

### `decode`

Раскодировать группу/телеграмму.

### `encode`

Из физических величин сформировать кодовую группу.

### `hotspot`

Указать точку/линию/область на карте.

Примеры:

- центр циклона;
- ось ложбины;
- участок фронта;
- подозрительная станция;
- зона ВФЗ.

### `drawLine`

Провести линию с допуском.

Примеры:

- изобара;
- изаллобара;
- фронт;
- ось струйного течения.

Проверка должна учитывать геометрию и допустимый коридор, а не точное совпадение пикселей.

### `findError`

Найти ошибку или противоречие.

### `compare`

Сопоставить два срока/уровня/источника данных.

### `classify`

Классифицировать объект/явление.

### `numeric`

Ввести численное значение с единицами и допуском.

### `scenario`

Многошаговая задача с состоянием и ветвлением.

## 3. Микрозадания для 5–15 секунд

- распознать ww;
- выбрать символ фронта;
- В или Н;
- П или Р;
- восстановить давление из сокращённой записи;
- декодировать T/Td;
- прочитать направление/скорость ветра;
- поставить один элемент схемы станции;
- выбрать физически невозможное сочетание;
- выбрать правильный следующий шаг.

## 4. Задания средней длины

- собрать всю станцию;
- найти ошибочную станцию среди 5–7;
- провести участок изобары;
- провести изаллобару;
- определить центр и оси барического поля;
- определить предполагаемое положение фронта;
- сопоставить приземную карту и АТ-850;
- определить тепло/холод по ОТ1000/500;
- оценить перемещение объекта по последовательным срокам.

## 5. Комплексные задания

- полный первичный анализ фрагмента карты;
- фронтологический анализ;
- анализ циклона в нескольких сроках;
- комплекс АТ/ОТ;
- вертикальный разрез;
- аэрологическая диаграмма;
- прогноз по ПЭСМ;
- кейс ОЯ;
- авиационный кейс.

## 6. «Алгоритмический конструктор»

Сложность растёт по ступеням:

1. готовые карточки без лишних шагов;
2. карточки + ложные шаги;
3. часть шагов скрыта;
4. нужно выбрать только следующий шаг;
5. свободное воспроизведение;
6. применение на карте.

Ошибка должна объяснять **нарушенный принцип**, например:

- историческая последовательность;
- трёхмерность;
- критика наблюдений;
- чистота/технология оформления карты;
- недостаточность одного признака.

## 7. «Критика наблюдений»

Набор шаблонов:

- неверный знак температуры;
- ошибка давления;
- неверная тенденция;
- ошибочное направление ветра;
- внутренняя несогласованность погоды и облачности;
- противоречие T/Td;
- резкий выброс относительно соседей;
- невозможная временная эволюция;
- неверное нанесение при корректной исходной телеграмме.

Для каждого кейса хранить причину и степень уверенности.

## 8. «Орографическая изобара»

Продвинутый тренажёр:

- рельеф отображается отдельно;
- игрок должен понять, где обычная интерполяция давления через хребет некорректна;
- провести/выбрать корректное соединение согласно профилю курса;
- получить объяснение физического смысла.

## 9. Фронтология

Нельзя использовать примитивную задачу «температура резко изменилась → здесь фронт» как эталон.

Минимальный набор данных для продвинутого фронтологического задания:

- предыдущий срок;
- приземное барическое поле;
- ветер;
- барическая тенденция;
- T/Td;
- облачность/осадки;
- АТ-850;
- при необходимости ОТ1000/500 и другие высотные данные.

Задача может постепенно открывать слои, чтобы студент учился порядку анализа.

## 10. ПЭСМ-сценарий

Структура:

### П — перемещение

- история объекта;
- ведущий поток;
- траектория;
- возможное положение к сроку прогноза.

### Э — эволюция

- углубление/заполнение;
- развитие/размывание фронтов;
- изменения поля.

### С — суточный ход

- температура;
- туман/конвекция и другие зависящие от времени суток элементы.

### М — местные факторы

- рельеф;
- водоёмы;
- побережье;
- город;
- локальные циркуляции в рамках курса.

## 11. Реальные и синтетические данные

### Комплексные сценарии

Приоритет — реальные архивные ситуации с известным сроком, источником и набором карт.

### Синтетика допустима

Для:

- тренировки одной группы кода;
- схемы станции;
- условных обозначений;
- численных drill-задач;
- генерации эквивалентных PvP-вариантов.

Такие задачи маркируются `data_origin: synthetic_drill`.

Нельзя выдавать синтетическую карту за реальный исторический случай.

## 12. Объяснение после ответа

Минимальный feedback:

- правильность;
- правильный ответ;
- краткое «почему»;
- нарушенный принцип;
- ссылка/идентификатор источника;
- при необходимости визуальная подсветка.

В Ranked подробное объяснение показывается после закрытия вопроса/раунда, чтобы не давать подсказку сопернику.

## 14. Интервальное повторение

Для каждого concept/skill хранить:

- число попыток;
- число корректных;
- последние попытки;
- streak;
- дату последней практики;
- difficulty distribution;
- confidence/mastery;
- типичные ошибки.

Планировщик выдаёт задания с учётом забывания и слабых мест.

## 15. Экзаменационный режим

Отличия:

- без игровых атак;
- без подсказок;
- фиксированный content pack;
- фиксированная версия методики;
- детальный audit log;
- ограничение повторной попытки задаётся курсом;
- итог можно экспортировать преподавателю.

## 16. Генерация эквивалентных PvP-задач

Генератор должен обеспечивать:

- одинаковую структуру;
- одинаковое число операций;
- близкую статистическую сложность;
- отсутствие неоднозначности;
- детерминированность по seed;
- серверную проверку.

Каждый generated task проходит property-based validation там, где возможно.

## 17. Контент-пайплайн

1. автор создаёт draft;
2. автоматическая schema validation;
3. методическая проверка;
4. проверка формулировки/неоднозначности;
5. dry-run;
6. публикация в versioned content pack;
7. сбор статистики;
8. recalibration difficulty;
9. при ошибке — deprecate/replace без изменения истории старых replay.

## 18. Минимальный content pack MVP

Рекомендуемый стартовый объём по категориям:

- условные знаки;
- КН-01;
- схема станции;
- В/Н, П/Р;
- критика наблюдений;
- изобары;
- базовые алгоритмы;
- простая фронтология;
- АТ-850/ОТ intro.

Количество вопросов не фиксируется этим документом: важнее достаточное разнообразие и статистическая калибровка, чем искусственное достижение заданной цифры.
