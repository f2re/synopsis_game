# Реализация закрытого доступа, панели администратора и персонажа

**Статус:** первый рабочий срез

Связанные задачи: `IDENTITY-001` (#12), `ADMIN-001` (#13), `AVATAR-001` (#14).

## 1. Граница регистрации

Публичной саморегистрации нет. Под «регистрацией пользователя» в первом рабочем срезе понимается создание записи администратором в закрытом списке.

Первоначальный администратор создаётся локально через `SYNOPSIS_BOOTSTRAP_ADMIN_CODE`. После этого новые пользователи создаются только из `/admin`.

## 2. Поток входа

```text
группа → профиль → персональный код → серверная проверка → сессионный токен → Hub
```

Код не сохраняется открытым текстом. Сервер хранит случайную соль и `scrypt`-verifier. После серии ошибок включается временная блокировка профиля и пары адрес/профиль.

Сессионный токен хранится браузером в `sessionStorage` и теряется при завершении сессии браузера.

## 3. Панель администратора

Маршрут `/admin` доступен только пользователю с ролью `admin`; это проверяется и клиентом, и каждым административным API на сервере.

Первый срез позволяет:

- видеть пользователей, группы, роли и состояние;
- создавать пользователя с начальным кодом;
- отключать и включать профиль;
- сбрасывать код;
- немедленно завершать сессии отключённого пользователя или пользователя со сброшенным кодом.

Verifier, salt и другие закрытые поля в административный интерфейс не передаются.

## 4. Внешность персонажа

Маршрут `/profile/avatar` использует стабильные идентификаторы слоёв:

```text
skinTone
hair
hairColor
headwear
top
bottom
footwear
backpack
heldItem
companion
badge
```

Текущий 32×48 preview является программным пиксельным прототипом. Когда будут готовы `.aseprite`-слои, значения полей и semantic ID сохраняются, меняется только renderer.

Базовые варианты доступны сразу и являются исключительно косметическими.

## 5. API первого среза

Публично до входа:

- `GET /api/identity/groups`;
- `GET /api/identity/roster?group=...`;
- `POST /api/identity/login`.

Для сессии:

- `GET /api/identity/me`;
- `POST /api/identity/logout`;
- `PATCH /api/identity/avatar`.

Для `admin`:

- `GET /api/admin/users`;
- `POST /api/admin/users`;
- `PATCH /api/admin/users/:id/status`;
- `POST /api/admin/users/:id/reset-code`.

`/arena-tv` не использует эти приватные API и не получает список пользователей.

## 6. Ограничения первого среза

- сессии пока хранятся в памяти процесса и сбрасываются при перезапуске сервера;
- локальное файловое хранилище предназначено для первого рабочего прототипа, а не для многосерверного развёртывания;
- импорт CSV/JSON, единый вход учреждения и привязка доверенного устройства остаются следующими этапами;
- роли при создании уже поддерживаются сервером, но интерфейс первого среза назначает одну основную роль за операцию создания.
