# 09. Политика источников и методической верификации

## 1. Зачем это нужно

Для «Синоптического центра» недостаточно, чтобы ответ выглядел правдоподобно. Учебное правило должно быть:

- прослеживаемым до конкретного источника;
- привязанным к редакции и году;
- отделённым от игровых условностей;
- отделённым от локальной кафедральной методики;
- воспроизводимым при разборе старых матчей.

## 2. Классы авторитетности

Машинные значения полей остаются английскими, но их смысл в документации формулируется по-русски.

### A — `official_current` — действующий официальный документ

Действующий нормативный или методический документ Росгидромета, Гидрометцентра России либо другого уполномоченного органа.

Используется для утверждений вида «в актуальной оперативной практике» или «согласно действующему нормативу».

### B — `classic_textbook` — фундаментальный отечественный учебник

Используется для понятий, классического синоптического метода и исторически сложившихся приёмов.

### C — `university_practicum` — вузовский практикум

Используется для технологии выполнения учебных операций.

### D — `department_custom` — кафедральная методика

Допустима, если явно названа и не выдаётся за общий норматив.

### E — `project_assumption` — проектное решение игры

Не может использоваться как источник метеорологического знания.

## 3. Правило конфликта источников

Если классический учебник и действующий норматив расходятся:

- нельзя молча «исправлять» один другим;
- создаются отдельные методические профили или версии правила;
- в современном оперативном режиме приоритет имеет актуальный официальный документ;
- в историческом или учебном режиме допускается классическая редакция с явной маркировкой.

## 4. Основные источники, использованные при формировании концепции

### 4.1. А. С. Зверев, «Синоптическая метеорология», 1977

Классический источник для:

- определения синоптического метода;
- структуры первичного анализа;
- понятия подъёма карты;
- критики данных;
- исторической последовательности;
- правила ведущего потока;
- схемы ПЭСМ.

Электронная копия, использованная для проектной сверки:

https://djvu.online/file/xhZZFjpf3uPUm

Перед формальным выпуском следует использовать проверенный библиографический экземпляр или скан и зафиксировать страницы для каждого правила.

### 4.2. Методический кабинет Гидрометцентра России

Официальная страница нормативных и методических документов:

https://method.meteorf.ru/norma/norma.html

На странице опубликованы, в частности:

- РД 52.27.724-2019 «Наставление по краткосрочным прогнозам погоды общего назначения»;
- РД 52.27.723-2009 «Базовые требования к технологии подготовки краткосрочных прогнозов погоды»;
- методические материалы по ДМРЛ-С;
- КН-01 SYNOP;
- другие специализированные руководства.

Для публикуемого учебного содержания необходимо сохранять точную редакцию и дату документа, а не ссылаться только на общий каталог.

### 4.3. КН-01 SYNOP

На официальной странице Методического кабинета опубликован «Код для оперативной передачи данных приземных метеорологических наблюдений с сети станций Росгидромета (КН-01 SYNOP)».

В реестре источников необходимо хранить:

- точное название;
- редакцию;
- дату загрузки или проверки;
- контрольную сумму разрешённой копии либо иной устойчивый идентификатор;
- область применения.

### 4.4. РГГМУ — практикум по синоптической метеорологии

В библиографическое ядро включается «Практикум по синоптической метеорологии» под редакцией В. И. Воробьёва в конкретной используемой редакции.

До публикации заданий на его основе необходимо занести точное издание в реестр и указать страницы или разделы.

### 4.5. С. П. Хромов, В. И. Воробьёв, Н. А. Дашко и другие отечественные источники

Используются как элементы российской синоптической школы и учебного курса. Для каждого правила требуется конкретная запись `Source`; фамилия автора без произведения и редакции недостаточна.

## 5. Проверка актуальности документов

Перед выпуском каждого крупного пакета учебного содержания проверяется:

- не появилась ли новая редакция РД;
- актуален ли КН;
- не заменён ли документ;
- не изменились ли критерии опасных явлений;
- не обновились ли методики МРЛ или спутникового анализа;
- не изменилась ли терминология.

Результат проверки фиксируется датой.

## 6. Реестр источников — обязательные поля

```json
{
  "id": "...",
  "type": "regulatory_method | textbook | practicum | department_note",
  "title": "...",
  "authors": ["..."],
  "issuer": "...",
  "year": 2019,
  "edition": "...",
  "document_number": "...",
  "authority": "official_current",
  "url": "...",
  "checked_at": "2026-10-25",
  "status": "active",
  "notes": "..."
}
```

Это технические поля схемы данных; их имена не переводятся.

Дополнительно для конкретного правила:

```json
{
  "source_id": "ZVEREV_1977",
  "locator": {
    "chapter": "3",
    "section": "3.4",
    "page": null
  }
}
```

## 7. Требование к источнику в `TaskDefinition`

Эталонное задание обязано иметь минимум один источник, кроме чисто технических учебных упражнений по интерфейсу.

```json
"sources": [
  {
    "source_id": "ZVEREV_1977",
    "locator": "chapter_3_section_3_4"
  }
]
```

## 8. Статусы проверки

В человекочитаемой документации используются:

- **черновик** — автор подготовил задание;
- **источник проверен** — ссылка и реквизиты подтверждены;
- **методически проверено** — выполнена предметная проверка;
- **проверено на пилотной группе** — студенты прошли задание без существенной неоднозначности;
- **опубликовано** — включено в выпускаемый пакет;
- **устарело** — больше не выдаётся новым игрокам;
- **отозвано** — обнаружена содержательная ошибка.

Машинные значения `draft`, `source_checked`, `method_reviewed`, `pilot_validated`, `published`, `deprecated`, `revoked` сохраняются только внутри схем данных и автоматизированных проверок.

## 9. Требование к спорным численным правилам

Любой коэффициент, порог или шаг, который может зависеть от:

- типа карты;
- редакции методики;
- региона;
- сезона;
- прогностического метода;
- кафедры,

хранится в учебном содержании или методическом профиле вместе с источником.

Запрещено встраивать такие значения как универсальную константу игрового движка.

## 10. Реальные архивные данные

Для каждого сценария хранится происхождение данных:

- поставщик;
- дата и срок;
- станционная, модельная, радиолокационная или спутниковая природа данных;
- выполненные преобразования;
- лицензия или право использования;
- контрольная сумма исходного файла;
- описание предварительной обработки.

Если изображение карты вручную размечено для игры, исходный материал и слой разметки хранятся отдельно.

## 11. Синтетические задания

Синтетические данные допустимы для учебных упражнений, если:

- физические величины валидны;
- генератор протестирован;
- задача не выдаётся за реальное наблюдение;
- используется машинная метка `data_origin = synthetic_drill`;
- синтетика не используется для доказательства реальной метеорологической закономерности.

## 12. Содержание, созданное с помощью ИИ

ИИ может:

- предложить формулировку;
- подготовить черновик ложного варианта ответа;
- разметить текст;
- помочь сформировать JSON.

Но правильный ответ, предложенный ИИ, **не публикуется без детерминированной проверки или независимой методической приёмки**.

Для карт и сложных физических задач обязательна экспертная проверка.

## 13. Цитирование внутри игры

Студенту не требуется показывать полную библиографию после каждого короткого вопроса.

Но из объяснения должна быть доступна кнопка «Источник», открывающая:

- название документа или учебника;
- раздел;
- редакцию;
- статус методического профиля.

## 14. Автоматическая проверка терминологии

Для профиля `RUS_CLASSIC_*` автоматические правила могут выявлять:

- `L/H` вместо В/Н в русском эталонном учебном слое;
- использование «подъём карты» как синонима всего анализа;
- конфликтующие версии одного идентификатора правила;
- отсутствие источника;
- устаревший статус источника.

Автоматическая проверка не заменяет методиста.

## 15. Методическая приёмка проекта

Перед публичным выпуском рекомендуется иметь минимум два независимых уровня проверки:

1. предметный специалист или преподаватель синоптической метеорологии;
2. независимый метеорологический верификатор, повторно выводящий правильный ответ и проверяющий неоднозначность.

Дополнительно редактор учебного содержания проверяет формулировку, ясность и структуру объяснения.

Для спорного рейтингового вопроса лучше временно исключить задание, чем решать спор по статистическому большинству игроков.

## 16. Золотое правило

Если команда не может ответить на вопрос:

> «Из какого источника, какой редакции и по какому методическому профилю это считается правильным?»

такое задание не должно попадать в рейтинговый или экзаменационный режим.
