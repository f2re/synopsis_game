# Автономный экран арены — зрительский и демонстрационный режим

**Статус:** принятая концепция

## 1. Цель

Большой экран должен работать **самостоятельно** без преподавателя или оператора. Он является частью продукта и должен удерживать внимание студентов, школьников, гостей кафедры и участников дня открытых дверей.

## 2. Основные режимы большого экрана

Клиент большого экрана, имеющий техническое имя `Arena TV` или `display`, автоматически переключается между:

- текущим матчем;
- финалом или полуфиналом;
- матчем сильнейших игроков;
- близким по счёту матчем;
- массовым блицем;
- таблицей лидеров;
- коротким повтором яркого момента;
- экраном достижений и сезона;
- живым центром в демонстрационном режиме, если активных матчей нет.

## 3. Выбор интересного матча

Сервис `broadcast-selector` периодически оценивает активные матчи.

Техническая формула может использовать внутренние коэффициенты:

```text
priority =
  tournament_stage_weight
+ player_rating_weight
+ score_closeness_weight
+ streak_weight
+ audience_interest_weight
+ freshness_weight
```

В пользовательской логике приоритет выглядит так:

1. финал;
2. полуфинал;
3. матч игроков с высоким рейтингом;
4. очень близкий матч;
5. матч с необычной серией или камбэком;
6. массовый блиц;
7. повтор яркого момента;
8. демонстрационный живой центр.

## 4. Автоматическое переключение

Экран не должен перескакивать между матчами каждую секунду.

Правила:

- для каждой сцены задаётся минимальное время показа;
- матч не переключается в середине критического задания без веской причины;
- после завершения показывается короткий итог;
- затем сервис выбирает следующую сцену;
- переход занимает несколько секунд и визуально объясняет смену контекста.

## 5. Состояния большого экрана

Технические состояния автомата остаются стабильными:

```text
BOOT
  ↓
ATTRACT
  ↓
LIVE_MATCH
  ↓
RESULT
  ↓
HIGHLIGHT / LEADERBOARD
  ↓
LIVE_MATCH or ATTRACT
```

Дополнительно:

- `OFFLINE_FALLBACK` — резервный режим при потере связи;
- `MAINTENANCE` — обслуживание;
- `EVENT_INTRO` — вступление к мероприятию.

Имена состояний являются частью программного контракта. В интерфейсе им соответствуют русские названия.

## 6. Демонстрационный режим

Если активных матчей нет, экран показывает живой центр:

- смену времени суток;
- птиц и животных;
- активность помещений;
- рейтинг и сезон;
- короткие факты о работе синоптика;
- последние достижения;
- небольшой демонстрационный повтор;
- пояснение, какую тему сейчас осваивают игроки.

Этот режим должен быть интересен человеку без учётной записи и без знания правил игры.

## 7. Что показывается во время матча

Минимум:

- имена или игровые псевдонимы;
- персонажи;
- лига или рейтинг в компактном виде;
- текущая Надёжность;
- тема задания;
- карта или задача;
- оперативный ресурс и серия;
- важные события;
- текущий раунд и время.

Правильный ответ скрывается до момента, разрешённого правилами матча.

## 8. Автоматическое пояснение для внешней аудитории

Для школьников и гостей большой экран может кратко пояснять происходящее:

> «Игроки определяют атмосферный фронт по комплексу признаков»

или

> «КН-01 — кодированное метеорологическое сообщение станции».

Это отдельный пояснительный слой зрительского интерфейса. Он не появляется на экране игрока и не подсказывает ответ до закрытия задания.

## 9. Автоматическое выделение ярких моментов

Система может помечать:

- камбэк;
- длинную серию;
- парирование или контратаку;
- быстро решённую сложную задачу;
- победу с минимальным остатком Надёжности;
- новый личный или групповой рекорд;
- финальный раунд.

По журналу событий короткие фрагменты воспроизводятся без записи видеопотока.

## 10. Преподаватель не является оператором

Для обычной эксплуатации преподаватель не должен нажимать:

- «начать трансляцию»;
- «выбрать матч»;
- «показать результат»;
- «переключить экран».

Администратор может иметь принудительное управление для исключительных случаев, но система должна полноценно работать без него.

## 11. Постоянная работа на проекторе или телевизоре

Клиент большого экрана должен уметь:

- запускаться сразу в полноэкранном режиме;
- автоматически входить с технической ролью `display`;
- переподключаться после обрыва;
- восстанавливать текущую сцену;
- работать длительно без ручного вмешательства;
- не показывать административные секреты;
- иметь механизм самовосстановления и перезапуска.

## 12. Приватность

На публичном экране показываются только разрешённые данные:

- отображаемое имя;
- персонаж;
- игровые показатели;
- группа или команда, если это разрешено.

Не показываются:

- код входа;
- адрес электронной почты;
- внутренние идентификаторы;
- техническая диагностика;
- персональные учебные комментарии.

## 13. API большого экрана

Рекомендуемые технические каналы:

```text
GET /broadcast/state
GET /broadcast/schedule
WS  /broadcast/live
GET /broadcast/highlights
GET /broadcast/leaderboard
```

Пути API не переводятся. Сервис `broadcast-selector` читает состояние матчей и журнал событий, но не меняет результат матча.

## 14. Резервное поведение

Если сервер сетевых матчей временно недоступен:

1. показывается последняя подтверждённая таблица лидеров;
2. затем локальный пакет воспроизведений;
3. затем живой центр;
4. при необходимости — автономный информационный экран.

Пустой чёрный экран недопустим.

## 15. Критерии готовности

- [ ] большой экран запускается без преподавателя;
- [ ] самостоятельно выбирает активный матч;
- [ ] после завершения показывает итог и выбирает следующую сцену;
- [ ] при отсутствии матчей переходит в демонстрационный режим;
- [ ] может работать несколько часов без ручного управления;
- [ ] правильный ответ не раскрывается преждевременно;
- [ ] существует резервный режим при потере сервера;
- [ ] публичные данные отделены от приватных;
- [ ] финалы и действительно интересные матчи получают повышенный приоритет;
- [ ] зрительский интерфейс читается с нескольких метров.
