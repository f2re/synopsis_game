# Autonomous Arena Display — unattended spectator / attract mode

**Статус:** accepted-concept

## 1. Цель

Большой экран должен работать **самостоятельно** без преподавателя или оператора. Он является частью продукта и должен удерживать внимание аудитории: студентов, школьников, гостей кафедры, участников дня открытых дверей.

## 2. Основные режимы экрана

`Arena TV` автоматически переключается между:

- live battle;
- финалом/полуфиналом;
- матчем сильнейших игроков;
- близким по счёту матчем;
- массовым блицем;
- leaderboard;
- коротким replay;
- экраном достижений/сезона;
- живым хабом в attract-mode, если активных матчей нет.

## 3. Match selector

Сервис `broadcast-selector` периодически ранжирует активные матчи.

Пример факторов:

```text
priority =
  tournament_stage_weight
+ player_rating_weight
+ score_closeness_weight
+ streak_weight
+ audience_interest_weight
+ freshness_weight
```

Приоритеты по умолчанию:

1. финал;
2. полуфинал;
3. матч top-rated игроков;
4. очень близкий live match;
5. матч с необычной серией/камбэком;
6. массовый блиц;
7. replay highlight;
8. attract hub.

## 4. Автопереключение

Экран не должен дёргаться между матчами каждую секунду.

Правила:

- минимальное время показа активной сцены;
- матч не переключается в середине критического задания без веской причины;
- при завершении матча показывается короткий result sting;
- затем selector выбирает следующую сцену;
- переходы занимают несколько секунд и имеют понятный визуальный контекст.

## 5. Состояния broadcast state machine

```text
BOOT
  ↓
ATTRACT
  ↓
LIVE_MATCH
  ↓
RESULT
  ↓
HIGHLIGHT / LEADERBOARD
  ↓
LIVE_MATCH or ATTRACT
```

Дополнительно:

- `OFFLINE_FALLBACK`;
- `MAINTENANCE`;
- `EVENT_INTRO`.

## 6. Attract mode

Если матчей нет, экран показывает живой центр:

- смену дня/ночи;
- птиц и животных;
- активность помещений;
- рейтинг/сезон;
- короткие факты о синоптике;
- последние достижения;
- небольшой demo replay;
- объяснение, что сейчас изучают игроки.

Attract mode должен быть интересен человеку без аккаунта.

## 7. Что показывается в live battle

Минимум:

- имена/ники;
- аватары;
- лига/рейтинг в компактном виде;
- текущая Надёжность;
- тема задания;
- карта/задача;
- OR/combo;
- важные события;
- текущий раунд/таймер.

Правильный ответ скрывается до момента, разрешённого правилами матча.

## 8. Автоматическое объяснение для внешней аудитории

Для школьников/гостей spectator UI может кратко пояснять термин:

> «Игроки определяют атмосферный фронт по комплексу признаков»

или

> «КН-01 — кодированное метеорологическое сообщение станции»

Это отдельный spectator-help layer, который не появляется на экране игрока и не подсказывает ответ до закрытия задания.

## 9. Highlight engine

Система может помечать события:

- comeback;
- серия ×N;
- parry/counter;
- сложное задание решено быстро;
- победа с минимальным остатком Reliability;
- новый личный/групповой рекорд;
- финальный раунд.

На основе event log можно автоматически показывать короткие replay-фрагменты без видеозаписи.

## 10. Преподаватель не оператор

Для обычной эксплуатации преподаватель не должен нажимать:

- «начать трансляцию»;
- «выбрать матч»;
- «показать результат»;
- «переключить экран».

Он может иметь admin override, но система должна полноценно работать без него.

## 11. Kiosk deployment

Projector/TV client должен уметь:

- стартовать сразу в fullscreen;
- автоматически авторизоваться как `display` role;
- переподключаться после обрыва;
- восстанавливать текущую сцену;
- работать сутками;
- не показывать административные секреты;
- иметь watchdog/reload policy.

## 12. Приватность

На публичном экране показываются только разрешённые display fields:

- display name/nickname;
- avatar;
- game stats;
- group/team при разрешении.

Не показывать:

- login PIN;
- email;
- внутренние ID;
- техническую диагностику;
- персональные учебные комментарии.

## 13. Display API

Рекомендуемые каналы:

```text
GET /broadcast/state
GET /broadcast/schedule
WS  /broadcast/live
GET /broadcast/highlights
GET /broadcast/leaderboard
```

`broadcast-selector` читает match/event state, но не меняет результат матча.

## 14. Fallback

Если realtime backend недоступен:

1. последний подтверждённый leaderboard;
2. локальный replay pack;
3. живой ambient hub;
4. offline информационный экран.

Пустой чёрный экран недопустим.

## 15. Acceptance criteria

- [ ] экран запускается без преподавателя;
- [ ] сам выбирает активный матч;
- [ ] после завершения показывает result и выбирает следующий;
- [ ] при отсутствии матчей переходит в attract-mode;
- [ ] live viewer может работать несколько часов без ручного управления;
- [ ] correct answer не раскрывается преждевременно;
- [ ] есть fallback при потере сервера;
- [ ] публичные поля отделены от приватных;
- [ ] selector отдаёт приоритет финалам и интересным матчам;
- [ ] spectator UI остаётся читаемым с нескольких метров.
