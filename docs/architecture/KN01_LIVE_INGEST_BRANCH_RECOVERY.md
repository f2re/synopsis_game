# Сохранение прототипа KN01 Live из изолированной ветки

Дата: 2026-11-05. Задача: [#119](https://github.com/f2re/synopsis_game/issues/119).

Источник: `feat/kn01-live-ingest` @ `5217a3a6cb16396bbb6652c2d1ddab7f831a693c` (шесть уникальных коммитов относительно прежнего `main`).

## Что переносится

- Разбор заголовка `AAXX YYGGiw IIiii` и сохранение бюллетенного префикса; канонизация пробелов и завершающего `=`; проверка диапазона дня, часа, допустимого `iw` по действующему кодеку.
- Локальный сервис загрузки КН-01: неизменяемое сохранение оригинала, SHA-256, реестр источников и станций, дедупликация, архив отклонённых сообщений и обработка входящего каталога.
- Изолированные тесты сервиса и заголовка; безопасное отклонение символических ссылок во входящем каталоге.
- Публичный дополнительный путь `@synopsis/kn01-codec/synop-header` в экспортах пакета. Ранее исходная ветка не содержала его, поэтому сервис не собирался как зависимость.

## Что сознательно не включено

- Никакой автоматический сетевой приём, HTTP endpoint или фоновое считывание каталогов: прототип подключается только вручную из кода после отдельной проверки.
- `content/stations/stations.json` намеренно пуст. Запрещено подставлять непроверенные реальные координаты, псевдостанции и данные без `sourceId` и `sourceLocator`.
- Нет гарантии полноты дешифровки всех групп КН-01: выполняется только проверка заголовка, не метеорологический контроль всей телеграммы.
- До производственной эксплуатации необходимо ограничить размер файлов до чтения, провести проверку устойчивости к параллельным ingest/записи индекса, восстановление после сбоя и атомарность записи исходного сообщения с метаданными.
- Статус **технический прототип**, не подтверждён промышленный приём, методическая проверка и эксплуатационные права на потоки данных.

## Приёмка

`pnpm -C packages/kn01-codec test`, `pnpm -C apps/server test`, `pnpm -C apps/server typecheck` и общая сборка. Независимые владельцы приёмки: `meteo-methodologist-ru`, `security-privacy-reviewer`, `integration-release-engineer`.

Перед удалением исходной ветки проверить совпадение каждого из её шести файлов по назначению (для сервиса и парсера допустимы перечисленные дополнительные защитные изменения) и наличие объединённого коммита в `main`.
