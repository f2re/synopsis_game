# Допуск производственных слоёв Hub и полноэкранная камера

Дата: 05.11.2026. Задачи: #109, #107, #31, #85, #94. **Статус: технический срез; ART/UX/GPU PASS не получен.**

- `HubScene.preload()` читает `packages/world-engine/src/assets/hub/runtime-approval.json`. Пока `artAcceptance=PENDING`, отсутствующие `/hub/layers/*.png` не запрашиваются; процедурный legacy fallback работает только как отладочный, не как production art.
- Статус `PASS` разрешён только после наличия всех PNG, SHA-256, ссылок на независимый art-review и контрольного composite/diff. Скрипт `node tools/assets/scripts/audit-hub-runtime.mjs --require-production` блокирует выпуск до выполнения этих условий. Обычный аудит CI фиксирует PENDING, не выдавая его за приёмку.
- `bindHubCoverViewport` применяется исключительно к Hub и вычисляет масштаб cover по максимуму отношений экрана к логической сетке 480x270. Камера центрируется, края симметрично обрезаются, геометрия интерактива и другие сцены не меняются.
- **Блокер мобильного портрета:** при 390x844 видимая ширина мира примерно 125/480; до специальной навигации и UX-проверки портретный режим не принимать. Реальные браузерные снимки на 1920x1080, 1440x900, 2560x1440, 390x844 обязательны.
- Экспериментальный Three.js из PR #95 не тронут, renderer default не меняется. Оригинальные шесть R01–R06 PNG должны быть импортированы отдельно; placeholder/candidate и испорченный дневной WebP не разрешены.

Список production-слоёв хранится в runtime-каталоге world-engine, поскольку web использует установку локального пакета (pnpm file:). Исходные editable art/assets и их художественные манифесты остаются в `assets/source` / `assets/manifests`; статус runtime-допуска — отдельная сущность.
