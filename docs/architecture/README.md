# Архитектура проекта

**Статус:** принято для первого рабочего среза

Этот раздел описывает целевую модульную архитектуру. Доменные границы должны оставаться стабильными. Технологические решения, закреплённые отдельным ADR, считаются контрактом до явной замены.

## 1. Целевая структура единого репозитория компонентов

```text
apps/
├── web/                 # основной React-интерфейс игрока
├── server/              # REST + сетевые матчи + авторитетное состояние
├── display/             # автономный большой экран
└── tools/               # служебные средства, импорт и подготовка данных

packages/
├── meteorology-domain/  # предметные сущности и термины
├── kn01-codec/          # версионируемое кодирование/дешифрирование КН-01
├── live-ingest/         # приём актуальных данных, удаление дублей, карантин
├── content-schema/      # схемы и проверка учебного содержания
├── content-engine/      # загрузка пакетов и формирование заданий
├── game-rules/          # детерминированные игровые правила
├── realtime-protocol/   # события и сетевые контракты
├── broadcast-selector/  # выбор сцены большого экрана
├── world-engine/        # Phaser 4 / WebGL, живой мир
├── identity/            # список пользователей, вход, роли, сессии
├── rewards/             # достижения, предметы оформления, инвентарь
├── map-engine/          # схемы станций, фронты, линии, SVG/Canvas-наложения
├── replay/              # журнал событий и воспроизведение
├── ui/                  # общие React-компоненты интерфейса
└── analytics-domain/    # освоение навыков, попытки, показатели группы

assets/
├── source/              # редактируемые исходники пиксельной графики
├── scenes/              # Tiled JSON (.tmj/.tsj)
├── manifests/           # semantic IDs, pivots, animation/provenance metadata
└── generated/           # производные игровые ресурсы; ручная правка запрещена

tools/
└── assets/              # sprite-tools / AssetPack integration

content/
├── sources/
├── method-profiles/
├── skills/
├── packs/
├── tasks/
├── scenarios/
├── cosmetics/
└── balance/

tests/
├── unit/
├── integration/
├── e2e/
└── content/
```

Названия каталогов и пакетов остаются английскими как программные идентификаторы. Их назначение описывается по-русски.

## 2. Главные границы

### `meteorology-domain`

Не знает о React, Phaser, рейтинге, соревновательных эффектах или базе данных. Содержит типы наблюдений, кодов, карт, фронтов, уровней АТ/ОТ и идентификаторы терминологии.

### `kn01-codec`

Знает правила конкретного `kn01_ruleset_id`, умеет дешифрировать, кодировать и выполнять проверку обратного преобразования. Не знает об интерфейсе, рейтинге и матчах.

### `live-ingest`

Принимает метеотелеграммы из папки, сетевого потока и других адаптеров, хранит исходные сообщения, удаляет дубли, проверяет время и станцию и передаёт нормализованные данные дальше. Не решает игровой баланс.

### `content-engine`

Из `TaskDefinition` или проверенного актуального наблюдения создаёт проверяемый `TaskInstance`. Не определяет силу игрового эффекта.

### `game-rules`

Не знает, что такое КН-01 или атмосферный фронт. Работает с абстрактным результатом задания и параметрами баланса.

### `world-engine`

Использует Phaser 4/WebGL как рабочий контур отрисовки живого мира. Отвечает за жизненный цикл сцены, загрузку проверенных ресурсов, камеры, воспроизведение кадровой анимации, tweens, частицы, фильтры/шейдеры и диагностику отрисовки. Не генерирует учебные наблюдения, не меняет метеорологические данные задания и не становится авторитетным источником матча.

Состояние времени суток, сезона, фоновых событий, интерактивных объектов и «Находок мира» задаётся WORLD-логикой поверх примитивов графического контура. Это разделяет поведение мира и внутреннее устройство отрисовки.

### `broadcast-selector`

Читает состояния матчей и журнал событий и выбирает сцену для большого экрана. Не имеет права менять результат матча.

### `identity`

Управляет закрытым списком пользователей, кодами входа, ролями и сессиями. Публичная саморегистрация отсутствует.

### `rewards`

Управляет схемой персонажа, предметами оформления, достижениями и происхождением наград. Не может изменять силу игрока в рейтинговом матче.

### `map-engine`

Рисует и проверяет профессиональную геометрию через SVG/Canvas, но не определяет методическую истинность без данных методического профиля и учебного пакета. Не переносится в Phaser только ради визуального единообразия.

### `server`

Авторитетен для матчей, таймеров, ответов, рейтинга, прав пользователя и публикации учебного содержания.

### `web`

Отвечает за представление и ввод. React является оболочкой приложения и монтирует рабочий контур Phaser как изолированную игровую область. Правильный ответ до проверки сервером не хранится в клиенте.

### `display`

Клиент большого экрана только для чтения. Автоматически подключается к состоянию трансляции и не требует преподавателя-оператора.

## 3. Основной поток задания

```mermaid
flowchart LR
    A[Пакет содержания / снимок данных] --> B[Модуль содержания]
    B --> C[Экземпляр задания]
    C --> D[Сервер]
    D --> E[Интерфейс игрока]
    E -->|ответ| D
    D --> F[Проверка]
    F --> G[Игровые правила]
    G --> H[Состояние матча]
    H --> I[Журнал событий]
    I --> J[Зритель / воспроизведение / выбор сцены]
```

## 4. Поток актуальных КН-01

```mermaid
flowchart LR
    A[Файл / TCP / WebSocket / иной канал] --> B[Приём данных]
    B --> C[Хранилище исходных сообщений]
    C --> D[Кодек КН-01]
    D --> E[Каноническое наблюдение]
    E --> F[Контроль качества]
    F --> G[Фиксированный снимок данных]
    G --> H[Формирование заданий]
```

Внешний источник не должен быть синхронной зависимостью каждого вопроса. Матч всегда работает на зафиксированном снимке и конкретной версии правил.

## 5. Поток живого мира

```text
серверное время / сезон / профиль местоположения / зерно событий
                        ↓
                 WORLD state logic
                        ↓
состояние центра + расписание фоновых событий + находки
                        ↓
          Phaser/WebGL world-engine локально
                        ↓
                 web / display
```

Покадровая анимация выполняется локально. Сервер не передаёт координату каждой птицы на каждом кадре. Частота смены кадров спрайта отделена от частоты дисплея: движение, камера и tween могут обновляться с частотой дисплея, а нарисованные кадры сохраняют художественно заданный ритм без размывающей интерполяции пикселей.

## 6. Автономный большой экран

```text
Активные матчи ─┐
Состояние турнира ├─> broadcast-selector ─> состояние показа ─> display
Журнал событий  ─┤
Таблица лидеров ─┤
Повторы         ─┘

Нет активного матча ─> демонстрационный режим / живой мир
```

## 7. Версионирование

Независимо версионируются:

- схема учебного содержания;
- методические профили;
- наборы правил КН-01;
- снимки актуальных данных;
- пакеты заданий;
- игровые правила;
- профили баланса;
- сетевой протокол;
- формат воспроизведения;
- профиль событий живого мира;
- каталог предметов оформления;
- формат манифеста ресурсов и контракт графических инструментов.

Воспроизведение матча обязано хранить версии, необходимые для точного восстановления старого состояния. Обновление Phaser между основными версиями требует отдельного архитектурного решения или явного пересмотра `ADR-0004`.

## 8. Запрещённые зависимости

- `meteorology-domain` → пользовательский интерфейс;
- `meteorology-domain` → Phaser/WebGL;
- `meteorology-domain` → игровой баланс;
- `live-ingest` → сила игрового эффекта;
- `world-engine` → учебный ответ;
- рабочий контур Phaser → авторитетное состояние матча;
- `map-engine` → Phaser только ради оформления;
- WORLD-логика → жёсткие координаты кадров внутри сгенерированного атласа;
- `assets/generated` → ручная правка как источник истины;
- `broadcast-selector` → изменение состояния матча;
- `rewards` → рейтинговая сила;
- `content` → конкретные клиентские компоненты;
- `web` → секретные ответы;
- `display` → административные секреты;
- `game-rules` → конкретные учебники;
- `replay` → текущая версия баланса без манифеста;
- методические коэффициенты → жёсткие константы пользовательского интерфейса.

## 10. Пользователи и закрытый список

Саморегистрация отсутствует.

```text
администратор / импорт → список → профиль пользователя → быстрый вход → сессия
```

Короткие коды из 1–2 символов разрешаются только в локальном доверенном профиле с ограничением числа попыток и временной блокировкой. Публичный профиль требует усиленной аутентификации.

## 11. Принцип автономной работы

Основной рабочий контур не зависит от присутствия преподавателя.

Автоматически работают:

- проверка заданий;
- расчёт освоения навыков;
- подбор соперников;
- продвижение турнира;
- рейтинг;
- приём актуальных КН-01;
- выбор сцены большого экрана;
- формирование повтора и ярких моментов;
- демонстрационный режим.

Интерфейс преподавателя и администратора нужен для настройки, методического контроля и исключительных вмешательств, а не для повседневного запуска игры.

## 12. Принцип вертикального рабочего среза

Каждый крупный модуль проходит полный путь:

`источник → методическое правило → данные → задание → отображение → проверка → журналирование → испытание`.

Для живого мира:

`editable asset → manifest → generated asset → Phaser scene → состояние мира → взаимодействие → сохранение → проверка режима уменьшенной анимации и производительности`.

Не следует заранее создавать большие подсистемы без работающего пользовательского сценария.

## 13. Архитектурные решения

Любое решение, влияющее более чем на один пакет, оформляется в `docs/decisions/` до существенной реализации. Phaser/WebGL и конвейер ресурсов закреплены `ADR-0004`.

## 14. Язык архитектурной документации

Пояснения пишутся по-русски. Английские имена сохраняются для путей, пакетов, типов, протоколов и полей данных согласно [`../LANGUAGE_POLICY.md`](../LANGUAGE_POLICY.md).

## 15. Граница React ↔ Phaser

```text
React application
├── DOM/CSS UI
├── map-engine (SVG/Canvas)
└── GameWorld mount
    └── @synopsis/world-engine
        └── Phaser 4 / WebGL
```

React передаёт графическому контуру крупнозернистое состояние и команды, а получает дискретные события. Передача каждого кадра через React state запрещена. При подключении и отключении игровой области должны освобождаться игровой цикл, обработчики событий и графические ресурсы; контур должен учитывать паузу/ограничение работы для невидимой вкладки и восстановление WebGL context.

## 16. Поток графических ресурсов

```text
Aseprite / Pixelorama
        ↓
assets/source + assets/manifests
        ↓
sprite-tools validation / tags / pivots / bounds / metadata
        ↓
Tiled scene (.tmj/.tsj) по semantic asset IDs
        ↓
AssetPack packing / optimisation
        ↓
assets/generated
        ↓
Phaser
```

`design/pixel-art/` хранит художественные эталоны, а не производственные игровые ресурсы. `assets/generated` является производным слоем и не редактируется вручную. Формальный минимальный контракт манифеста хранится в `assets/manifests/asset-manifest.schema.json`. Подробности — в `GAME_RUNTIME_AND_ASSETS.md` и `../design/PIXEL_ASSET_PIPELINE.md`.
