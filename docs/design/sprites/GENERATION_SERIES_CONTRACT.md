# Контракт серийной генерации графических ресурсов

**Статус:** обязательный контракт

Этот документ определяет смысл слова «серия» для генерации графических ресурсов проекта `26063: Позывной «Синоптик»`.

## 1. Базовое правило

**Один промпт / один `asset_id` = один отдельный вызов генератора = один отдельный выходной файл изображения.**

Серия — это упорядоченная последовательность независимых генераций. Серия не является коллажем, контактным листом, общей таблицей или одним изображением, содержащим результаты нескольких разных промптов.

Запрещено:

- объединять несколько разных `asset_id` в один вызов генератора;
- размещать `BODY-01` и `BODY-02`, `HAIR-01` и `HAIR-02` и любые другие независимые ассеты на одном изображении;
- заменять серию одним обзорным листом с миниатюрами;
- считать объединённый коллаж выполнением нескольких пунктов очереди генерации;
- переносить в новый вызов объекты, композицию или фон из предыдущего несвязанного промпта.

## 2. Что считается одним ассетом

Содержимое, которое прямо предусмотрено **одним** промптом одного `asset_id`, остаётся одним ассетом и может находиться в одном выходном изображении.

Примеры:

- четыре канонических направления одного персонажа — один ассет, если этого требует его промпт;
- восемь вариантов формы головы внутри `FACE-01` — один концептуальный ассет, потому что они определены одним промптом;
- `COMPATIBILITY SHEET` — один ассет, потому что сам промпт явно определяет проверочный лист;
- кадры или ключевые позы, явно перечисленные внутри одного анимационного промпта, относятся к одному результату этого промпта.

Это исключение не разрешает объединять разные `asset_id`.

## 3. Изоляция контекста между вызовами

Перед каждым следующим элементом серии генеративный контекст должен быть очищен от несвязанных требований предыдущего ассета.

Допускается переносить только явно объявленные общие контракты и утверждённые референсы:

- обязательный `STYLE LOCK`;
- каноническую геометрию персонажа;
- утверждённую палитру;
- фиксированные точки привязки;
- непосредственно указанный референс предыдущего утверждённого ассета.

Нельзя неявно наследовать:

- фон или сцену предыдущей генерации;
- прежний тип объекта;
- композицию;
- случайно появившиеся детали;
- стилистические отклонения, отсутствующие в действующем контракте.

Если при запросе спрайта персонажа генератор продолжает выдавать, например, панораму кампуса из предыдущей задачи, такой результат является **ошибочным наследованием контекста**.

## 4. Правило приёмки результата серии

Результат засчитывается как выполненный элемент серии только когда одновременно выполнены условия:

1. использован ровно один целевой промпт / `asset_id`;
2. выполнен отдельный вызов генератора;
3. получен отдельный файл изображения;
4. изображение соответствует именно текущему промпту;
5. отсутствуют артефакты или содержимое предыдущего несвязанного вызова;
6. соблюдены требования `STYLE LOCK`, геометрии, альфа-канала и масштаба, если они применимы;
7. результат зарегистрирован в манифесте/журнале происхождения.

Если любое условие нарушено, элемент помечается `REJECTED` / `INVALID` и **не увеличивает счётчик выполненных элементов серии**.

Повторная генерация ошибочного элемента выполняется отдельным новым вызовом.

## 5. Именование и трассируемость

Для каждого результата должна существовать однозначная связь:

```text
asset_id -> prompt_id -> generation_call -> output_file -> review_status
```

Рекомендуется использовать стабильный идентификатор ассета в имени файла, например:

```text
body.standard_a.png
body.standard_b.png
hair.short_straight_01.png
npc.operational_forecaster.png
```

При наличии нескольких кандидатов одного ассета используется номер кандидата, а не объединение кандидатов в один лист:

```text
body.standard_a__candidate-01.png
body.standard_a__candidate-02.png
```

## 6. Коллажи и обзорные листы

Коллаж, контактный лист или сравнительный лист допускается только как **производный контрольный артефакт** после того, как исходные элементы серии уже существуют отдельными файлами.

Такой производный файл:

- не заменяет исходные изображения;
- не считается исходной генерацией;
- не закрывает несколько `asset_id`;
- должен быть помечен как `review/composite` или эквивалентно.

Исключение — ассет, чей собственный промпт прямо требует лист (`COMPATIBILITY SHEET` и аналогичные явно определённые ресурсы).

## 7. Обязательное поведение агентов

Любой агент, запускающий генерацию графики, обязан:

1. разобрать очередь на отдельные `asset_id`;
2. запускать генератор последовательно по одному `asset_id`;
3. после каждого вызова проверить соответствие текущему промпту;
4. отклонить результат при наследовании несвязанного контекста;
5. сохранить каждый принятый результат отдельным файлом;
6. только после этого переходить к следующему элементу;
7. создавать обзорные листы исключительно как отдельный постпроцесс при необходимости.

Формулировка «сгенерировать серию» **никогда не означает** «сделать один коллаж со всей серией».
