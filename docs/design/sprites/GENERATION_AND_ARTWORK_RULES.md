# Правила генерации и ручной доработки пиксельной графики

**Статус:** принято к реализации

Документ разделяет задачи, которые можно ускорять генеративными средствами, и задачи, где требуется ручное построение пиксельной геометрии. Для локальной ComfyUI/MCP-генерации дополнительно обязательны [`LOCAL_AI_ASSET_PIPELINE_V2.md`](../LOCAL_AI_ASSET_PIPELINE_V2.md), [`PORTRAIT_ART_DIRECTION.md`](../PORTRAIT_ART_DIRECTION.md) и `config/art-generation-profiles.json`.

## 1. Что разрешено генерировать как черновик

Генеративные средства допустимы для поиска формы и композиции:

- портреты персонажей;
- варианты зданий и силуэтов кампуса;
- облака и дальний рельеф;
- деревья/кусты;
- бытовые предметы;
- одежда и причёски;
- редкие декоративные события;
- фоновые NPC;
- животные как референс позы/силуэта;
- интерьерные композиции;
- сезонные варианты.

Генеративный результат не считается производственным ресурсом автоматически.

## 2. Персонажные представления

Персонаж имеет минимум три независимых класса:

```text
dialogue_portrait  → 256×320 logical px
profile_portrait   → 160×160 logical px
world_character    → 32×48 logical px
```

Запрещено использовать один и тот же workflow/normalizer для этих классов.

Диалоговый портрет должен сохранять человеческое лицо и мимику; мировой спрайт может быть существенно упрощён.

## 3. Что требуется доводить вручную или контролируемым refinement

Обязательная доработка:

- лицо, волосы, очки и руки ключевых персонажей;
- сохранение идентичности между выражениями лица;
- циклы ходьбы/работы;
- модульные слои одежды;
- точки опоры и привязки;
- животные;
- тайлы;
- интерактивные объекты с несколькими состояниями;
- спрайты, где требуется точное совпадение слоёв.

Refinement может быть автоматизирован, но не должен менять идентичность, возраст, мимику, пропорции или крупный силуэт.

## 4. Что нельзя принимать только по генерации/метрикам

Без художественной проверки запрещено принимать:

- диалоговый портрет;
- листы анимации;
- набор модульной одежды;
- изображения с плавающей перспективой;
- генеративные надписи;
- метеорологические условные знаки;
- схемы станций;
- фронты/изобары;
- графику без provenance;
- любой результат только потому, что технический checker вернул `PASS`.

## 5. Порядок создания портрета

1. Загрузить персонажный ЛОР и внешний контракт.
2. Выбрать профиль `dialogue_portrait`.
3. Сгенерировать 6 кандидатов.
4. Отбросить chibi/kawaii/toy-like и лица с неправильным возрастом.
5. Выбрать вариант по идентичности и мимике.
6. Выполнить low-denoise refinement без изменения геометрии лица.
7. Перенести на логическую сетку без majority-downsampling.
8. Сравнить selected raw и refined в нативном масштабе.
9. При ухудшении лица поставить `REFINEMENT_REJECTED`.
10. Провести art review.
11. После художественного PASS выполнить техническую проверку.

## 6. Порядок создания остальных семейств

1. Художник получает идентификатор семейства и визуальный бриф.
2. Определяет класс, рамку, точку опоры, palette role и состояния.
3. Создаёт 4 кандидата по умолчанию.
4. `art-director` выбирает направление до refinement.
5. Создаётся эталонный статичный вид в нативном масштабе.
6. Проверяется силуэт в сцене.
7. Создаются остальные направления/варианты.
8. Создаются ключевые позы анимации.
9. Проверяются точки опоры и отсутствие дрожания.
10. Создаётся/обновляется манифест.
11. Выполняется художественная приёмка.
12. `pixel-asset-pipeline-engineer` выполняет техническую проверку и упаковку.
13. Ресурс тестируется в Phaser-сцене.

## 7. Правила пиксельной очистки

После выбора кандидата:

- удалить случайный шум;
- привести контуры к системе конкретного класса;
- привести свет к одному направлению;
- убрать случайные оттенки, не уничтожая полезные цветовые рампы;
- очистить грязные субпиксельные края;
- проверить пропорции;
- проверить силуэт;
- убрать непреднамеренный текст/логотипы.

### Для диалогового портрета

Допустимы осознанные 1–2 px детали лица и локальный контролируемый антиалиасинг.

Запрещены:

- aggressive/majority downsampling;
- chunky-pixel переработка лица;
- толстая чёрная обводка каждой черты;
- posterization кожи до нескольких плоских тонов;
- потеря носа, рта, глаз, оправы и возрастных деталей.

## 8. Правила для модульного мирового персонажа

Мировой спрайт 32×48 проверяется на шаблонах `idle_down`, `walk_down`, `walk_side`, `walk_up`, `work_table`, `celebrate`.

Именно здесь допустим крупный pixel cluster и строгая palette quantization. Эти правила нельзя переносить на диалоговый портрет.

## 9. Правила для животных

Форма тела и окраска должны оставаться постоянными между кадрами. Анимация не строится из случайно сгенерированных независимых кадров.

## 10. Правила для окружения

Сначала создаются модульные детали: фасад, окна, двери, крыша, передний слой, ночной свет, сезонные накладки.

Запрещено генерировать независимую геометрию здания для каждого времени суток. Day/night выводятся из общей базы.

## 11. Палитры и количество цветов

Малое количество цветов не является самоцелью.

Рабочие диапазоны финала:

- диалоговый портрет 256×320: 48–96, мягкий потолок 128;
- профильный портрет 160×160: 36–72, мягкий потолок 96;
- мировой персонаж 32×48: 16–32, мягкий потолок 40;
- крупная архитектура: 48–96, мягкий потолок 128;
- сцена 480×270: 96–192, мягкий потолок 256;
- props: 16–32;
- UI: 8–24.

Диалоговый портрет должен иметь достаточные рампы кожи, волос, ткани, металла/стекла, света и холодной тени. Нельзя уменьшать палитру ценой потери мимики, возраста или материалов.

## 12. Техническая проверка

После художественного `PASS` проверяются:

- рамка/логический размер;
- число кадров и метки;
- длительность;
- точка опоры;
- финальный alpha-контракт;
- manifest/provenance;
- совместимость слоёв;
- права и происхождение.

`python tools/assets/check_asset_contract.py` проверяет структуру manifests.

`python tools/assets/check_generation_profiles.py` защищает профиль портретов от возврата к 128×128/16-color/majority-downsample конвейеру.

## 13. Использование ИИ-агента художника

Агент может генерировать кандидатов, ранжировать их, сравнивать raw/refined, находить расхождения и формировать исправления.

Агент не может объявить художественный PASS только по техническим метрикам.

## 14. Критерий готовности семейства

Семейство готово только когда существуют одновременно:

- редактируемый исходник;
- полный набор обязательных состояний;
- манифест;
- собранный атлас/игровой вывод;
- испытание в сцене;
- `art_status: pass`;
- `technical_status: pass`;
- подтверждение воспроизводимости сборки.
