# Проверка пиксельной графики и сцен

**Статус:** обязательный этап художественной приёмки.

Производственный ресурс не считается принятым только потому, что PNG технически корректен. Художественная и техническая приёмка разделены принципиально.

## 1. Стадии кандидата

```text
generated_raw → candidate → selected → pixel_refined → art_review → technical_review → approved
```

```yaml
art_status: pending | pass | fail
technical_status: pending | pass | fail
production_status: candidate | approved | rejected
```

`technical_status: pass` не означает художественную пригодность.

## 2. Класс ассета определяет тип проверки

Проверка не может применять одинаковые критерии к диалоговому портрету и мировому спрайту.

### Диалоговый портрет

Канонический профиль: `256×320`, минимум `192×240`, мелкий pixel language, высокая детализация лица.

Проверяются:

1. взрослые пропорции для взрослого NPC;
2. возраст;
3. индивидуальная форма лица;
4. глаза, нос, рот и линия челюсти;
5. реальная мимика и направление взгляда;
6. волосы/очки/характерный предмет;
7. профессиональная идентичность;
8. отсутствие chibi/kawaii/toy-like эстетики;
9. отсутствие чрезмерно толстой обводки лица;
10. сохранение выразительности после refinement.

### Профильный портрет

Отдельная композиция `160×160`. Нельзя автоматически считать уменьшенную 128×128 копию диалогового портрета корректным профилем.

### Мировой персонаж

`32×48` проверяется как игровой спрайт: силуэт, направление, anchor, постоянство тела/одежды, читаемость в сцене. Микромимика здесь не является целью.

## 3. Художественная проверка остальных классов

`pixel-art-quality-reviewer` и затем `art-director` проверяют:

- соответствие `asset_id` и классу ресурса;
- читаемость силуэта в нативном масштабе;
- соответствие ЛОРу/локации;
- постоянство пропорций;
- отсутствие случайного шума финала;
- осмысленность кластеров;
- обязательные/запрещённые признаки;
- возможность переиспользования объекта отдельно от сцены.

## 4. Цвета

Жёсткое правило «меньше цветов = лучше pixel art» отменено.

Целевые диапазоны финальных ресурсов:

- диалоговый портрет 256×320: `48–96`, мягкий потолок `128`;
- профильный портрет 160×160: `36–72`, мягкий потолок `96`;
- мировой персонаж 32×48: `16–32`, мягкий потолок `40`;
- крупная архитектура: `48–96`, мягкий потолок `128`;
- сцена 480×270: `96–192`, мягкий потолок `256`;
- props 32–64 px: `16–32`, мягкий потолок `48`;
- UI-иконки: `8–24`, мягкий потолок `32`.

Превышение диапазона — сигнал проверить шум, а не автоматический `FAIL`.

Для диалогового портрета строгая квантизация выключена. Нельзя уничтожать мимику/возраст ради маленькой palette.

## 5. Raw-кандидаты

Для `generated_raw` и `candidate` не являются blocking-условиями:

- точное число цветов;
- бинарная альфа;
- точный финальный размер;
- строгая project palette;
- наличие антиалиасинга;
- временный нейтральный фон.

Это рабочий материал.

## 6. Pixel refinement

Refinement допускает очистку кластеров, outline, palette harmonization и приведение к логической сетке.

Для портретов запрещены:

- majority downsampling;
- chunky-pixel преобразование лица;
- posterization кожи в несколько плоских тонов;
- потеря глаз, носа, рта, оправы;
- изменение возраста и формы головы.

Если после refinement результат хуже raw, ставится `REFINEMENT_REJECTED`.

## 7. Техническая проверка

Технический checker отвечает только на вопрос «может ли принятый файл корректно использоваться движком?». Он проверяет:

- manifest;
- стабильный идентификатор;
- source path;
- logical size;
- pivot/origin;
- frame-grid/число кадров, если применимо;
- alpha-контракт финального файла;
- provenance;
- ссылки на generated assets.

Техническая проверка не оценивает красоту, мимику или возраст.

## 8. Регрессионная защита pipeline

`python tools/assets/check_generation_profiles.py` обязан падать, если:

- `dialogue_portrait` становится меньше 192×240;
- снова включается строгая квантизация портрета;
- включается majority downsampling;
- запрещаются тонкие детали лица;
- portrait и world sprite получают один workflow.

Это не художественный скоринг. Это защита архитектуры производства от возврата к заведомо грубому pipeline.

## 9. Масштаб проверки

Каждый выбранный кандидат показывается в нативном `1×`, плюс `2×` и `4×` для технического просмотра. Решение о читаемости принимается по нативному мастеру.

## 10. Продвижение в производство

Только после `art_status: pass` и `technical_status: pass`:

1. кандидат становится каноническим редактируемым source;
2. фиксируются pivots/tags/frame durations;
3. `pixel-asset-pipeline-engineer` собирает atlas/игровой вывод;
4. рабочий контур использует semantic asset ID.
