# Проверка пиксельной графики и сцен

**Статус:** обязательный этап художественной приёмки.

Производственный ресурс не считается принятым только потому, что он выглядит удачно на одном скриншоте. Для каждого семейства применяются два независимых этапа.

## 1. Исполнитель

`pixel-asset-designer` создаёт candidate-версию в `assets/source/**/candidates/`.

Candidate может быть PNG, если это генеративная или программная первая итерация. Он не считается каноническим `.aseprite`-источником до прохождения двух проверок.

## 2. Пиксельная проверка

`pixel-art-quality-reviewer` проверяет:

1. логический размер;
2. прозрачность только 0/255, если нет специального эффекта;
3. ограничение палитры;
4. корректный frame-grid;
5. постоянство силуэта и пропорций;
6. отсутствие сглаживания;
7. отсутствие случайного микрошумового пикселя;
8. достаточную крупность кластеров;
9. полный набор обязательных состояний;
10. возможность переиспользования объекта отдельно от сцены.

Объективные пункты дополнительно проверяет `python tools/validate_pixel_art.py`.

## 3. Арт-директор

После `PASS` пиксельного проверяющего `art-director` оценивает:

- соответствие принятому «уютному научному» миру;
- иерархию «локация → действие → декор»;
- зелёную пастельную базу без выцветания;
- отсутствие дворцового пафоса;
- читаемость open/locked/active;
- правило плотности 60/30/10;
- научность через предметы, а не административную строгость;
- пригодность к дневной/вечерней/сезонной палитре;
- отсутствие лишнего baked-in UI или профессиональной метеосимволики.

## 4. Возврат на доработку

`REQUEST_CHANGES` обязан перечислять asset ID, проблему и конкретную правку. Новая версия получает следующий суффикс (`v2`, `v3`...), старая не перезаписывается в материалах проверки.

## 5. Продвижение в производство

Только после двух `PASS`:

1. candidate импортируется/перерисовывается в `.aseprite`;
2. фиксируются pivots, tags и frame durations;
3. `pixel-asset-pipeline-engineer` собирает generated atlas;
4. рабочий контур использует semantic asset ID, а не координаты атласа.

Flattened 480×270 сцена может храниться как **контрольный композит**, но живой Hub и помещения должны иметь отдельные слои/спрайты.
