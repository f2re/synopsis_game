# Конвейер пиксельной графики и анимации

**Статус:** принято

## Контракт подготовки исходников

Основной редактор — Aseprite. Свободная альтернатива — Pixelorama. Канонический редактируемый формат спрайта — `.aseprite`. Канонический редактор сцен — Tiled с JSON-форматами `.tmj/.tsj`.

Каждый производственный ресурс имеет манифест: стабильный идентификатор, путь к исходнику, логические размеры, pivot/origin, состояния анимации, роль палитры, слой мира, provenance и ожидаемые производные файлы.

## Производственный конвейер

Для ручного ассета:

1. `art-director` задаёт бриф, класс ресурса, масштаб и palette role.
2. `pixel-asset-designer` создаёт/изменяет source.
3. `art-director` принимает внешний вид в `1×`.
4. `pixel-asset-pipeline-engineer` проверяет manifest/pivots/tags/frames.
5. AssetPack собирает игровые ресурсы.
6. Phaser использует semantic asset ID.

Для локальной ИИ-генерации применяется отдельный контракт `LOCAL_AI_ASSET_PIPELINE_V2.md`:

```text
SPEC
→ PROMPT COMPILE
→ 4–6 CANDIDATES
→ RANK/SELECT
→ PIXEL REFINEMENT
→ ART REVIEW
→ TECHNICAL CONTRACT CHECK
→ APPROVED SOURCE
→ PACK
```

Нельзя автоматически принимать первый результат генератора или превращать обычную AI-иллюстрацию в финальный pixel art агрессивным downsampling.

## Классы генеративных workflow

Минимально раздельно производятся:

- portrait;
- world character sprite;
- architecture;
- props;
- terrain/tiles;
- vegetation;
- UI icons.

Один универсальный workflow для всех типов ресурсов запрещён.

## Палитры

Количество цветов не является самостоятельным критерием художественного качества. Используются классовые palette families и управляемые цветовые рампы.

Ориентиры финальных ресурсов:

- портрет: 24–40;
- персонаж 32×48: 16–28;
- архитектура: 32–56;
- сцена 480×270: 48–96;
- props: 12–24;
- UI: 8–16.

Мягкие технические потолки предназначены только для обнаружения шума/антиалиасинга и не дают автоматический художественный `FAIL`. Raw-кандидаты вообще не ограничиваются этими диапазонами.

## Прозрачность

Основной production-путь: контролируемый фон/матт + mask/segmentation → финальная alpha. `#FF00FF` разрешён только как fallback конкретного workflow и не должен загрязнять края после refinement.

## Нормализация

Нормализатор не исправляет плохую композицию. Он может очищать пиксельные кластеры, outline, palette mapping, одиночный шум и приводить результат к логической сетке.

Запрещено использовать destructive majority downsampling как главный способ получения pixel art. Если нормализация разрушает лицо, очки, предмет, купол радара, входы или крупный силуэт — refinement отклоняется.

## Политика анимации

Плавность движения не означает 60 нарисованных кадров/с. Для многих действий художественная частота составляет примерно 4–15 кадров/с; камера, tween и положение объекта могут обновляться с частотой дисплея. Размытые интерполированные пиксельные кадры не создаются.

## Техническая проверка

Технические проверки не являются арт-директором. Они проверяют только:

- manifest/provenance;
- logical size;
- pivots/origin;
- frame-grid/tags/durations;
- alpha-контракт принятого финала;
- ссылки на generated outputs;
- воспроизводимость упаковки.

Плохой, но технически корректный ассет обязан иметь `art_status: fail`.

## Художественная приёмка

Final acceptance выполняется в `1×` с preview `2×/4×`. Для персонажей проверяются возраст, характер, пропорции и идентичность; для архитектуры — силуэт, обязательные признаки и принадлежность локации; для сцен — композиция и иерархия.

Не принимаются неизвестное происхождение, ручная правка производных файлов, несовместимые pivots, невоспроизводимая сборка, bleeding, случайное сглаживание финала, дублирование полной геометрии дня/ночи и автоматическое `approved` по числу цветов.
