# Локальный конвейер ИИ-генерации графики v2

**Статус:** обязательный производственный контракт

Этот документ задаёт целевую архитектуру `synopsis-assets-mcp` / ComfyUI для проекта «26063: Позывной „Синоптик“».

Канонические численные профили хранятся в `config/art-generation-profiles.json`. Художественные требования к лицам — в `docs/design/PORTRAIT_ART_DIRECTION.md`.

## 1. Главный принцип

Генератор создаёт художественно правильный кандидат. Refiner приводит уже хороший кандидат к дисциплине логического пикселя. Техническая проверка проверяет пригодность файла для движка. Арт-директор принимает внешний вид.

Запрещена схема:

```text
обычный AI-рендер
→ агрессивный downsample
→ жёсткая квантизация
→ valid=true
```

Целевая схема:

```text
SPEC
→ PROMPT COMPILE
→ STRUCTURED GENERATION
→ CANDIDATE RANKING
→ CLASS-SPECIFIC REFINEMENT
→ ART REVIEW
→ TECHNICAL CONTRACT CHECK
→ APPROVED
```

## 2. Представления персонажа — разные классы ресурсов

Один NPC не должен иметь один универсальный «пиксельный размер».

### `dialogue_portrait`

Канонический высокодетальный портрет по грудь:

```text
256×320 logical px
minimum master: 192×240
workflow: portrait_character_v3
```

Назначение: диалоги, сюжетные сцены, крупные карточки персонажа.

Портрет обязан сохранять:

- человеческую мимику;
- возраст;
- форму носа, рта, глаз, челюсти;
- индивидуальную причёску;
- характер и профессиональную идентичность.

Он **не** использует chunky-pixel язык мирового спрайта.

### `profile_portrait`

Компактный портрет для интерфейса:

```text
160×160 logical px
workflow: profile_portrait_v2
```

Это отдельная композиция, а не автоматический 128×128 downsample диалогового портрета.

### `world_character`

Мировой спрайт:

```text
32×48 logical px
workflow: world_character_sprite_v2
```

Здесь крупные пиксельные кластеры допустимы, а мимика упрощена.

Запрещено использовать один workflow и одну нормализацию для `dialogue_portrait` и `world_character`.

## 3. Статусы

Для каждого `asset_id` используются независимые статусы:

```yaml
production_status: candidate | approved | rejected
art_status: pending | pass | fail
technical_status: pending | pass | fail
```

Технический `pass` никогда не означает художественную приёмку.

## 4. Классы workflow

Минимальный набор:

- `portrait_character_v3`;
- `profile_portrait_v2`;
- `world_character_sprite_v2`;
- `architecture_building_v3`;
- `prop_object_v2`;
- `terrain_tile_v2`;
- `vegetation_v2`;
- `ui_icon_v2`;
- `scene_environment_v2`.

Z-Image-Turbo используется как быстрый генератор кандидатов, а не как безусловный финальный рендерер.

## 5. Кандидаты

По умолчанию:

- диалоговый портрет ключевого NPC — 6 кандидатов;
- остальные классы — 4 кандидата.

MCP не принимает первый результат автоматически. Сначала оцениваются:

- соответствие спецификации;
- композиция;
- силуэт;
- идентичность персонажа/локации;
- мимика и возраст для портрета;
- наличие обязательных признаков;
- отсутствие запрещённых признаков;
- соответствие стилю 26063.

## 6. Портреты: приоритет лица, а не «пиксельности»

Для взрослых персонажей обязательны взрослые пропорции. Для Веры Павловны и других старших сотрудников запрещены:

```text
chibi
kawaii
super-deformed
baby face
oversized head
toy proportions
sticker character
anime child proportions
```

Для диалогового портрета разрешены и требуются более тонкие детали, чем для мирового спрайта:

- 1–2 px элементы глаз/рта/оправы;
- контролируемые одиночные пиксели на лице;
- тонкие цветовые рампы;
- локальный контролируемый антиалиасинг;
- сложный контур волос и одежды.

Грубая чёрная обводка вокруг глаз, носа, рта и очков запрещена.

## 7. Цвета и палитры

Малое число цветов само по себе не является признаком качественного pixel art.

Целевые диапазоны финала:

| Класс | Целевой диапазон | Мягкий потолок |
|---|---:|---:|
| Диалоговый портрет 256×320 | 48–96 | 128 |
| Профильный портрет 160×160 | 36–72 | 96 |
| Мировой персонаж 32×48 | 16–32 | 40 |
| Крупная архитектура | 48–96 | 128 |
| Большая сцена 480×270 | 96–192 | 256 |
| Props 32–64 px | 16–32 | 48 |
| UI-иконки | 8–24 | 32 |

Превышение диапазона — сигнал проверить шум, а не автоматический художественный `FAIL`.

Для диалоговых портретов `strictQuantization=false`. Нельзя срезать лицо до 16/24 цветов ради формального соответствия палитре.

## 8. Прозрачность

`#FF00FF` не является стандартным способом удаления фона. Предпочтительно:

```text
controlled matte/background
→ mask/segmentation
→ clean alpha
```

Хромакей разрешён только как fallback конкретного workflow.

## 9. Refinement

Refiner не должен заново рисовать объект.

Разрешены:

- очистка случайного шума;
- аккуратный repair outline;
- исправление неудачных микрокластеров;
- palette harmonization;
- приведение к логической сетке.

Запрещены:

- majority downsampling;
- уменьшение лица до грубой сетки;
- жёсткая posterization кожи;
- изменение возраста;
- изменение пропорций головы;
- потеря глаз, рта, носа, оправы;
- перестройка крупного архитектурного силуэта.

Если refined хуже selected raw — ставится `REFINEMENT_REJECTED`.

## 10. Проверка портрета

Диалоговый портрет проверяется в нативном `1×`.

Обязательные художественные признаки:

```text
adult_proportions
age_readability
facial_expression
eyes_readable
mouth_readable
nose_readable
hair_identity
professional_identity
not_chibi
not_toy_like
not_overoutlined
```

Если не проходят `adult_proportions`, `facial_expression`, `professional_identity` или `not_chibi`, портрет отклоняется независимо от технических метрик.

Для ключевого NPC допускается/рекомендуется набор мимики:

```text
neutral
attentive
skeptical
warm_smile
concerned
thinking
```

## 11. Архитектура

Архитектура строится от силуэта и обязательных признаков, а не от пейзажной миниатюры.

Для landmark-здания нельзя использовать чрезмерно маленький исходный мастер, который при нормализации теряет архитектурную идентичность. Профиль `architecture_landmark` задаёт минимум 96×96 logical px; конкретный spec может требовать больше.

Day/night варианты выводятся из одной геометрии:

```text
BASE → DAY → NIGHT LIGHTING → WINDOWS MASK
```

## 12. ЛОР в prompt compiler

MCP загружает `docs/lore/lore-registry.yaml` и добавляет только релевантный контекст: эпоху, материалы, свет, локального человека, предмет-символ, человеческие следы и северо-западную идентичность.

ЛОР не заменяет размер, pivot, composition profile и обязательные признаки.

## 13. Проверки и тесты

`tools/assets/check_asset_contract.py` проверяет только техническую целостность manifests.

`tools/assets/check_generation_profiles.py` является регрессионной защитой от возврата к плохому pipeline. Он обязан падать, если:

- диалоговый портрет снова становится меньше `192×240`;
- портрет снова получает строгую квантизацию;
- включается majority downsampling;
- запрещаются тонкие детали лица;
- портрет и мировой спрайт начинают использовать один workflow.

Эти проверки не пытаются оценивать красоту автоматически — они не дают архитектуре pipeline снова сделать красивое лицо технически невозможным.

## 14. MCP API

Целевые операции:

```text
asset_spec
generate_candidates
rank_candidates
select_candidate
refine_candidate
preview_asset
art_review
check_asset_contract
approve_asset
reject_candidate
regenerate_asset

```

Автоматический переход `generated_raw → approved` запрещён.

## 15. Контрольный пилот

До массовой генерации принять минимум:

1. новый диалоговый портрет Веры Павловны `256×320`;
2. профильный портрет Веры `160×160`;
3. мировой спрайт Веры `32×48` как отдельную работу;
4. `BLD-RADAR-DAY` на новом architecture workflow;
5. `BLD-ARCHIVE-DAY`;
6. кота Паскаля;
7. один prop;
8. один terrain tile.

Массовая очередь запрещена, пока новый диалоговый портрет не выглядит заметно живее и выразительнее текущего грубого 128×128 результата.

## 16. Условия завершения

Конвейер считается внедрённым, когда:

- портрет и мировой спрайт полностью разделены;
- канонический диалоговый портрет имеет мастер 256×320;
- портрет сохраняет мелкую мимику и возраст;
- нет majority downsampling;
- нет auto-approve по числу цветов;
- техническая и художественная приёмка независимы;
- regression-check защищает размеры и правила портрета;
- пилотная Вера Павловна проходит художественную приёмку как живой взрослый персонаж, а не как chibi-иконка.
