# Локальный конвейер ИИ-генерации графики v2

**Статус:** обязательный производственный контракт.

Этот документ задаёт архитектуру `synopsis-assets-mcp` / ComfyUI для проекта «26063: Позывной „Синоптик“».

Канонические численные профили хранятся в `config/art-generation-profiles.json`.

Художественные контракты:

- `docs/design/PORTRAIT_ART_DIRECTION.md` — лица и портреты;
- `docs/design/ENVIRONMENT_ART_DIRECTION.md` — мир, здания, материалы, предметы, растительность и погода;
- `docs/design/SPRITE_CLASS_MATRIX.md` — матрица классов ресурсов.

## 1. Главный принцип

Генератор создаёт художественно правильный кандидат. Доработка приводит уже хороший кандидат к требованиям конкретного класса. Техническая проверка проверяет пригодность файла для движка. Арт-директор принимает внешний вид.

Запрещена схема:

```text
обычный AI-рендер
→ агрессивное уменьшение
→ жёсткая квантизация
→ valid=true
```

Целевая схема:

```text
SPEC
→ CLASS PROFILE
→ PROMPT COMPILE
→ STRUCTURED GENERATION
→ CANDIDATE RANKING
→ CLASS-SPECIFIC REFINEMENT
→ ART REVIEW
→ TECHNICAL CONTRACT CHECK
→ APPROVED
```

## 2. Один универсальный workflow запрещён

В проекте обязательны независимые классы:

```text
dialogue_portrait
profile_portrait
world_character
companion_sprite
architecture_landmark
architecture_small
interactive_object
prop_sprite
terrain_tile
vegetation_sprite
ui_icon
ui_frame
vfx_small
large_scene
```

Каждый класс имеет собственные:

- размер;
- workflow;
- цветовой диапазон;
- масштаб кластеров;
- правила сглаживания;
- художественные приоритеты;
- критерии приёмки.

Нельзя использовать один normalizer для портрета, тайла, здания и UI.

## 3. Представления персонажа

Один NPC имеет разные графические представления.

### `dialogue_portrait`

```text
256×320 logical px
minimum master: 192×240
workflow: portrait_character_v3
```

Приоритеты: живое лицо, мимика, возраст, характер, профессиональная идентичность.

### `profile_portrait`

```text
160×160 logical px
workflow: profile_portrait_v2
```

Это отдельная композиция, а не автоматическое уменьшение диалогового портрета.

### `world_character`

```text
32×48 logical px
workflow: world_character_sprite_v3
```

Приоритеты: силуэт, одежда, причёска, осанка, жест и цветовая идентичность.

Мировой спрайт не должен быть грубым безликим манекеном только потому, что он маленький.

## 4. Мир и окружение

### Архитектура

Крупная архитектура использует отдельный профиль `architecture_landmark`.

Обязательны:

- уникальный силуэт;
- профессиональная функция;
- материалы;
- следы эксплуатации;
- погодное состояние;
- человеческий масштаб;
- характерный свет.

Архитектура не должна превращаться в крупную пиктограмму.

### Props и интерактивные объекты

Предмет должен быть узнаваем, иметь материал и конкретную причину существования в сцене.

Интерактивный объект дополнительно должен иметь визуально различимые состояния, если они предусмотрены спецификацией.

### Тайлы

Тайлы оцениваются по материалу, бесшовности, вариативности и отсутствию заметного повторяющегося узора.

### Растительность

Растительность различается по виду, сезону, ветру и свету. Универсальный зелёный «шум» запрещён.

### Погодные эффекты

Эффекты поддерживают глубину и состояние атмосферы, но не закрывают слабую сцену декоративным шумом.

## 5. Цвет

Малое число цветов не является признаком качества.

Текущие ориентиры задаются только `config/art-generation-profiles.json`.

Ключевые диапазоны:

| Класс | Целевой диапазон |
|---|---:|
| Диалоговый портрет | 48–96 |
| Профильный портрет | 36–72 |
| Мировой персонаж | 24–48 |
| Спутник/фауна | 24–48 |
| Крупная архитектура | 48–96 |
| Малая архитектура | 32–72 |
| Интерактивный объект | 28–64 |
| Props | 24–56 |
| Тайлы | 24–48 |
| Растительность | 28–64 |
| UI-иконки | 12–32 |
| UI-рамки | 24–56 |
| Малые эффекты | 16–40 |
| Большая сцена | 96–192 |

Диапазоны не являются автоматическим художественным PASS/FAIL. Они нужны для диагностики чрезмерного шума или, наоборот, обеднения палитры.

## 6. Палитровая дисциплина

`strictQuantization=true` запрещён в генерационных профилях.

Это не означает отсутствие общей палитры проекта. Это означает, что гармонизация цвета не имеет права разрушать:

- лицо;
- материал;
- погодный свет;
- фактуру;
- различие тёплого и холодного;
- глубину сцены.

## 7. Прозрачность

`#FF00FF` не является стандартным способом удаления фона.

Предпочтительный путь:

```text
controlled matte/background
→ mask/segmentation
→ clean alpha
```

Хромакей разрешён только как совместимый fallback конкретного workflow.

## 8. Refinement

Refinement работает только после выбора хорошего кандидата.

Разрешены:

- очистка случайного шума;
- исправление неудачных кластеров;
- аккуратная работа с outline;
- цветовая гармонизация;
- приведение к логической сетке;
- очистка альфы.

Запрещены:

- majority downsampling;
- глобальная жёсткая posterization;
- изменение лица и возраста;
- уничтожение материалов;
- перестройка крупного силуэта;
- потеря световой атмосферы;
- превращение предмета в generic-иконку.

Если refined хуже selected raw, ставится `REFINEMENT_REJECTED`.

## 9. Художественные приоритеты

Каждый профиль обязан иметь `artPriorities`.

Примеры:

```text
portrait     → expression, age, identity
character    → silhouette, clothing, pose
architecture → materials, silhouette, weather, light
prop         → recognition, texture, lore
terrain      → material, seam, variation
vegetation   → species, season, wind
UI           → semantic clarity, hierarchy
scene        → composition, depth, weather, human traces
```

Технически корректный ассет может и должен быть отклонён, если эти приоритеты не выполнены.

## 10. ЛОР и вайб

MCP загружает `docs/lore/lore-registry.yaml` и добавляет только релевантный контекст.

Для мира особенно важны:

- профессиональная функция;
- северо-западный характер;
- погода;
- материалы;
- локальный свет;
- следы человеческой работы;
- малая история места.

Для обитаемой крупной сцены обязательны минимум три человеческих следа и один локальный сюжетный крючок.

## 11. Day/night и сезонные варианты

Независимая повторная генерация геометрии одного здания для разных состояний запрещена.

Базовый принцип:

```text
BASE GEOMETRY
→ DAY
→ NIGHT LIGHTING
→ WINDOWS MASK
→ WEATHER/SEASON VARIANTS
```

Геометрия и основные окна должны совпадать.

## 12. Проверки и тесты

`tools/assets/check_asset_contract.py` проверяет только техническую целостность подходящих manifest-схем.

`tools/assets/check_generation_profiles.py` защищает архитектуру художественного конвейера.

Он обязан падать, если:

- исчезает любой обязательный класс;
- два класса начинают использовать один workflow;
- включается majority downsampling;
- включается строгая квантизация;
- цветовой диапазон класса искусственно схлопывается;
- портрет снова становится слишком маленьким;
- большая сцена перестаёт использовать канонический холст 480×270;
- профиль теряет `artPriorities`.

Этот тест не оценивает красоту. Он не даёт технической архитектуре снова сделать красивый результат невозможным.

## 13. Статусы

Используются независимые статусы:

```yaml
production_status: candidate | approved | rejected
art_status: pending | pass | fail
technical_status: pending | pass | fail
```

Технический `pass` никогда не означает художественный `pass`.

## 15. Контрольный набор

До массовой генерации новых пакетов принять минимум по одному эталону каждого класса:

- диалоговый портрет;
- профильный портрет;
- мировой персонаж;
- спутник;
- крупное здание;
- малая архитектура;
- интерактивный объект;
- prop;
- terrain tile;
- растение;
- UI-иконка;
- UI-рамка;
- погодный эффект;
- крупная сцена.

Эти ресурсы формируют gold set для последующих генераций.

## 16. Условия завершения

Конвейер считается корректным, когда:

- все классы имеют независимые профили;
- у каждого класса собственный workflow;
- нет majority downsampling;
- нет строгой квантизации как универсального этапа;
- цветовой бюджет соответствует художественной задаче;
- refined не ухудшает raw;
- техническая и художественная приёмка независимы;
- regression-check защищает все классы;
- мир сохраняет материалы, цвет, свет, погоду, обжитость и характер 26063.
