# Локальный конвейер ИИ-генерации графики v2

**Статус:** обязательный производственный контракт

Этот документ задаёт целевую архитектуру `synopsis-assets-mcp` / ComfyUI для проекта «26063: Позывной „Синоптик“».

## 1. Главный принцип

Генератор создаёт художественно правильный кандидат. Refiner приводит уже хороший кандидат к дисциплине логического пикселя. Техническая проверка проверяет пригодность файла для движка. Арт-директор принимает внешний вид.

Запрещена схема `обычный AI-рендер → агрессивный downsample → квантизация → valid=true`.

Целевая схема:

```text
SPEC
→ PROMPT COMPILE
→ STRUCTURED GENERATION
→ CANDIDATE RANKING
→ PIXEL REFINEMENT
→ ART REVIEW
→ TECHNICAL CONTRACT CHECK
→ APPROVED
```

## 2. Статусы

Для каждого `asset_id` используются независимые статусы:

```yaml
production_status: candidate | approved | rejected
art_status: pending | pass | fail
technical_status: pending | pass | fail
```

Технический `pass` никогда не означает художественную приёмку.

## 3. Классы ресурсов

Один универсальный workflow запрещён. Минимальный набор:

- `portrait_character_v2`;
- `world_character_sprite_v2`;
- `architecture_building_v2`;
- `prop_object_v2`;
- `terrain_tile_v2`;
- `vegetation_v2`;
- `ui_icon_v2`.

Z-Image-Turbo используется как быстрый генератор кандидатов, а не как безусловный финальный рендерер.

## 4. Кандидаты

По умолчанию создаются 4 независимых кандидата. Для важных NPC допускается 6.

MCP не принимает первый результат автоматически. Сначала оцениваются:

- соответствие спецификации;
- композиция;
- силуэт;
- идентичность персонажа/локации;
- наличие обязательных признаков;
- отсутствие запрещённых признаков;
- соответствие стилю 26063.

## 5. Портреты

Портреты и мировые спрайты являются разными ассетами. Портрет нельзя просто уменьшать до `32×48`.

Для взрослых персонажей обязательны взрослые пропорции. Для Веры Павловны и других старших сотрудников запрещены `chibi`, `kawaii`, `super-deformed`, `baby face`, `oversized head`, `sticker character`, `toy proportions`, `anime child proportions`.

Для `128×128` фон вторичен, лицо и плечи занимают основную площадь. Важные признаки — возраст, очки, волосы, выражение, один характерный предмет — должны читаться в масштабе `1×`.

## 6. Архитектура

Архитектура строится от силуэта и обязательных признаков, а не от пейзажной иллюстрации.

Пример для `BLD-RADAR-DAY`:

```yaml
required_features:
  - white_radar_dome
  - technical_radar_tower
  - service_building
forbidden_features:
  - generic_house
  - fantasy_observatory
  - church_dome
  - sci_fi_antenna
```

Day/night варианты выводятся из одной геометрии: `BASE → DAY → NIGHT LIGHTING → WINDOWS MASK`. Независимая повторная генерация геометрии для ночи запрещена.

## 7. Цвета и палитры

Малое число цветов само по себе не является признаком качественного pixel art. Качество задают контролируемые цветовые рампы, крупные кластеры, единый логический пиксель, читаемый силуэт и отсутствие случайного сглаживания/шума.

Рекомендуемые рабочие диапазоны финального ассета:

| Класс | Целевой диапазон | Мягкий технический потолок |
|---|---:|---:|
| Портрет 96–128 px | 24–40 | 48 |
| Мировой персонаж 32×48 | 16–28 | 36 |
| Крупная архитектура | 32–56 | 64 |
| Большая сцена 480×270 | 48–96 | 128 |
| Props 32–64 px | 12–24 | 32 |
| UI-иконки | 8–16 | 24 |

Это не blocking-правило художественной приёмки. Превышение диапазона является сигналом проверить шум/антиалиасинг, а не автоматическим основанием отклонения.

Палитры делятся по ролям:

```text
master_26063_v3.gpl
environment_26063_v1.gpl
architecture_26063_v1.gpl
people_26063_v2.gpl
props_26063_v1.gpl
terrain_26063_v1.gpl
ui_26063_v1.gpl
```

`master` — библиотека, а не жёсткий лимит для каждого ассета.

## 8. Прозрачность

`#FF00FF` не является стандартным production-механизмом удаления фона. Предпочтительно хранить RGB-кандидат и отдельную mask/segmentation map, затем строить чистую альфу.

Хромакей разрешён только как совместимый fallback для конкретных workflow.

## 9. Pixel refinement

Refiner не должен заново рисовать объект. Разрешены:

- объединение неудачных микрокластеров;
- удаление одиночного шума;
- ремонт ступенчатого контура;
- очистка мелких дыр;
- palette mapping;
- выравнивание логического пикселя.

Запрещены агрессивный majority downsampling, изменение лица, пропорций и ключевого силуэта. Если они нужны, кандидат отклоняется и генерируется заново.

Защищённые признаки портрета: глаза, очки, рот, волосы, характерный предмет. Архитектуры: крыша/купол, башня, входы, крупные окна.

## 10. Проверка в реальном масштабе

Каждый выбранный кандидат и финал показываются в `1×`, `2×`, `4×`. Арт-приёмка в первую очередь ведётся по `1×`.

Если лицо, предмет или здание читаются только в увеличенном preview, ассет отклоняется.

## 11. ЛОР в prompt compiler

MCP загружает `docs/lore/lore-registry.yaml` и добавляет в prompt только релевантные поля: эпоху, материалы, характерный свет, локального человека, предмет-символ, человеческие следы и северо-западную идентичность.

ЛОР не заменяет техническую спецификацию размера/anchor/pivot.

## 12. MCP API

Целевые операции:

```text
asset_spec
generate_candidates
rank_candidates
select_candidate
refine_candidate
preview_asset
art_review
check_asset_contract
approve_asset
reject_candidate
regenerate_asset
build_sprite_sheet
generate_day_night_pair
gpu_status
queue_status
```

Автоматический переход `generated_raw → approved` запрещён.

## 13. Gold set и LoRA

Создать `assets/reference/gold/` по классам. В gold попадают только вручную утверждённые работы.

После накопления выборки предпочтительны отдельные LoRA/адаптеры минимум для:

- `26063_environment`;
- `26063_character`;
- общего пиксельного языка.

Не обучать универсальную LoRA на смешанной куче портретов, зданий, UI и тайлов без классового контроля.

## 14. Контрольный пилот

До массовой генерации прогнать и принять:

1. `BLD-RADAR-DAY`;
2. `BLD-ARCHIVE-DAY`;
3. `portrait.npc.vera_ladozhskaya`;
4. портрет Семёна Круглова;
5. кота Паскаля;
6. vegetation asset;
7. prop;
8. terrain tile.

Массовая очередь не запускается, пока эти восемь примеров не показывают, что refined-версия не хуже raw и соответствует арт-направлению.

## 15. Definition of Done

Конвейер v2 считается внедрённым, когда:

- художественная и техническая приёмка разделены;
- старый общий pixel validator не является CI-гейтом;
- нет auto-approve по размеру/числу цветов;
- есть разные workflow минимум для portrait/character/architecture/prop/tile;
- palette limits являются диапазонами, а не художественными запретами;
- majority downsampling не является production-нормализатором;
- `#FF00FF` не является основным production alpha workflow;
- есть `1×`-приёмка;
- есть причины художественного отклонения;
- `BLD-RADAR-DAY` и Вера Павловна проходят пилотную приёмку на новом pipeline.
