# Композиционный контракт интерфейса главного кампуса

**Статус:** нормативный контракт главного экрана кампуса.

## 1. Базовый принцип

Мир первичен, интерфейс вторичен. В состоянии покоя сначала должен читаться кампус: центральный оперативный корпус, площадь, маршруты и специализированные здания. Интерфейс раскрывается только в ответ на намерение пользователя.

## 2. Иерархия

Визуальный вес распределяется так: текущая локация → архитектура и маршруты → выбранный объект → доступные точки взаимодействия → системная навигация → закрытые точки → вспомогательная информация.

На idle-кадре запрещены крупные постоянные подписи над зданиями. Разрешены только компактные пространственные маркеры у входов. Одновременно раскрыта не более чем одна карточка локации.

## 3. Состояния локаций

- `available`: нормальная насыщенность, тёплый вход, компактный золотисто-зелёный маркер; при наведении — тонкий контур.
- `active`: признаки `available` плюс один слабый акцент; без мигания.
- `locked`: приглушённое состояние, знак замка и конкретное условие открытия; состояние обязано читаться без цвета.
- `disabled`: ещё более спокойное состояние и доступное объяснение причины.

Подробное досье открывается только по явному действию пользователя.

## 4. Цвет и типографика

Источник истины — `design/tokens/pixel-art-theme.yaml`. Декоративный электрический синий, неон, glassmorphism и крупные мягкие свечения запрещены. Основные русскоязычные подписи используют `PixCyrillic`/`PixCyrillic-Dense`; сплошной верхний регистр для всей иерархии не используется.

Phaser numeric colors задаются только как `0xRRGGBB`; прозрачность передаётся отдельным параметром. Литералы больше `0xFFFFFF` запрещены, если API явно не требует иной формат.

## 5. Геометрия и размещение

Для каждой локации отдельно хранятся world bounds, hit area, entrance anchor, marker anchor, preferred tooltip direction, альтернативные направления и priority. Карточка проверяет границы viewport и зарезервированные зоны профиля/нижнего dock и при конфликте меняет направление.

UI нельзя размещать поверх главного входа центрального корпуса, ключевых лестниц и маршрутов, горизонта/главного светового центра или другой активной карточки.

## 6. HUD и профиль

Профиль по умолчанию свёрнут в компактный chip; команды пользователя находятся внутри раскрываемого popover. Нижний dock содержит только глобальные действия сцены и не дублирует переходы по зданиям.

Стационарный HUD должен занимать не более 10–12 % viewport; idle-подписи поверх мира — не более 4–5 %.

## 7. Доступность

Интерактив поддерживает мышь и клавиатуру: `Tab`, `Shift+Tab`, `Enter`, `Space`, `Escape`. Минимальная фактическая зона нажатия — 44×44 CSS px. Необязательная анимация отключается при `prefers-reduced-motion`.

## 8. Критерий приёмки

Решение не принимается, если при беглом взгляде первыми читаются панели, одновременно раскрыты несколько карточек, закрытая локация ярче доступной, UI перекрывает ключевую архитектуру или состояние определяется только цветом.

Правильная последовательность чтения: **сцена → объект → действие → пояснение**.
