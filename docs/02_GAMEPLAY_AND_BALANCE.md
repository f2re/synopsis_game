# 02. Игровые правила, режимы и баланс

## 1. Основная метафора матча

Игроки — синоптики, которые параллельно ведут анализ одной или эквивалентных синоптических ситуаций. Вместо условного «здоровья» используется **Надёжность решения**.

Пример:

```text
Иванов                         Петров
Надёжность                     Надёжность
██████████ 86                  ███████░░░ 63
```

При достижении нуля решение игрока считается потерявшим устойчивость/согласованность, и раунд завершается.

В интерфейсе допустимо внутренне использовать `HP`, но пользователю предпочтительно показывать тематический термин.

## 2. Главный принцип боя

**Ответ не покупает действие. Ответ и есть действие.**

Правильная профессиональная операция немедленно вызывает игровой эффект.

Примеры:

| Учебное действие | Тип | Типичный эффект |
|---|---|---|
| расшифровать короткую группу КН-01 | quick | небольшой урон / накопление ресурса |
| собрать элемент схемы станции | quick/defense | щит |
| распознать ww/облачность/тенденцию | quick | небольшой урон, серия |
| найти ошибку наблюдения | defense | парирование/контратака |
| корректно продолжить изобару | medium | средний урон |
| определить П/Р | medium | ресурс/контроль |
| выполнить подъём карты | medium | комбо/поддержка |
| определить фронт по комплексу признаков | heavy | сильный урон |
| согласовать фронт с АТ/ОТ | heavy | усиление следующего действия |
| решить комплексную задачу ПЭСМ | ultimate | сильный финальный эффект |

Все численные значения задаются конфигурацией баланса.

## 3. Оперативный ресурс

Для сильных действий используется условный ресурс `OR` (Operational Resource / Оперативный ресурс).

Базовая модель:

- максимум: 5 единиц;
- простое правильное решение: +1;
- серия: дополнительный бонус;
- тяжёлые операции требуют 2–3;
- комплексная способность требует 5.

Пример стоимости:

| Действие | Стоимость |
|---|---:|
| КН-01 quick | 0 |
| схема станции | 1 |
| критика наблюдений | 1 |
| фронтология | 2 |
| трёхмерное согласование | 3 |
| комплексный прогноз | 5 |

Ресурс нельзя купить за реальные деньги или постоянную мета-валюту в рейтинговом матче.

## 4. Серии и комбо

### 4.1. Обычная серия

Несколько правильных ответов подряд увеличивают темп, но бонус ограничен.

Пример:

- ×2 — визуальный индикатор;
- ×3 — +1 OR;
- ×5 — небольшой бонус эффекта;
- ошибка — серия сбрасывается.

### 4.2. Профессиональное комбо

Особый бонус даётся за логически связанную последовательность, например:

`КН-01 → наноска → критика → барическое поле`

или

`история процесса → АТ-850 → ОТ1000/500 → приземные признаки → фронт`.

Случайная последовательность несвязанных дисциплин специального бонуса не даёт.

Цель: игрок запоминает рабочие цепочки, а не только отдельные карточки.

## 5. Эффекты

Эффекты должны иметь нейтральные игровые названия, чтобы не искажать профессиональные термины.

Разрешённый базовый набор:

- **Щит** — поглощает часть следующего эффекта;
- **Задержка** — увеличивает время появления следующей карточки/действия на малую величину;
- **Блокировка** — временно запрещает тяжёлую способность;
- **Разведка** — показывает категорию следующего задания соперника;
- **Помеха** — добавляет одну правдоподобную ложную альтернативу;
- **Контроль** — повышает сложность следующего задания в допустимом диапазоне;
- **Контратака** — отражает часть эффекта после успешной защиты.

Нельзя называть игровые станы «инверсией», «адвекцией» и т. п., если эффект не отражает физический смысл термина.

## 6. Критика наблюдений как парирование

Это базовая защитная механика.

Сценарий:

1. соперник завершает сильное действие;
2. защищающемуся предлагается короткая «Критическая проверка»;
3. на фрагменте из нескольких станций нужно указать подозрительную/ошибочную;
4. правильный ответ отменяет часть эффекта;
5. быстрый точный ответ может дать контратаку.

Так профессиональный контроль качества становится естественной игровой защитой.

## 7. Скорость и правильность

Скорость никогда не должна перевешивать знание.

Рекомендуемая модель:

```text
score = correctness * (1 + speed_bonus)
```

где `speed_bonus` ограничен, например диапазоном 0…0.15.

Неправильный ответ не может получить положительный результат только за скорость.

Для задач, где обдумывание является частью навыка, `speed_bonus` может быть равен нулю.

## 8. Задержка сети

Время ответа рассчитывается сервером с учётом сетевой модели матча. Требования:

- использовать серверный timestamp старта;
- не давать миллисекундной задержке определять исход;
- минимизировать зависимость бонуса от ping;
- применять grace-window для сетевой вариативности;
- хранить latency telemetry для разбора спорных матчей.

## 9. Ranked-нормализация

В рейтинговых матчах:

- одинаковая базовая Надёжность;
- одинаковые коэффициенты эффектов;
- одинаковые cooldown;
- одинаковый потолок OR;
- постоянная прокачка не усиливает урон/защиту.

Прокачка открывает контент, ранги, сложность, косметику и варианты центра, но не создаёт pay/grind-to-win.

## 10. Режим «Блиц»

Продолжительность: конфигурируемо, базовая цель — 60–120 секунд.

Типовая цепочка:

- условный знак;
- группа КН-01;
- В/Н;
- П/Р;
- элемент станции;
- фронт;
- T850;
- ОТ1000/500.

Правильный ответ → очко/импульс/серия.

Блиц должен хорошо работать на телефоне одной рукой.

## 11. Режим 1v1 «Синоптическая дуэль»

Базовая длительность: 3–6 минут.

Перед матчем игрок выбирает набор доступных **рабочих инструментов**, например:

- КН-01;
- схема станции;
- критика;
- барическое поле;
- фронтология;
- АТ/ОТ;
- прогноз.

Это аналог «колоды», но инструменты определяют типы задач, а не магические способности.

## 12. Режим 2v2 «Синоптическая бригада»

Две роли:

- приземный анализ;
- высотный/термический анализ.

Команда получает бонус за **согласование по вертикали**.

Пример:

- игрок A предполагает положение холодного фронта по приземной карте;
- игрок B подтверждает/опровергает по АТ-850 и ОТ;
- согласованный вывод усиливает командное действие.

## 13. Режим 3v3 «Оперативная смена»

Рекомендуемые роли:

1. кодовый пост/наблюдения;
2. приземный анализ/фронтология;
3. аэрология/высотные поля.

В финале команда получает общую прогностическую задачу, использующую результаты предыдущих этапов.

## 14. Все против всех

Подходит для аудитории:

- 10–30 студентов;
- синхронные короткие раунды;
- после серии раундов top-N проходит в playoff;
- затем 1v1/2v2 сетка.

## 15. Босс/PvE рейд

Группа совместно анализирует сложную ситуацию.

Пример структуры:

`телеграммы → критика → наноска → приземный анализ → АТ/ОТ → фронтология → эволюция → прогноз`.

«HP босса» в UI лучше интерпретировать как **неопределённость ситуации** или **неразобранный объём сценария**, а не физическое здоровье циклона.

## 16. Рейтинги

Поддерживаются независимо:

- `Mastery` — учебное владение;
- `Arena Rating` — PvP;
- `Accuracy` — точность;
- `Group Rating` — рейтинг учебной группы;
- `Season Rating` — сезонное соревнование.

## 17. Формула рейтинга

Для PvP рекомендуется Elo/Glicko-подобная система с учётом неопределённости рейтинга. Конкретный алгоритм выбирается на этапе реализации.

Рейтинг не должен напрямую смешиваться с учебной оценкой.

## 18. Матчмейкинг

Приоритеты:

1. близкий Arena Rating;
2. совместимый уровень открытого контента;
3. одинаковый профиль методики;
4. допустимая задержка;
5. расширение диапазона поиска со временем.

Нельзя матчить игроков по разным методическим правилам без явного режима cross-profile.

## 19. Сложность

Каждое задание имеет как минимум:

- `difficulty`;
- `estimated_cognitive_load`;
- `time_limit_policy`;
- `topic`;
- `prerequisites`;
- `method_profile`.

Эквивалентные PvP-задачи должны быть калиброваны статистически по фактической точности и медианному времени ответа.

## 20. Антифрустрация

- не отнимать постоянный учебный прогресс за поражение;
- объяснять профессиональную причину ошибки после матча;
- не спамить станами;
- ограничить цепочки контроля;
- давать comeback-механику только через знания, а не случайный бонус;
- не использовать loot-box механику для учебных преимуществ;
- не наказывать за медленное чтение там, где задача не должна быть скоростной.

## 21. Победа должна отражать качество решения

Приоритет при расчёте исхода:

1. правильность;
2. последовательность и полнота анализа;
3. согласованность решения;
4. сложность;
5. скорость как ограниченный бонус.

Это обязательное правило баланса проекта.
