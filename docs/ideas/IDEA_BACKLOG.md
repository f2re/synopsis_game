# Idea backlog

**Статус:** living document

Здесь хранятся идеи, которые ещё не являются обязательствами roadmap. Идея переносится в `roadmap/` только после оценки учебной ценности, стоимости и рисков.

## Формат идеи

```text
IDEA-XXX — название
Статус: raw | exploring | validated | rejected | promoted
Проблема:
Гипотеза:
Учебная ценность:
Игровая ценность:
Стоимость: S | M | L | XL
Риски:
Как проверить:
Следующий шаг:
```

## IDEA-001 — Live classroom commentator mode

- **Статус:** exploring
- Преподаватель отмечает ключевые моменты матча и после завершения получает автоматический список эпизодов для разбора.
- **Стоимость:** M.
- **Проверка:** пилот на группе 15–25 студентов.

## IDEA-002 — «Синоптический кубок» между учебными группами

- **Статус:** exploring
- Сезон из массовых квалификаций, 1v1 финалов и командной смены.
- Нужна нормализация по численности групп.

## IDEA-003 — Ghost replay

- **Статус:** raw
- Игрок соревнуется не в realtime, а против event log предыдущего сильного прохождения.
- Полезно при малом онлайне.

## IDEA-004 — Daily real case

- **Статус:** raw
- Один короткий архивный или актуальный кейс дня с общим leaderboard.
- Требует строгого provenance и прав на данные.

## IDEA-005 — «Ошибка дня»

- **Статус:** exploring
- Система выбирает типичную ошибку группы и даёт всем короткий корректирующий drill.
- Высокая учебная ценность, низкая стоимость.

## IDEA-006 — Skill draft перед дуэлью

- **Статус:** raw
- Игрок выбирает 4–6 тематических инструментов из разрешённого пула; сервер строит матч из соответствующих типов задач.
- Не должно превращаться в контрпик по незнанию соперника.

## IDEA-007 — Weather map fog-of-war

- **Статус:** raw
- Игрок постепенно открывает слои карты, выбирая порядок анализа.
- Смысл: обучать последовательности работы, а не скрывать данные ради сложности.

## IDEA-008 — Collaborative front placement 2v2

- **Статус:** raw
- Один игрок ставит предварительный фронт по приземной карте, второй подтверждает по высотным данным.
- Итог оценивается как согласованное командное решение.

## IDEA-009 — «Архив ошибок» как коллекция

- **Статус:** exploring
- Вместо коллекционных карточек игрок собирает типы ошибок, которые уже научился уверенно распознавать.
- Косметическая подача не влияет на Ranked.

## IDEA-010 — Метеорологические достижения без grind

- **Статус:** exploring
- Награды за качество: 20 station plots без ошибки, 10 корректных parry, комплексный кейс без подсказок.

## IDEA-011 — Методический sandbox преподавателя

- **Статус:** raw
- Instructor создаёт custom content pack через форму, задаёт allowed swaps, источники и критерии.
- Публикация в Ranked запрещена без review.

## IDEA-012 — Региональные кампании

- **Статус:** raw
- ЕТР, Арктика, Сибирь, Дальний Восток, горные районы.
- Кампания должна опираться на реальные региональные синоптические особенности и источники.

## IDEA-013 — «Ныряющий циклон» raid

- **Статус:** raw
- Команда разбирает процесс по срокам; ошибки увеличивают неопределённость сценария.

## IDEA-014 — «Южный циклон» raid

- **Статус:** raw
- Упор на историю, ВФЗ, осадки и сложную эволюцию.

## IDEA-015 — Tournament broadcaster overlay

- **Статус:** raw
- Отдельный минималистичный projector view: игроки, надёжность, текущая категория, streak, карта, закрытый результат.

## IDEA-016 — Adaptive difficulty by empirical calibration

- **Статус:** exploring
- Сложность задачи корректируется не вручную только по мнению автора, а по accuracy/median response time после пилота.

## IDEA-017 — Offline practice packs

- **Статус:** raw
- PWA кэширует выбранные темы для аудитории с нестабильным интернетом.

## IDEA-018 — Replay branching

- **Статус:** raw
- В разборе студент останавливает replay перед ошибкой и выбирает альтернативное действие.

## IDEA-019 — «Синоптический стол» tabletop mode

- **Статус:** raw
- Один большой экран/проектор, команды отвечают со смартфонов; карта общая для всех.

## IDEA-020 — Content health dashboard

- **Статус:** exploring
- Для автора контента: ambiguous rate, distractor quality, source status, revoke/deprecate flags.

## Правила удаления идей

Идеи не удалять без следа. При отказе менять статус на `rejected` и кратко фиксировать причину — это предотвращает повторное обсуждение уже проверенной гипотезы.
