# Блиц-практика: шесть заданий за 90 секунд

**Задача:** `20261111-modular-player-r03-completion`.
**Реализация:** `/root/blitz_flow`, роли `realtime-arena-engineer`, `gameplay-balance-designer`, `identity-avatar-engineer`.
**Версия правил:** `blitz-practice-v1`.

## Принятое решение

В текущем приложении добавлен отдельный тренировочный сценарий **«Блиц-практика · 90 с»**. Он открывается после одной завершённой учебной смены КН-01, подтверждённой серверным хранилищем учебной экипировки. Достаточно завершить все задания; процент правильных ответов не является новым квалификационным условием.

Весь раунд длится 90 секунд. Игрок получает шесть существующих заданий, по одной попытке на каждое. Итог показывает правильные, отправленные и оставшиеся без ответа задания. Бонус скорости отсутствует. Учебные знаки, количество завершённых обычных смен, даты практики, квалификационный допуск и рейтинг не меняются.

Сценарий использует `core_ru_001@0.6.0` со статусом `draft`. Правильные ответы, объяснения, источники и функции проверки не изменены. На экране до начала, во время раунда и в результате явно обозначен черновой статус пакета.

Это решение не активирует допуск после С2/«Термометра» из проекта первого уровня и не использует отклонённые материалы этапа W2-06. Квалификационный и рейтинговый блиц требуют отдельной приёмки банка заданий и подключения подтверждённой прогрессии. Старый неподключённый выбор «60 секунд» не является маршрутом нового сценария.

## Набор заданий

Версия правил закрепляет существующие ID, а не выбирает первые шесть строк произвольного будущего пакета. При отсутствии любого из них запуск закрывается.

| Порядок | ID | Существующее действие |
| --- | --- | --- |
| 1 | `kn01_temp_001` | Числовой ответ к кодовой группе |
| 2 | `kn01_dewpoint_001` | Числовой ответ к кодовой группе |
| 3 | `kn01_station_pressure_001` | Числовой ответ к кодовой группе |
| 4 | `kn01_tendency_001` | Выбор ответа |
| 5 | `kn01_section1_order_001` | Порядок групп |
| 6 | `station_plot_basic_001` | Размещение данных на схеме станции |

Каждый экземпляр формируется существующим `createTaskInstance`; до ответа в клиент передаётся только проверенный `PublicTaskInstance`. Сервер применяет существующий `validateTaskAnswer`. Объяснение уже принятого ответа сохраняется для итогового разбора; текст к ещё не решённым заданиям не выдаётся.

## Персонаж и экипировка

При начале раунда сервер сохраняет все 11 полей `AvatarProfile` и снимок учебной экипировки. При возобновлении и на итоговом экране используется этот комплект. Изменение гардероба в другой вкладке относится к следующему раунду.

`AvatarPreview` получает этот снимок и контекст `blitz-practice`. Он использует общий сборщик слоёв одежды, обуви и предметов; отдельное изображение каждой комбинации не создаётся. Контекст сохраняет спокойную позу, не показывает компаньона поверх задания и не изменяет сохранённую внешность. Эффекты предметов и значков отключены: оба количества применений равны нулю. Справка, повтор и отдельное открытие решения недоступны.

## Время, восстановление и повторные запросы

Время начала и `deadlineAt = startedAt + 90 000 мс` вычисляет сервер внутри последовательной транзакции. Клиент не передаёт время, продолжительность, правильность или итог. Ответ принимается только при серверном времени строго меньше `deadlineAt`. В момент достижения границы новый ответ не учитывается.

Браузер отображает оценку оставшегося времени из серверных отметок с помощью монотонного счётчика. Она не разрешает отправку на сервере и не определяет результат. При локальном нуле экран запрашивает серверное завершение. Выход в кампус, закрытие вкладки, потеря сети и перезапуск сервера не добавляют времени. После возвращения сервер сверяет сохранённый срок; при необходимости завершает раунд с отметкой окончания, равной `deadlineAt`.

За одним пользователем закрепляется не более одного активного блица. Обычная учебная смена и блиц имеют отдельные активные состояния. Нажатие «Новый блиц» после завершения создаёт новый раунд с новым ключом запроса.

Идемпотентность действует на двух уровнях:

- каждый успешно обработанный ключ запуска связан с конкретным раундом, включая ключи разных вкладок, возобновивших один раунд; его повтор после завершения возвращает прежний раунд;
- первая попытка имеет ключ экземпляра задания и отпечаток ответа; одинаковый повтор возвращает сохранённую обратную связь и актуальный снимок раунда, другой ответ для той же попытки отклоняется.

Количество различных ключей запуска, привязанных к одному раунду, ограничено 64. После достижения ограничения остаётся доступно чтение состояния. Все изменения срока, ответов и результата сохраняются атомарно через `TrainingStore`. При ошибке записи видимое состояние не меняется. Журнал `attempts.jsonl` восстанавливается из канонических записей хранилища.

На диске проверяются версия правил, точная длительность, закреплённые ID заданий, согласованность количества ответов и результата, отсутствие помощников и наград, допустимость внешности, уникальность ключей запуска и единственность активного раунда. Повреждённая запись не заменяется новым таймером.

## Маршруты приложения и API

Экран `/blitz` доступен после входа через существующий закрытый список учебной группы. В кампусе он открывается через «Маршрут» и диалог Кодового поста. Перед началом показываются условия и явная кнопка запуска; открытие страницы само по себе не запускает новый отсчёт.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/blitz-practice` | Условие доступа, версия правил и последний собственный раунд |
| `POST /api/blitz-practice` | Начать или идемпотентно возобновить раунд; тело `{ requestId }` |
| `GET /api/blitz-practice/:id` | Актуальное состояние, проверка срока и восстановление |
| `POST /api/blitz-practice/:id/answer` | Передать `{ instanceId, answer }`; проверка и переход выполняются сервером |

Все маршруты требуют текущую сессию и проверяют владельца. Чужой ID не раскрывает данные. Старые маршруты `/api/shifts/*` и `/api/tasks/*/answer` отклоняют ID блица, поэтому через них нельзя обойти срок или получить помощника. Небезопасная клиентская запись прогрессии остаётся закрытой.

Ответ на отправку содержит `accepted` и актуальный `session`. Если срок уже истёк, возвращается `accepted: false` вместе с сохранённым результатом; это позволяет зафиксировать истечение срока в той же атомарной операции. Если повторяется ранее принятый ответ, возвращаются его сохранённая обратная связь и текущее состояние без повторного начисления.

## Проверка и оставшиеся границы

Собственные проверки реализации записаны в [отчёте](../testing/2026-11-11-blitz-practice-implementation.md). Независимые проверки безопасности, браузера и интеграции ведёт корневой агент; автор сценария не выдаёт себе разрешение на выпуск.

Открытый визуальный стенд находится в `apps/web/tools/review/blitz-practice.html` и доступен только в режиме разработки Vite. Он использует настоящий компонент, но полностью заменяет API локальными состояниями, снятыми существующим `ShiftService`. Баннер явно отмечает подмену и отсутствие реальных аккаунтов. Ввод на этом стенде не оценивается; проверка работает на обычном `/blitz` после входа.

Текущая реализация — индивидуальная тренировка. В ней нет подбора соперников, рейтинга, соревновательного допуска или подключения к публичному экрану. Итог и разбор доступны для последнего раунда; отдельный архив всех блицев не добавлен.
