# 00. Видение и полный GDD

## 1. Назначение проекта

«Синоптический центр» — учебная соревновательная игра для освоения синоптической метеорологии через многократное выполнение реальных профессиональных операций.

Игра должна решать не только задачу проверки знаний, но прежде всего задачу **формирования процедурной памяти**: студент должен автоматически помнить, что, в какой последовательности, по каким признакам и с какими ограничениями делает синоптик.

Целевая аудитория:

- студенты метеорологических и гидрометеорологических вузов;
- курсанты/слушатели программ переподготовки;
- преподаватели синоптической метеорологии;
- молодые специалисты ГМС, АМЦ, УГМС и прогностических подразделений;
- в расширенной версии — школьные/олимпиадные метеокружки и профессиональные тренажёры.

## 2. Игровая фантазия

Игрок развивает собственный **Синоптический центр**, проходя путь от практиканта до начальника прогностического подразделения. Центр — это не декоративная ферма ресурсов, а карта компетенций игрока.

Каждый объект базы соответствует реальному блоку подготовки:

| Объект | Учебный смысл |
|---|---|
| Телетайпная / кодовый пост | КН-01, КН-04, SHIP, авиационные коды для профильных модулей |
| Пост наноски | схема нанесения метеорологических данных вокруг кружка станции |
| Стол приземного анализа | первичный анализ приземных карт, изобары, изаллобары, подъём карты, кольцовки |
| Аэрологический отдел | АТ-850/700/500/300, ОТ1000/500, ТБ, аэрологическая диаграмма, вертикальные разрезы |
| Кабинет фронтологии | историческое и трёхмерное согласование фронтов, ВФЗ, T850, приземные признаки |
| Пост МРЛ и спутникового анализа | радиоэхо, опасные явления, облачные системы, нефанализ |
| Прогностический зал | прогноз синоптического положения и погоды, схема ПЭСМ, региональные сценарии |
| Архив | реальные исторические ситуации, replay, разбор ошибок |
| Турнирный зал | PvP, групповые батлы, рейтинги, spectator mode |

## 3. Четыре столпа дизайна

### 3.1. Профессиональная операция = игровое действие

Не должно быть конструкции «ответил на вопрос — получил монеты — купил удар». Правильное решение само создаёт игровой эффект.

Примеры:

- расшифрованная группа КН-01 → быстрый импульс/атака;
- корректно собранная станция → щит;
- найденная ошибка наблюдения → парирование/контратака;
- правильно определённый фронт → тяжёлая атака;
- согласование по вертикали → усиление/блокировка;
- комплексный прогноз → финальная способность.

### 3.2. Игра должна учить порядку действий

Ключевой образовательный результат — не узнавание термина, а воспроизведение профессиональной последовательности.

Модель сложности:

1. узнать правильный шаг;
2. расставить готовые шаги;
3. выбрать шаг среди лишних;
4. восстановить пропущенные шаги;
5. самостоятельно выполнить последовательность;
6. применить её в реальной архивной ситуации.

### 3.3. Игровой экран — не дашборд

Основную площадь занимает карта/ситуация/задача. Вторичные элементы — рейтинг, XP, лига, статистика — должны уходить на периферию.

Рекомендуемая иерархия экрана:

1. текущая учебно-игровая ситуация;
2. одно главное действие;
3. состояние матча/прогресса;
4. вторичные панели;
5. мета-игровая статистика.

### 3.4. Методика должна быть версионируемой

Классический учебник, современный нормативный документ и локальная кафедральная последовательность не должны смешиваться в один «абсолютный стандарт».

Каждое содержательное задание имеет `method_profile`, `sources` и версию.

## 4. Основная игровая петля

### 4.1. Ежедневная петля

Игрок открывает игру и получает «смену»:

- 2 задания на интервальное повторение;
- 2 задания по текущей теме;
- 1 усложнённое или интеграционное задание;
- при желании — PvP/блиц.

Результат смены:

- XP общего прогресса;
- изменение mastery конкретных навыков;
- пополнение журнала ошибок;
- прогресс объектов центра;
- достижения/косметические награды;
- рейтинг только для соревновательных режимов.

### 4.2. Учебная петля

`задача → решение → объяснение → классификация ошибки → повторение → перенос навыка в сценарий`

### 4.3. Соревновательная петля

`быстрые задачи → оперативный ресурс → усиленное профессиональное действие → давление на соперника → защита/критика → комплексная задача → завершение матча`

## 5. Карьерная лестница

Рекомендуемый игровой путь:

1. Практикант;
2. Техник-метеоролог;
3. Техник-аэролог;
4. Синоптик II категории;
5. Синоптик I категории;
6. Ведущий/дежурный синоптик смены;
7. Начальник прогностического отдела.

Это игровая педагогическая шкала, а не кадровый классификатор. Наименования и допуски должны быть проверены методистом перед публичным релизом.

## 6. Дерево компетенций

Минимальный набор ветвей:

- условные обозначения;
- КН-01;
- КН-04/аэрология;
- схема нанесения станции;
- критика наблюдений;
- барическое поле;
- изобары/изаллобары;
- подъём карты;
- приземные карты и кольцовки;
- АТ-850;
- АТ-700;
- АТ-500;
- АТ-300;
- ОТ1000/500;
- термобарическое поле;
- аэрологическая диаграмма;
- вертикальные разрезы;
- воздушные массы;
- фронтология;
- ВФЗ;
- МРЛ;
- спутниковый анализ/нефанализ;
- краткосрочный прогноз;
- ПЭСМ;
- опасные явления;
- региональная синоптика.

Mastery хранится отдельно от PvP-рейтинга.

## 7. Прогрессия

### 7.1. XP

XP показывает объём освоенной практики и не уменьшается.

### 7.2. Mastery

По каждому навыку рассчитывается уровень владения. Он зависит от:

- точности;
- сложности;
- числа независимых попыток;
- давности повторения;
- способности переносить навык в комплексные сценарии.

### 7.3. Arena Rating

Отдельный соревновательный рейтинг. Может расти и падать.

### 7.4. Групповой рейтинг

Для учебных групп использовать нормализованный/средний или медианный результат, чтобы размер группы не давал прямого преимущества.

## 8. Игровые режимы

### Solo

- тренировка;
- ежедневная смена;
- экзамен/допуск;
- архивная ситуация;
- босс-сценарий;
- интервальное повторение.

### PvP

- блиц 60–120 секунд;
- 1v1 «Синоптическая дуэль»;
- 2v2 «Синоптическая бригада»;
- 3v3 «Оперативная смена»;
- турнир группы;
- все-против-всех с отбором в playoff.

### Cooperative PvE

- групповой «рейд» по южному циклону;
- ныряющий циклон;
- блокирующий антициклон;
- опасное явление;
- авиационная смена.

## 9. Боссы и крупные сценарии

Босс — не фантастическое существо, а сложная реальная/архивная синоптическая ситуация.

Примеры:

- ныряющий циклон;
- южный циклон;
- блокирующий антициклон;
- активный фронт с конвекцией;
- сильный снег/метель/гололёд;
- авиационный сценарий со струйным течением, ТЯН и обледенением;
- сценарий ОЯ.

Сценарий раскрывается этапами: первичные данные → критика → приземный анализ → высотные карты → фронтология → эволюция → прогноз.

## 10. Журнал ошибок

Каждая ошибка классифицируется, например:

- кодирование/декодирование;
- схема нанесения;
- знак/индекс;
- порядок операций;
- барическое поле;
- фронтология;
- несогласование по времени;
- несогласование по вертикали;
- неверная интерпретация одного признака как достаточного;
- физическая несогласованность;
- невнимательность/единицы/знак.

Журнал ошибок используется для адаптивного повторения.

## 11. Допуски

Часть контента открывается не только уровнем, но и квалификационным испытанием.

Пример допуска к самостоятельному первичному анализу:

- mastery по нанесению ≥ порога;
- mastery по КН-01 ≥ порога;
- mastery по барическому полю ≥ порога;
- экзамен без подсказок с минимальной точностью.

Порог задаётся профилем курса, а не жёстко прошивается в клиенте.

## 12. Достижения

Достижения должны поощрять полезное поведение:

- серия без ошибок;
- 100 корректно разобранных станций;
- 50 найденных ошибок наблюдений;
- прохождение комплексного сценария без подсказок;
- стабильность точности в течение нескольких сессий;
- командное согласование 2v2/3v3;
- правильный анализ архивного случая.

Не поощрять бессмысленный grind.

## 13. Что проектом не является

- не обычный тест с игровой рамкой;
- не экономическая стратегия;
- не симулятор кадровой структуры Росгидромета;
- не замена нормативных документов;
- не pay-to-win;
- не система, в которой скорость важнее правильности;
- не инструмент автоматического выставления итоговой оценки без контроля преподавателя.

## 14. Критерии успеха

Проект считается концептуально успешным, если студент:

1. быстрее воспроизводит последовательности операций;
2. реже путает обозначения и элементы нанесения;
3. умеет объяснить, почему действие выполняется в данном месте алгоритма;
4. использует историю процесса и вертикальное согласование;
5. переносит навыки из микроупражнений в архивную карту;
6. хочет добровольно повторить материал в PvP/блице;
7. преподаватель может увидеть типичные ошибки группы и провести их разбор.
