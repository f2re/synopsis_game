# Каталог игровых механик

**Статус:** living document

Файл предназначен для независимого развития механик. Каждая механика получает ID, учебную цель, игровой эффект, ограничения и статус.

## Формат карточки

```text
ID:
Название:
Статус: idea | prototype | accepted | implemented | deprecated
Учебная цель:
Игровой цикл:
Входные данные:
Результат:
PvP-эффект:
Риски:
Зависимости:
Acceptance criteria:
```

## M-001 — Быстрый декод КН-01

- **Статус:** accepted
- **Учебная цель:** автоматизация чтения коротких групп.
- **Цикл:** код → ответ за 5–10 с → мгновенный результат.
- **PvP:** quick action, небольшой эффект, +OR.
- **Риск:** скорость не должна перевешивать точность.

## M-002 — Собери станцию

- **Статус:** accepted
- **Учебная цель:** схема нанесения метеоданных вокруг кружка станции.
- **Цикл:** исходные величины → drag/drop → покомпонентная проверка.
- **PvP:** защитный щит или восстановление устойчивости.

## M-003 — Критика наблюдений / Parry

- **Статус:** accepted
- **Учебная цель:** поиск подозрительного или ошибочного наблюдения.
- **Цикл:** 5–7 станций → выбор → причина.
- **PvP:** парирование, при быстром точном ответе — контратака.
- **Ограничение:** различать `suspect`, `wrong`, `insufficient_data`.

## M-004 — Следующий шаг

- **Статус:** accepted
- **Учебная цель:** процедурная память.
- **Цикл:** показ текущего состояния анализа → выбор следующей операции.
- **PvP:** комбо-строитель.

## M-005 — Алгоритмический конструктор

- **Статус:** accepted
- **Учебная цель:** порядок первичной обработки, фронтологического анализа, ПЭСМ и других процедур.
- **Усложнение:** порядок → лишние шаги → частичный порядок → свободное воспроизведение.
- **PvP:** heavy action или усилитель серии.

## M-006 — Проведи изобару

- **Статус:** proposed
- **Учебная цель:** анализ барического поля.
- **Цикл:** station field → drawLine → геометрическая и топологическая проверка.
- **PvP:** medium action.
- **Технически:** reference corridor + topology rules, не pixel-perfect.

## M-007 — Фронт по комплексу признаков

- **Статус:** accepted
- **Учебная цель:** исключить привычку определять фронт по одному признаку.
- **Цикл:** история → АТ/ОТ → приземные признаки → линия фронта.
- **PvP:** heavy action.

## M-008 — Вертикальное согласование

- **Статус:** proposed
- **Учебная цель:** связать приземный анализ с АТ-850/700/500 и ОТ.
- **PvP:** усиление командного действия или временная блокировка тяжёлой способности соперника.

## M-009 — Подъём карты

- **Статус:** accepted
- **Учебная цель:** корректное выделение осадков, туманов и явлений цветом/условными знаками.
- **PvP:** поддержка серии; не используется как самостоятельный «магический» эффект.

## M-010 — История процесса

- **Статус:** accepted
- **Учебная цель:** анализ последовательных сроков.
- **Цикл:** переключение −3/−12/−24 ч → оценка траектории/эволюции.
- **PvP:** разведка следующего шага или бонус к сложному анализу.

## M-011 — ПЭСМ chain

- **Статус:** proposed
- **Учебная цель:** комплексный прогноз через Перемещение → Эволюцию → Суточный ход → Местные факторы.
- **PvP:** ultimate только после успешных подготовительных действий.

## M-012 — Эквивалентные PvP-задачи

- **Статус:** accepted
- **Учебная цель:** честное соревнование без одинакового payload.
- **Технически:** одинаковая структура и близкая эмпирическая сложность, разные данные.

## M-013 — Mirror round

- **Статус:** proposed
- **Назначение:** демонстрационные финалы, занятие с проектором.
- **Особенность:** у обоих игроков один task instance; правильный ответ скрыт до закрытия раунда.

## M-014 — Командное вертикальное комбо 2v2

- **Статус:** proposed
- **Роли:** приземный анализ + высотный анализ.
- **Условие:** выводы игроков должны быть согласованы.
- **Результат:** командный бонус только за содержательно совместимое решение.

## M-015 — Оперативная смена 3v3

- **Статус:** proposed
- **Роли:** наблюдения/коды, приземный анализ/фронтология, аэрология.
- **Финал:** общая прогностическая задача использует результаты трёх ролей.

## M-016 — Raid: архивный синоптический процесс

- **Статус:** idea
- **Учебная цель:** коллективный разбор реального случая.
- **Этапы:** данные → критика → карта → АТ/ОТ → фронтология → прогноз.
- **UI:** вместо HP босса — «неопределённость ситуации» или прогресс анализа.

## M-017 — Ошибка как отдельный объект обучения

- **Статус:** accepted
- **Механика:** ошибка получает reason code и возвращается в spaced repetition.
- **Примеры:** знак, код, порядок, вертикальная несогласованность, один-признак-вместо-комплекса.

## M-018 — Допуск

- **Статус:** accepted
- **Механика:** крупный блок открывается не только XP, но и квалификационной проверкой.
- **Важно:** пороги задаются курсом/профилем, не клиентом.

## M-019 — Сезонный сценарий

- **Статус:** idea
- **Назначение:** современная live-service подача без monetization pressure.
- **Структура:** сценарий недели + награды + рейтинговая лига + архив.

## M-020 — Instructor challenge

- **Статус:** idea
- **Механика:** преподаватель собирает 5–10 задач в живой челлендж, запускает QR-room и получает мгновенную аналитику группы.

## Правила принятия новой механики

Механика принимается только если:

1. у неё есть конкретная учебная цель;
2. её игровой эффект не искажает метеорологический термин;
3. её можно протестировать независимо;
4. она не создаёт pay/grind-to-win;
5. для Ranked возможна нормализация;
6. её можно выключить без поломки предметного контента.
