# ADR-0006 — Релизы, развёртывание и безопасное обновление

**Статус:** принято  
**Дата:** 2026-10-26

## Исходная ситуация

Приложение должно устанавливаться на Linux-сервер, в том числе Astra Linux Special Edition 1.7, работать за Nginx или Apache и обновляться с минимальным участием администратора. При выпуске новой версии нельзя терять локальные настройки, ключи карт, параметры сети и КН-01, рейтинги, историю матчей и другие пользовательские данные.

## Решение

1. GitHub Release содержит самодостаточный архив `synopsis-game-<version>-linux-x64.tar.gz` и файл SHA-256. В архив входят собранный браузерный клиент со стилями и ресурсами, сервер, Node.js LTS, systemd-шаблоны и средства установки/обновления. На целевой машине сборка исходников не выполняется.
2. Версии приложения неизменяемы и устанавливаются в `/opt/synopsis-game/releases/<version>`. Активная версия выбирается атомарной ссылкой `/opt/synopsis-game/current`.
3. Локальная конфигурация хранится только в `/etc/synopsis-game`, изменяемые данные — только в `/var/lib/synopsis-game`. Они не входят в каталог релиза.
4. При обновлении значения существующей конфигурации имеют приоритет. Новые параметры добавляются из новой версии defaults; номер схемы конфигурации повышается до версии релиза.
5. Перед миграциями создаётся резервная копия. SQLite копируется локально; для PostgreSQL обязателен успешный `pg_dump`. Неуспешное резервное копирование блокирует обновление.
6. Миграции имеют неизменяемые имена и SHA-256. Уже применённый файл миграции изменять запрещено. SQL-миграции выполняются транзакционно.
7. После переключения версии обновляются systemd unit-файлы и конфигурация Nginx/Apache, затем выполняется проверка `/ready`. При ошибке приложение возвращается на предыдущий релиз; для SQLite автоматически восстанавливаются данные и журнал миграций из резервной копии.
8. Одновременные обновления блокируются файловой блокировкой. После успешного обновления сохраняется ограниченное число предыдущих версий и резервных копий.
9. Поддерживаются два источника обновления: GitHub Releases и локальный каталог для изолированной сети.
10. Доступ через веб-сервер имеет явный режим `lan` или `public`. В режиме `lan` список `TRUSTED_LAN_CIDRS` преобразуется в реальные правила Nginx/Apache.
11. Совместимость с Astra Linux 1.7 проверяется в CI на официальном UBI-образе Astra Linux 1.7, включая Python-скрипты, встроенный Node.js и запуск серверного `/ready`.

## Последствия

Положительные:
- обновление приложения отделено от пользовательских данных;
- откат версии выполняется без повторной сборки;
- локальная конфигурация и секреты переживают обновления;
- один и тот же релиз работает с Nginx, Apache или внешним веб-сервером;
- установка не зависит от системной версии Node.js;
- изолированная локальная сеть не требует доступа к GitHub.

Ограничения:
- автоматическое восстановление внешнего PostgreSQL намеренно не выполняется; его дамп сохраняется, а миграции должны быть обратно совместимыми минимум с предыдущим релизом;
- изменение ОС-пакетов при обновлении приложения не выполняется автоматически, кроме первичной установки выбранных компонентов;
- TLS-сертификаты и политика корпоративного PKI остаются внешней инфраструктурой и не перезаписываются приложением.
