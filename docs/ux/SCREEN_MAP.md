# Карта экранов и маршрутов

**Статус:** предложено

Цель — зафиксировать пространство продукта и не допустить превращения интерфейса студента в перегруженную информационную панель.

## 1. Маршруты игрока

Технические пути URL остаются английскими как часть программного контракта:

```text
/
├── home
├── play/
│   ├── daily-shift
│   ├── blitz
│   ├── duel/:matchId
│   ├── team/:matchId
│   └── raid/:scenarioId
├── learn/
│   ├── skills
│   ├── module/:moduleId
│   └── errors
├── map/:scenarioId
├── replay/:replayId
├── league
└── profile
```

В пользовательском интерфейсе им соответствуют русские названия: «Синоптическая смена», «Блиц», «Дуэль», «Команда», «Архивная ситуация», «Навыки», «Журнал ошибок», «Повтор», «Лига», «Профиль».

## 2. Маршруты преподавателя

```text
/instructor
├── groups
├── group/:id
├── room/create
├── tournament/:id
├── live/:matchId
├── content
├── analytics
└── replay/:id
```

## 3. Зрительские маршруты

```text
/watch/:matchId
/tournament/:id/stage
/projector/:roomId
```

## 4. Главный экран

Главный фокус — **одно действие**: «Начать смену» или актуальная синоптическая ситуация.

Вторичный слой:

- ежедневные задания;
- прогресс навыков;
- лига;
- достижения;
- текущий сезон.

Не показывать одновременно полную таблицу лидеров, всё дерево навыков, инвентарь, архив и аналитику.

## 5. Активная задача

Настольный вариант:

```text
┌───────────────────────────────────────────┐
│ Игрок А        Раунд / время      Игрок Б │
├───────────────────────────────────────────┤
│                                           │
│             КАРТА / ЗАДАНИЕ               │
│                                           │
├───────────────────────────────────────────┤
│ ответы / инструменты / оперативный ресурс │
└───────────────────────────────────────────┘
```

Мобильный вариант:

```text
┌───────────────────┐
│ состояние матча   │
├───────────────────┤
│                   │
│  ЗАДАНИЕ / КАРТА  │
│                   │
├───────────────────┤
│ ответы / действия │
└───────────────────┘
```

## 6. Рабочее пространство карты

Режимы:

- полноэкранный вид;
- слои;
- предыдущий срок;
- разделённый экран;
- переключение АТ/ОТ;
- рисование или выбор;
- фокус на станции.

Во время задания карта не должна быть уменьшенной декоративной карточкой.

## 7. Экран после задания

### Рейтинговый режим

До закрытия раунда показывается только краткая обратная связь. Подробное объяснение появляется после того, как уже не может помочь сопернику.

### Одиночная работа

Сразу показываются:

- правильность;
- объяснение;
- источник;
- тип ошибки;
- действие «повторить похожее».

## 8. Зрительский режим

Крупно показываются:

- игроки;
- Надёжность;
- текущая категория;
- карта или задание;
- серия правильных действий;
- стадия турнира;
- результат закрытого задания.

Элементы ввода игрока отсутствуют.

## 9. Экран преподавателя

Допустима высокая плотность информации:

- ответы;
- время решения;
- коды причин ошибок;
- уровень освоения;
- сетевая задержка;
- метки важных моментов;
- сводная точность группы.

Экран преподавателя не является визуальным шаблоном интерфейса студента.

## 10. Навигация во время игры

В активном матче обычная навигация сворачивается. Игрок не должен случайно покинуть матч обычным нажатием на боковое меню.

## 11. Адаптивные режимы

Точные размеры задаются системой оформления, но функционально поддерживаются:

- телефон в книжной ориентации;
- телефон в альбомной ориентации;
- планшет;
- ноутбук;
- широкий настольный экран;
- проектор или телевизор.

## 12. Критерий приёмки интерфейса

За три секунды пользователь должен понять:

1. какая задача активна;
2. какое действие главное;
3. где показано состояние матча;
4. что относится к метеорологическим данным;
5. что относится к игровому интерфейсу.
